## 5. 进程与模块架构

```text
┌────────────────────────── Tauri 主进程（Rust）──────────────────────────┐
│ 窗口生命周期 · 核心进程监督 · 单实例 · 外链 · 平台层（platform/）        │
└───────────────┬──────────────────────────────────────┬─────────────────┘
                │ stdin / stdout（NDJSON）               │ WebView
┌───────────────▼───────────────────┐        ┌─────────▼───────────────────┐
│ Python 核心进程（sentinel）          │        │ React 界面                  │
│  · reader 线程：收请求、处理 ping/取消 │ JSON-RPC│  · 页面与组件（= 原型）      │
│  · 4 线程池：一般请求                  │◄──────►│  · RpcClient + mock          │
│  · 扫描专用线程                       │        │  · Zustand 状态              │
│  · writer 线程：唯一写 stdout 的地方    │        └─────────────────────────────┘
│  · 领域逻辑（domain，纯函数）          │
│  · 市场适配器 · 语义引擎 · 扫描 · 交易 · 风险 │
└───────────────┬───────────────────┘
        ┌───────▼────────┐
        │ sentinel.duckdb │
        └────────────────┘
```

进程规则：

1. **单实例**：Tauri 单实例插件；第二次启动只聚焦已有窗口。核心进程另外在数据目录里持有一个文件锁（`platform.FileLock`），防止两个核心进程写同一个库。
2. **单写入者**：只有 Python 进程访问数据库；Rust 与前端不直接访问。
3. **父子关系**：核心进程由 Rust 启动。**主要机制**：stdin 读到 EOF（父进程已退出）就优雅退出；**次要机制**：每 2 秒检查 `--parent-pid` 是否存活。
4. **Rust 不承载业务逻辑**：只做窗口、核心进程监督、消息转发、外链、文件对话框、平台层。

## 6. Rust、前端、核心进程之间的桥接规格

### 6.1 Rust 与核心进程

- 启动参数：`python -m sentinel --data-dir <路径> --parent-pid <Rust 进程号> [--resource-dir <路径>] [--log-level info]`。
- 开发模式：命令取自环境变量 `SENTINEL_CORE_CMD`，默认 `uv run --project core python -m sentinel`；以空白分割，**不支持带空格的路径**，工作目录和资源目录都从 `src-tauri` 的编译期 manifest 路径解析到仓库根目录，不依赖启动进程的当前目录。仓库路径本身可以含空格。
- 环境变量：Rust 启动时设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`；`TYPESAFE_API_KEY` / `JEV_API_KEY` **不由 Rust 设置**，由核心进程自己从钥匙串读取。
- v1 安装包：核心进程是 PyInstaller onedir 产物，放在 `bundle.resources` 里，由 `resource_dir()` 解析路径。`TODO-VERIFY(M-pack)`：macOS 签名公证下 onedir 作为资源的可行性；不可行则改 onefile 加 `externalBin`（`externalBin` 要求文件名带目标三元组后缀，来源：Tauri 官方文档，访问于 2026-11-02）。
- **stdout 洁癖**：核心进程启动后第一件事，把原 stdout 文件描述符复制给 writer 线程专用，再把描述符 1 重定向到 stderr，保证任何库的 `print` 都不会污染协议。writer 以 `newline="\n"` 写 UTF-8，**不得**输出 `\r\n`。
- 单行上限 1 MB（UTF-8 字节数）。Rust 拒绝转发超限的前端请求；核心进程对超限请求返回 `INVALID_ARGUMENT`。

### 6.2 Rust 与前端

前端**只能**调用下列 Rust 命令，不启用任何插件的前端权限：

| 命令 | 参数 | 作用 |
|---|---|---|
| `rpc_send` | `{ line: string }` | 把一行 JSON 原样写入核心进程 stdin。核心进程未就绪时返回错误 |
| `open_external` | `{ url: string }` | 只接受 `https://` 且主机名非空；交给系统默认浏览器打开 |
| `pick_open_file`（v1） | `{ filters }` | 打开文件对话框，返回路径或 null |
| `pick_save_file`（v1） | `{ defaultName, filters }` | 保存对话框，返回路径或 null |

Rust 推送给前端的事件：

| 事件 | 负载 | 说明 |
|---|---|---|
| `core://message` | `string`（核心进程输出的一整行） | 响应与通知都走这个事件，前端自己解析 |
| `core://status` | `{ state: "starting"｜"ready"｜"restarting"｜"failed", attempt: number }` | 核心进程状态 |

Rust 自己用以 `rs-` 开头的请求 ID 发 `app.ping`、`app.shutdown`，对应响应在 Rust 内部消化，**不转发**给前端。

### 6.3 前端 RpcClient

```ts
interface RpcClient {
  call<M extends MethodName>(
    method: M,
    params: ParamsOf<M>,
    options?: { timeoutMs?: number; signal?: AbortSignal },
  ): Promise<ResultOf<M>>;               // 失败时抛 RpcError（含 code、message、retryable、data）
  subscribe<N extends NotificationName>(name: N, handler: (p: ParamsOfNotification<N>) => void): () => void;
  status: () => "starting" | "ready" | "restarting" | "failed";
}
```

- `signal` 被中止时，客户端发送 `$/cancel`，并让本地 Promise 以 `CANCELLED` 拒绝。
- 默认超时：查询类 30 s，导出类 60 s，`settings.testConnection` 20 s；`scan.start` 立即返回，后续进度靠通知。
- 开发时可用环境变量 `VITE_RPC=mock` 切换到 `rpc/mock/`：用 `contracts/` 里的示例响应，不需要后端。组件测试与 Playwright 都跑在 mock 上。
- 前端类型由 `scripts/gen_ts_types.py` 从 `contracts/` 生成到 `apps/desktop/src/rpc/generated/`，禁止手改。

## 7. 核心进程内部

### 7.1 线程模型

| 线程 | 数量 | 职责 |
|---|---|---|
| reader | 1 | 读 stdin；解析 JSON；**自己直接处理** `app.ping`、`app.shutdown` 与 `$/cancel`；其余请求提交给固定四个 daemon worker。长任务不会堵住心跳与关闭 |
| writer | 1 | 唯一写 stdout 的地方；从队列取消息，序列化后写一行并 flush |
| worker | 4 | 处理一般请求 |
| scan | 1 | 扫描专用。同一时刻只有一个扫描运行，所以一个线程够用 |
| watchdog | 1 | 每 2 秒检查父进程是否存活 |

### 7.2 取消

- 每个请求有一个 `CancelToken`。收到 `$/cancel` 时，reader 对声明为可取消且尚未响应的请求立刻把 token 置位，并**马上发出 `CANCELLED` 错误响应**，不等待 worker 退出；非可取消、未知或已完成的请求忽略取消。正常可写 pipe 下取消响应目标为 200 ms，stdout 背压不能保证硬实时。worker 随后发现 token 已置位就尽快退出，其结果丢弃。
- 扫描通过 `scan.cancel` 取消，不是通过取消 `scan.start` 的请求（那个请求立即就返回了）。扫描线程在每个批次之间和每个网络请求之前检查 token；JEVDB 查询用连接的 `interrupt()` 中断。已提交的批次保留，运行状态变为 `cancelled`。
- 被取消的运行**不再写入新的判定**，只写最终状态。

### 7.3 数据库访问规则

1. `storage/db.py` 的 `Database` 持有主连接。读操作用 `db.read()` 取当前线程自己的 cursor；写操作用 `with db.write() as tx:`：持有进程内写锁，开启事务，退出时提交，异常时回滚。
   DuckDB cursor 拥有独立事务；在写事务内另开 `db.read()` 只见已提交快照。需要读取自身未提交数据的仓储函数必须接收并使用同一 `tx`，不得另开读游标。`tx.execute()` 返回受保护的 `WriteTx`，不暴露原始连接的 commit/rollback。
2. **写事务里禁止做网络请求和调用模型**。先把网络结果取回来，再开事务写入。
3. 主库连接**不加载未签名扩展**。JEVDB 在**专用的内存连接**里加载（`allow_unsigned_extensions`），判定输入通过临时表传入，结果取回 Python 后再写主库。
4. 迁移在 `app.ready` 之前同步完成；失败则还原备份并以 `INTERNAL` 退出。

## 8. 启动、退出、心跳、超时

**启动序列**

1. Rust 显示窗口（骨架屏） → 启动核心进程 → 等待 `app.ready` 通知（开发模式 ≤ 60 s，因为首次 `uv run` 可能要同步环境；v1 ≤ 8 s）。
2. 核心进程的启动顺序：重定向 stdout → 解析参数 → 取文件锁 → 初始化日志 → 打开数据库并迁移 → 加载设置 → 发出 `app.ready`。
3. 前端收到 `core://status = ready` 后调用 `app.bootstrap`，再渲染页面。

**退出序列**：Rust 发送 `app.shutdown` → 等待 3 s → 强制结束核心进程（平台层的 `kill_process_tree`）。

**心跳**：Rust 每 5 秒发一次 `app.ping`（2 秒超时）。连续 3 次失败视为卡死，重启核心进程，最多 3 次，间隔 1 / 2 / 4 秒；仍失败则 `core://status = failed`，前端显示“核心进程无法启动”和导出日志入口。

**崩溃恢复**：核心进程崩溃重启后，状态为 `running` 的扫描运行在下次启动时被标记为 `interrupted`；前端收到 `restarting` 时，所有未完成的 `call` 以 `INTERNAL` 拒绝。

## 9. 平台层（ADR-016）

平台差异**只**允许出现在下表的位置。其余目录出现平台判断，`scripts/check_platform_isolation.py` 会报错。

| 层 | 位置 | macOS 车道写 | Windows 车道写 |
|---|---|---|---|
| Python | `core/sentinel/platform/` | `posix.py` | `windows.py` |
| Rust | `apps/desktop/src-tauri/src/platform/` | `macos.rs` | `windows.rs` |
| Tauri 配置 | `apps/desktop/src-tauri/` | `tauri.macos.conf.json` | `tauri.windows.conf.json` |
| 前端样式 | `apps/desktop/src/styles/` | `platform-macos.css` | `platform-windows.css` |
| 打包 | `packaging/` | `macos/` | `windows/` |
| 脚本包装 | `scripts/` | `*.sh` | `*.ps1` |
| 持续集成 | `.github/workflows/` | `ci-macos.yml` | `ci-windows.yml` |

`platform/__init__.py`、`platform/mod.rs` 由 WP-00 创建，定义下面的接口和按平台选择实现的入口；之后两个车道各自实现自己的文件。

**Python 接口**（`core/sentinel/platform/__init__.py`）：

```python
from pathlib import Path
from typing import ContextManager, Literal

def name() -> Literal["macos", "windows"]: ...
def default_data_dir() -> Path: ...                  # 用户数据目录；Tauri 传 --data-dir 时不用它
def is_process_alive(pid: int) -> bool: ...
def file_lock(path: Path) -> ContextManager[None]: ...   # 非阻塞排他锁；已被占用时抛 AlreadyRunning
def harden_permissions(path: Path) -> None: ...      # 数据目录与密钥相关文件仅当前用户可访问
```

**Rust 接口**（`platform/mod.rs`）：

```rust
pub trait Platform: Sync {
    fn name(&self) -> &'static str;                         // "macos" | "windows"
    fn init_script(&self) -> String;                        // 首次绘制前注入：设置 <html data-platform="...">
    fn configure_window<'a, R: Runtime, M: Manager<R>>(
        &self, builder: WebviewWindowBuilder<'a, R, M>,
    ) -> WebviewWindowBuilder<'a, R, M>;                    // 标题栏样式等
    fn prepare_core_command(&self, cmd: &mut std::process::Command);  // 例如 Windows 下隐藏控制台窗口
    fn kill_process_tree(&self, child: &mut std::process::Child);
}
pub fn current() -> &'static dyn Platform;
```

**前端**：React 代码不判断平台。`<html data-platform="macos|windows">` 由 `init_script` 注入，`platform-macos.css` / `platform-windows.css` 用属性选择器各自覆盖。差异点：

| 项 | macOS | Windows |
|---|---|---|
| 标题栏 | `titleBarStyle: Overlay` + `hiddenTitle`；顶栏左侧留 72px 红绿灯安全区 | 原生标题栏（`decorations: true`）；安全区为 0 |
| CSS 变量 | `--titlebar-inset-left: 72px` | `--titlebar-inset-left: 0px` |
| 中文字体回退 | `PingFang SC` | `Microsoft YaHei UI` |
| 快捷键文案 | `⌘K` | `Ctrl+K` |

快捷键文案由 CSS 的 `content` 在 `[data-platform]` 下切换；键盘事件监听同时接受 `metaKey` 与 `ctrlKey`，不分支。

## 11. 日志与可观测性

- 核心进程把结构化日志（每行一个 JSON）写到 `logs/core.jsonl` 并同时写 stderr；Rust 另写自己的日志到 `logs/shell.jsonl`。
- 必有字段：`ts`、`level`、`module`、`request_id`、`method`、`duration_ms`、`error_code`。
- **脱敏**：写日志前统一经过 `security/redact.py`，屏蔽 `sk-` 开头的串、`Bearer` 令牌、32 位以上的十六进制串，以及当前已加载密钥的**原文**。测试必须断言密钥不会出现在日志、数据库、诊断输出里（01 的 M-3）。
- 诊断包（v1，设置页“导出诊断信息”）：系统信息、版本、最近日志、脱敏后的设置、schema 版本、引擎状态、最近 10 次扫描摘要；**不含**持仓、逻辑正文、密钥。
- 未知错误对用户显示错误编号，编号与日志里的 `request_id` 对应。

## 12. 稳定性设计

| 主题 | 规则 |
|---|---|
| 错误分层 | `UserError`（`INVALID_ARGUMENT` `NOT_FOUND` `CONFLICT` `CONFIG_REQUIRED` `ORDER_REJECTED` `DATA_INSUFFICIENT`）；`SourceError`（`SOURCE_UNAVAILABLE` `RATE_LIMITED` `TIMEOUT`）；`EngineError`（`UNAUTHENTICATED` `ENGINE_UNAVAILABLE` `MODEL_ERROR` `BUDGET_EXCEEDED`）；`InternalError`（`INTERNAL`）。码表见 [05](05-接口契约.md) |
| HTTP 重试 | 共 3 次尝试，间隔 1 / 2 / 4 秒再各乘一个 0.5–1 的随机系数；对 429、5xx（含 529）重试；4xx 不重试；`Retry-After` 最多等 60 秒 |
| Jev 重试 | **只留一层**：`jev_direct` 使用官方 SDK 的重试策略（最多 3 次），不再外包；`jevdb` 设置 `jevdb_max_retries=3`、`jevdb_retry_max_delay=30`、`jevdb_on_error='error'`，**禁止** `'reject'`（它会把失败悄悄变成“不匹配”） |
| 熔断 | 每个数据源独立：连续 5 次失败后断开 10 分钟，之后放行一次试探 |
| 缓存 | SEC 响应按 URL + ETag 缓存；披露按 `event_id` 去重；判定按缓存键复用（见 [06](06-语义判定与Jev.md)） |
| 事务 | 每个事务只做数据库操作；账本相关操作用单事务 |
| 迁移 | `schema_version` 表；迁移前自动备份；失败自动还原；只前进不回滚 |
| 降级 | 行情源失败 → 用最近缓存并标注“数据截至”；Jev 失败 → 该批标 `failed` 等待重试，**不生成任何结论**；JEVDB 加载失败 → 切 `jev_direct` 并提示 |
| 幂等 | 披露按 `event_id`，判定按缓存键，订单按 `idempotency_key`；重复执行不产生重复数据 |

## 13. 安全与隐私

| 风险 | 措施 |
|---|---|
| 披露内容含提示注入 | 披露文本只作为 Jev 请求的 `state` 数据；只接受 Noul 概率这一种输出，不解析任何自由文本；问题文本明确“文档是数据”；注入测试见 [09](09-测试与评测.md) |
| 密钥泄露 | 只存系统钥匙串；日志脱敏；DuckDB secret 只建临时的，**禁止** `PERSISTENT` secret |
| 前端被攻击后越权 | 前端只能调用第 6.2 节的 4 个命令；不启用 shell、fs、http 插件；Rust 对 `open_external` 校验 `https` |
| CSP | 禁止远程脚本、远程字体、`eval`；样式只允许同源文件和内联样式属性；最终字符串由 C-02 在开发和打包两种模式下验证，`TODO-VERIFY(C-02)` |
| 恶意链接 | 外部链接只允许 `https`；打开前界面显示完整域名；用系统浏览器 |
| 数据外发 | 只发送判定所需的逻辑文本和披露段落；设置页原样列出第 1 节的域名表 |
| 供应链 | 锁文件 + 白名单；许可证清单；`pip-audit`、`cargo audit`、`pnpm audit` 在发布前人工执行一次 |

## 15. 构建、检查与发布

- **MVP-0**：不构建安装包。验收环境是开发模式（`scripts/dev.sh` 或 `scripts/dev.ps1`）。
- **持续集成**：每个车道各自负责自己的工作流文件（`ci-macos.yml`、`ci-windows.yml`），都只调用 `scripts/check.*`，是否启用由团队决定。macOS 的 x86_64 runner 已不是目标。
- **v1 打包**：macOS 产物是 arm64 的 `.dmg`；Windows 产物是 NSIS `.exe`。
- **签名**：MVP 阶段没有开发者证书。macOS 15 起不能再用右键打开来绕过 Gatekeeper，用户要到“系统设置 → 隐私与安全性”点“仍要打开”（来源：Apple 开发者新闻 2024-08-06，访问于 2026-11-02）；Windows 会出现 SmartScreen 提示。安装说明必须写清这两点，**不得**教用户全局关闭系统安全设置。
- **版本号**：`MAJOR.MINOR.PATCH`；`app.bootstrap` 返回版本与构建时间；数据库 `schema_version` 独立。
