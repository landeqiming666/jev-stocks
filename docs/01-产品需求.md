# 01 产品需求

> 版本：v2.1 · 2026-11-02 · 状态：已定稿；定位修订待小组确认
> 产品名：投资逻辑哨兵（Thesis Sentinel），内部代号 `sentinel`。术语见 [00-术语与约定.md](00-术语与约定.md)。

## 0. 产品定位

**品类**：投资逻辑监控器（thesis monitor）。不是 AI 选股器，也不是荐股助手。

**定位陈述**：给持有 3–20 只美股、会自己研究但没时间天天读公告的个人投资者，Thesis Sentinel 是一个本地运行的投资逻辑监控器：你写下买入理由，它每天只挑出真正动摇这些理由的披露，并附上原文；它不荐股、不预测、不替用户决策。

**口号**：不推荐股票，只守住你买入的理由。

**产品承诺**：每天 30 秒，知道持仓逻辑有没有被新披露动摇。默认最多 5 条；没有变化时明确说“今天没有需要处理的变化”。

**三个差异点**

1. 监控对象是“你的判断”，不是股票代码。
2. 只输出类型化关系（无关/支持/削弱/推翻）与原文证据，不生成长篇观点。
3. 本地数据 + JEVDB 批量判定，成本低到可以每天跑。

**它不是什么**

| 不是 | 原因 |
|---|---|
| 选股器 | 不帮用户发现新标的，只监控已写下的判断 |
| 荐股/预测工具 | 不给目标价、收益预测或买卖建议 |
| 股票问答聊天框 | 用户不需要每天提问，系统主动给出“需要处理的事” |
| 券商交易终端 | 不接真实下单；模拟交易只用于复盘与课程验收 |

## 1. 一句话定义

记下你买入每只股票的理由；系统每天把新披露与这些理由逐条比对，只在披露**削弱或推翻**理由时提醒你，并附上原文。判断归你，系统只负责盯住判断的前提。

## 2. 要解决的问题

个人投资者面对的不是“没有信息”，而是“信息与自己的判断脱节”：

1. **提醒太粗**：券商 App 的公告推送按“股票”订阅，不区分例行公告与实质变化。一只股票一个月十几条公告，用户最终关闭提醒，重要变化随之漏掉。
2. **买入理由无处安放**：买入时的判断留在脑子里或聊天记录里，事后无法检查“当初的逻辑还成立吗”。
3. **AI 荐股不可信**：现有 AI 投研工具替用户下结论，结论会翻转、依据难追溯。

核心洞察：用户需要的不是另一个“告诉我买什么”的 AI，而是一个**守住自己判断**的助手。判断由人做，系统负责盯住判断的前提是否还成立。

**现有替代方案为什么不够**

| 替代方案 | 局限 |
|---|---|
| 券商 App / 同花顺公告推送 | 按股票推全部公告，不理解用户的投资逻辑，噪声大 |
| SEC Alerts / 邮件订阅 | 按表单或公司订阅，仍需人工逐条判断是否影响自己的逻辑 |
| AI 投研聊天 / TradingAgents | 一次性深度报告，慢且贵，倾向于给结论；不是每天守持仓 |
| 笔记 / Notion / Excel | 能记录理由，但不会主动监控，也不会把新披露关联回理由 |
| 自己读 8-K / 6-K | 准确，但时间成本高，持有 10 只以上就容易漏 |

## 3. 需求证据与可信度

2026-11-02 在 V2EX、Hacker News 和 GitHub 热门股票项目 issue 中检索（Reddit、雪球无可用数据，X、小红书、知乎未覆盖）：

| 痛点 | 证据 | 强度 |
|---|---|---|
| 交易记录与复盘缺工具 | V2EX 多帖求“记录买卖原因、阶段收益”的复盘工具 | 强，多源重复出现 |
| 只想知道和持仓相关的少数要事 | HN “每日 AI 持仓简报”讨论；HN 减少过度交易工具强调“明确告诉你无需操作” | 中 |
| 公告冗长，怕漏重要消息 | HN SEC Alerts 作者自述痛点 | 中 |
| 提醒只在 App 内、到价提醒不便 | V2EX 自建推送、多个盯盘插件 | 强 |
| 不信任 AI 结论 | V2EX “AI 炒股分析不到位”；TradingAgents issue：同日结论翻转、未来数据泄漏 | 中 |

诚实结论：

- “公告提醒”本身是已被基本满足的旧需求，单做这一层没有竞争力。
- “按个人投资逻辑过滤公告”只有间接证据，未见到直接对标产品，但检索范围有限。
- 因此 v1 必须内置需求验证（见第 10 节），用真实使用数据决定是否继续投入。

## 4. 目标用户

### 4.1 主用户画像（ICP）

| 维度 | 具体描述 |
|---|---|
| 身份 | 25–45 岁的在职人士或研究生，有稳定收入，自己管理一部分资金 |
| 持仓 | 3–20 只美股，持有周期数月至数年，不做日内 |
| 研究习惯 | 买入前看过财报/新闻，能用自己的话写出 1–3 条买入理由；会用备忘录、Notion 或聊天记录记判断 |
| 使用频率 | 每周看几次盘，没时间每天读公告；希望有人替他盯住持仓 |
| 关键约束 | 不想把持仓和判断上传到云端；不愿为“AI 荐股”付费 |
| 成功时刻 | 早上 30 秒看完清单，确认“今天没事”，或者及时发现一条推翻原逻辑的披露 |

### 4.2 核心任务（JTBD）

1. 当我买入一只股票后，我想确保当初的理由没有被新披露推翻，这样我不会在逻辑失效后还继续持有。
2. 当我看到大量公告时，我想只看到与我的判断相关的少数几条，这样我不用全部读完。
3. 当我想复盘时，我想看到当时的理由、期间发生的事和我的处理，这样我能判断自己的决策过程，而不只是看盈亏。

### 4.3 非目标用户

- 短线、日内、打板交易者：需要秒级行情与盘口，不需要“长期逻辑监控”
- 期权、杠杆、合约交易者：风险模型与产品假设不同
- 只买指数基金、不写个股逻辑的被动投资者：没有可监控的 thesis
- 机构投研：需要付费数据、合规与团队协作能力

### 4.4 次用户

投资学习者 / 课程小组：想练习“写下逻辑 → 验证逻辑 → 复盘决策”的研究方法，需要可记录、可演示、可评测的原型。

## 5. 核心体验

```text
记录逻辑 ──► 扫描披露 ──► 待处理清单 ──► 查看证据 ──► 处理（仍然成立 / 修正 / 准备卖出 / 忽略）──► 复盘（v1）
```

MVP-0 的一次典型使用：

1. 用户搜索并添加持仓或关注的美股，为每只写 1–5 条投资逻辑，可选填失效条件。
2. 用户点“立即扫描”。系统抓取这些标的自上次扫描以来的 8-K / 6-K，切成段落，用 Jev 判断每个段落与每条逻辑的关系。
3. 今日页显示待处理清单：每条有标的、关系标签、概率、用户当初写的逻辑、证据句、原文链接。
4. 用户打开证据抽屉核对原文，选择处理方式。处理过的条目移出清单。
5. 没有任何待处理条目时，页面写“今天没有需要处理的变化”，并告知检查了多少标的、披露和段落。

v1 把第 2 步改为定时自动执行，应用常驻托盘，结果以系统通知推送。

## 6. 阶段范围

### 6.1 MVP-0 保底版

目标：约 1 周内做出一个能演示、能交作业的版本。以开发模式运行，不做安装包。**macOS（Apple Silicon）是主线，验收以它为准**；Windows 由独立车道并行做到“开发模式对等”，不阻塞 macOS 验收（见 [ADR-016](decisions.md)）。

> 范围说明：本产品的核心是“持仓逻辑监控”。模拟交易与风险分析是支撑“验证与复盘”的课程模块，不构成对外定位；界面与文档不得把它们包装成交易终端或投资建议工具。

| 模块 | 包含 |
|---|---|
| 标的与持仓 | 美股标的搜索（代码、英文名、中文别名）；登记持仓（数量、成本、备注）；只关注（数量 0）；归档 |
| 投资逻辑 | 每只最多 5 条有效逻辑；正文 1–500 字，失效条件 ≤ 300 字；中文或英文；版本历史；乐观锁；归档 |
| 披露与判定 | 手动扫描 8-K、8-K/A、6-K 及其 EX-99.* 附件；Jev 判定；证据句；两个引擎（JEVDB、Jev 直连） |
| 待处理清单 | 今日页；证据抽屉；四种处理方式和“重新打开”；空状态 |
| 扫描统计 | 扫描页：每次运行的数量、token、估算费用、耗时、引擎、失败批次；每日预算 |
| 模拟交易 | 模拟账户；开盘市价单；回放时钟与“下一交易日”；费用与滑点；拒单原因；持仓、现金、权益 |
| 风险 | 美元口径：年化波动率、最大回撤、有效持仓数、相关系数热图、SVD 解释方差 |
| 设置 | Jev 密钥、SEC 联系邮箱、引擎选择、连通性测试、外联域名清单、每日预算 |
| 演示与评测 | 演示数据脚本（虚构公司）；至少 60 对的标注集与评测脚本，中英文逻辑分开报告 |

MVP-0 **明确不做**：定时扫描、托盘、开机自启、通知与推送、首次启动引导、复盘页、命令面板、CSV 导入、10-Q / 10-K / 20-F / Form 4、人民币口径、限价单、K 线图、安装包、自动更新、Intel Mac、A 股与港股。

### 6.2 v1 完整美股版

在 MVP-0 之上增加：

- 应用关窗后驻留托盘（macOS 菜单栏），开机自启可选且默认关闭；每天 08:30 / 20:30（用户时区）定时扫描；睡眠错过的扫描在唤醒后 6 小时内补跑一次。
- 系统通知；飞书 Webhook（不发送持仓数量和成本）。
- 首次启动引导（3 步，可跳过）、复盘页（时间线 + K 线 + 事件标记）、命令面板、CSV 导入。
- 10-Q、10-K、20-F、Form 4 披露类型。
- 人民币口径的风险分析；限价单。
- 诊断包导出、数据备份与恢复。
- macOS 安装包（arm64）与 Windows x64 安装包，分别由对应车道交付；7 天稳定性测试；至少 200 对的评测集与 G2 闸门。

### 6.3 平台分工与 v2

| 项 | 内容 |
|---|---|
| macOS 车道 | MVP-0 与 v1 的主线。共享代码、macOS 专属代码、macOS 验收都由它负责 |
| Windows 车道 | **MVP-0 暂缓**（ADR-017）。W-00～W-05 文档保留，但不派发；macOS 版本稳定后再恢复，目标是 v1 安装包、原生标题栏、托盘与自启清理 |
| v2 | A 股、港股：公告适配器、PDF 正文抽取、整手与涨跌停规则、跨市场风险与汇率口径、红涨绿跌。旧版 v1.0 文档里的相关设计保存在 `.kiro/backup/`，届时重新设计 |

### 6.4 永远不做

- 不给出买卖建议、目标价或收益预测。
- 不接入真实券商下单。
- 不做实时行情与盘中交易。

## 7. 用户故事与验收（MVP-0）

每条故事的验收用 Given / When / Then 写成，可以直接转成端到端测试。“页面”指 [03-界面设计规范.md](03-界面设计规范.md) 里的页面。

### US-01 搜索并添加美股标的
- 页面：持仓
- Given 标的表已加载（首次启动联网下载，之后读本地缓存）。
- When 我在添加框输入 `AAPL`、`apple` 或 `苹果`。
- Then 300 ms 内列表显示 `us:AAPL`，含代码、英文名、交易所；选中后该标的出现在持仓页。
- And 输入不存在的代码时显示“没有找到匹配的美股标的”，而不是空白。

### US-02 登记持仓或只关注
- 页面：持仓
- When 我为一个标的填写数量和成本并保存。
- Then 持仓表出现该行，数量与成本按 [00](00-术语与约定.md) 的金额格式显示。
- When 我把数量填 0。
- Then 该标的标记为“关注”，仍可写逻辑、参与扫描，但不计入风险权重。
- And 数量为负数或非数字时被拒绝，并在字段下提示原因。
- And 归档一个持仓后，它从列表消失，历史判定仍可查询。

### US-03 写投资逻辑
- 页面：持仓（行内编辑器）
- When 我为 `us:ZZAR` 写下逻辑“控股股东长期持股，不会大幅减持”，失效条件“控股股东减持超过 2%”，保存。
- Then 逻辑保存为第 1 版，出现在该标的下。
- And 正文为空、纯空白、超过 500 字，或失效条件超过 300 字，保存被拒绝，字段下显示具体原因。
- And 同一标的已有 5 条有效逻辑时，“添加逻辑”按钮禁用，并说明上限。
- And 编辑器旁提示：“精确的数值比较请写进失效条件的文字里，例如‘减持超过 2%’，系统按字面理解。”

### US-04 修改与归档逻辑
- 页面：持仓
- When 我修改一条逻辑并保存。
- Then 生成新的版本（版本号 +1），旧版本仍可在版本历史里查看。
- When 两个窗口同时修改同一条逻辑，后保存的一方。
- Then 收到“这条逻辑已被修改，请刷新后再试”，不覆盖对方的修改。
- When 我归档一条逻辑。
- Then 它不再参与扫描，但历史判定与处理记录保留。

### US-05 配置密钥与联系邮箱
- 页面：设置
- Given 尚未配置。
- When 我点“立即扫描”。
- Then 扫描不会开始，页面提示“请先填写 Jev 密钥和 SEC 联系邮箱”，并带一个跳转到设置页的按钮。
- When 我填写密钥并保存。
- Then 设置页只显示“已保存”，任何界面和接口都不再返回密钥明文；密钥存入系统钥匙串。
- When 我点“测试连接”。
- Then 看到 Jev 与 SEC 的连通结果、延迟、当前引擎（JEVDB 加速 / Jev 直连）和模型 ID；失败时显示原因与建议。
- And 设置页列出本应用会访问的全部外部域名。

### US-06 手动扫描
- 页面：今日、扫描
- Given 至少一个标的有至少一条有效逻辑，且已配置密钥与邮箱。
- When 我点“立即扫描”。
- Then 看到进度（阶段：抓取、解析、判定、完成；已完成 / 总数），首次扫描默认覆盖最近 7 天，之后从上次成功扫描的水位线继续。
- And 点“取消”后 1 秒内停止发起新的请求，已完成的批次保留，运行状态为 `cancelled`。
- And 扫描进行中，再次点击“立即扫描”被拒绝并提示“扫描正在进行”。
- And 没有任何有效逻辑的标的不会被扫描，页面告知“N 只标的因没有逻辑被跳过”。

### US-07 查看待处理清单
- 页面：今日
- Given 扫描产生了判定。
- Then 今日页顶部显示“今天有 N 件事需要你看一眼”（N 为未处理的推翻 + 削弱条目数）。
- And 条目按严重度排序（推翻在前，削弱在后），同级按概率从高到低；前 5 条展开，其余折叠为“其余 M 条”。
- And 每条显示：市场徽标、代码与名称、关系标签、概率、我写的逻辑摘要、证据摘要（≤ 2 行）、披露标题与发布时间、三个操作。
- And “待确认”的条目单独折叠成一组，标题为“系统拿不准的 K 条”，不计入 N。

### US-08 核对证据
- 页面：今日（证据抽屉）
- When 我点“查看原文”。
- Then 右侧抽屉打开，显示：整段原文，其中证据句高亮；披露标题、类型（8-K / 6-K）、发布时间、SEC 原文链接；我的逻辑与失效条件；五个概率；引擎徽标与模型 ID。
- And 当证据只能用整段（没有单句达到阈值）时，显示“未能定位到单句，以下为整段原文”。
- And 当披露只有标题没有正文时，显示“仅依据标题判定”。
- And 点击原文链接用系统浏览器打开，打开前显示完整域名，只允许 `https`。

### US-09 处理判定
- 页面：今日
- When 我选择“仍然成立”“修正逻辑”“准备卖出”或“忽略”，可附一句备注。
- Then 该条目移出待处理清单，处理记录被保存；选“修正逻辑”会打开该逻辑的编辑器，但不会自动修改逻辑；选“准备卖出”只记录意图，不会产生任何订单。
- And 今日页底部“已处理”折叠区列出最近 30 天的处理记录，每条可“重新打开”，重新打开后回到清单。

### US-10 没有事时的空状态
- 页面：今日
- Given 清单为空且至少完成过一次扫描。
- Then 页面用大字写“今天没有需要处理的变化”，下方写“已检查 3 只标的、4 份披露、27 个段落，上次扫描 2026-11-02 08:31”（数字取实际值）。
- Given 还没有任何标的。
- Then 显示引导“先添加第一只标的”，带跳转按钮。

### US-11 扫描统计与预算
- 页面：扫描
- Then 扫描页列出每次运行：时间、标的数、披露数、段落数、判定数、请求数、token 用量、估算费用（美元）、耗时、引擎、模型 ID、状态。
- When 我点开一次运行。
- Then 看到每个批次的结果，失败批次显示失败原因和“重试”按钮。
- And 页面顶部显示“今日已用 X / 2,000,000 tokens”；用量达到上限时，剩余批次挂起，运行状态为 `partial`，并提示“今日预算已用完”。

### US-12 失败可见与降级
- Given 断网，或 SEC、Jev 暂时不可用。
- When 我打开应用或点“立即扫描”。
- Then 应用不崩溃；已有的清单、持仓、逻辑、账本照常可查看；页面显示失败原因和数据截至时间；失败的批次保留，下次扫描自动重试。
- And 引擎降级（JEVDB 加载失败，改用 Jev 直连）时，顶栏徽标变为“Jev 直连”，并出现一次可见的提示。
- And 任何模型调用失败都不会被当成“无关”静默丢弃。

### US-13 回放模式模拟交易
- 页面：交易
- When 我创建模拟账户：名称、初始现金（美元）、回放起始日（过去的某个交易日）。
- Then 账户当前模拟日期为起始日，现金为初始值。
- When 我下一笔买入 `us:ZZFD` 100 股的开盘市价单。
- Then 订单状态为“待成交”，资金被冻结；点“下一交易日”后，按该日开盘价加滑点成交，现金、持仓、权益更新，成交记录显示价格、数量、费用。
- And 资金不足、卖出超过持仓、数量不是正整数、目标日没有价格（连续 5 个交易日仍无价则拒单）时，订单被拒绝，并显示中文原因。
- And 相同的幂等键重复提交只成交一次。
- And 回放期间，任何估值和撮合都不会使用模拟日期之后的行情。

### US-14 查看风险
- 页面：风险
- Given 至少 2 只持仓（数量 > 0）且各有至少 60 个共同交易日的行情。
- Then 显示年化波动率、最大回撤、有效持仓数、权重最大的 3 只标的占比、相关系数热图、SVD 前 5 个主成分的解释方差。
- Given 共同交易日少于 60。
- Then 显示“样本不足：共同交易日 N 天，至少需要 60 天”，不显示任何数字。
- And 任何数字都能通过切换“表格视图”读到。

### US-15 演示数据
- 页面：设置（“载入演示数据”）
- When 我运行 `scripts/load_demo.sh`（或点设置页的按钮）。
- Then 数据库中出现 [00](00-术语与约定.md) 里的 6 家虚构公司、各自的逻辑、披露事件与预置判定、合成行情；全部页面有内容可看。
- And 演示脚本在 `SENTINEL_OFFLINE=1` 下可以完整跑完 5 分钟流程。
- And 演示数据明确标注“示例数据”，不会与真实数据混淆，可一键清除。

## 9. 产品原则

1. **判断归用户**：系统只报告“事件与你的逻辑的关系”，不替用户决策。
2. **每条提醒都有依据**：判定必须附原文句子与来源链接；没有依据的结论不展示。
3. **宁可少推，不可乱推**：清单只含推翻和削弱；“待确认”折叠；默认展开 5 条。
4. **数据留在本地**：持仓数量、成本、备注永远不离开本机。**会发给 Jev 的只有**：逻辑正文、失效条件、披露段落。设置页必须如实列出这一点和全部外联域名。
5. **失败必须可见**：缓存数据、仅标题、整段证据、引擎降级、预算耗尽，一律在界面标注。
6. **不用未来信息**：回放、估值、复盘只使用当时已经公开的数据。
7. **安静**：界面没有红绿闪烁、没有跑马灯、没有“紧急”角标。

## 10. 为什么用 Jev

产品里的判断都是“这段话与我的逻辑是否相关、是否削弱了它”这类**有类型的决策**，不需要生成文字。

| 对比 | 说明 |
|---|---|
| Jev 的特点 | 是“决策模型”：一次请求可带多个问题，每个问题返回概率或选项，不生成文字。输入按 token 计费，输出免费；定价在 [models 页](https://docs.typesafe.ai/models)（访问于 2026-11-02）。官方文档说明英文效果最好，中日韩文字“能处理但效果不如英文”，并列出已知弱点：只按字面理解、不擅长数值与日期比较、输入里无关内容越多越不准、对抗性文本会影响答案。本产品的设计逐条对应这些弱点，见 [06-语义判定与Jev.md](06-语义判定与Jev.md) |
| JEVDB 的作用 | 把语义判断写进 SQL（语义连接、键剪枝、批处理）。本产品里，键剪枝的实际效果等同于“只拿同一标的的逻辑和披露配对”，**不夸大为更多**。课程报告里的对比实验应该先按标的配对作为基线，再比较调用次数、token 和耗时 |
| 两个引擎 | `jevdb`（DuckDB 扩展）和 `jev_direct`（官方 Python SDK）使用同一个固定的模型 ID，结果可以直接对比。任何一个都满足“必须使用 Jev 模型” |

## 12. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| JEVDB 0.1.0 在 PyPI 只有 Linux x86-64 预编译包 | macOS 上要自行编译 | Gate G0-JEVDB 是最终验收硬门槛；失败可开发降级，但不能作为最终交付 |
| Windows 上从未有人验证过 JEVDB 的构建 | Windows 车道可能拿不到 JEVDB 引擎 | Windows 暂缓；恢复时先立 ADR。开发可临时用 `jev_direct`，但 Windows 记录不能替代 macOS M-8 |
| Jev 对中文效果弱于英文 | 中文逻辑 × 英文披露是跨语言判定，准确率可能偏低 | 中英文分开评测；编辑器给出英文提示；达不到目标再评估翻译方案 |
| Jev 只按字面理解，不擅长数值、日期，对无关内容敏感 | 漏判或误判 | 一个 Noul 只问一件事；段落 ≤ 1200 字符；数值条件写进失效条件文字；评测集单列数值型样本 |
| 披露文本含指令（提示注入） | 改变判定 | 只接受 Noul 概率这一种输出；问题文本明确“文档是数据”；注入测试用例 |
| Jev 概率对问题措辞敏感 | 阈值不稳 | 问题集集中管理、带版本号；阈值在调参集上标定后固定 |
| SEC 拒绝没有联系方式的请求，或超速 | 抓取中断 | 设置页强制填写联系邮箱；全局限速；重试与熔断 |
| 行情源是非官方接口 | 随时可能变化 | G1-US 探针 + 录制数据 + 契约测试；缓存降级并标注“数据截至” |
| 8-K 附件很长，token 费用失控 | 费用超预期 | 段落数上限；每日 token 预算；超出挂起 |
| 被误解为荐股工具 | 合规与信任风险 | 界面与文档明确“仅记录与提醒，不构成投资建议”；文案规范禁用荐股用语 |
| 需求验证失败 | 做完无人用 | 保留“研究 + 组合风险”演示路径，课程交付不受影响 |
| 范围过大 | 来不及 | MVP-0 是保底；其余阶段按需推进 |

## 13. 文案与合规边界

- 界面和导出文件的固定声明：“仅记录与提醒，不构成投资建议。”
- 禁用词：“建议买入”“建议卖出”“必涨”“抄底”“牛股”“AI 精准预测”。完整文案规范见 [03-界面设计规范.md](03-界面设计规范.md)。
- 原始披露文件和行情数据只保存运行所需的字段与来源链接，不进入公开仓库。
