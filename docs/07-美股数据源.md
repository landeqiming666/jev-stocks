## 1. 原则

1. 数据源全部是**公开接口**，不需要付费账号。SEC 是官方来源；行情源是非官方来源，随时可能变化，所以只通过适配器接口访问，并有契约测试和降级。
2. **所有外部数据视为不可信输入**：解析失败写脱敏的原始响应摘要（前 500 字符）到日志，报 `SOURCE_UNAVAILABLE`，不让异常穿透。
3. 适配器只做“取数与规范化”，不做判定；返回的数据必须带 `source` 与 `fetched_at`。
4. 只保存运行所需的字段与来源链接。披露原文、行情数据**不进入公开仓库**（测试用的少量片段见第 10 节）。
5. 遵守来源条款与速率限制。SEC 的限速、`User-Agent` 要求是硬约束（第 2 节）。
6. 设置了 `SENTINEL_OFFLINE=1` 时，所有适配器在发出任何网络请求之前抛 `SOURCE_UNAVAILABLE`（`data.reason = "OFFLINE"`）。

## 2. SEC 访问规则

| 项 | 规则 | 核实 |
|---|---|---|
| `User-Agent` | SEC 要求每个请求带能识别请求者的 `User-Agent`，格式为“名称 联系邮箱”。我们用 `Sentinel/<版本> <用户在设置页填写的联系邮箱>`，例：`Sentinel/0.1.0 name@example.com` | **已验证（2026-11-02）**：带 `SentinelResearch/0.1 (research prototype; contact: …)` 时三个 SEC 端点均返回 200；不带或使用空 UA 时曾返回 403。测试用占位邮箱，正式使用必须填真实邮箱 |
| 限速 | SEC 的公平访问限制为每秒 10 个请求。我们**全局**限制在每秒 **5** 个（令牌桶，容量 5，每秒补 5 个），所有 SEC 主机（`www.sec.gov`、`data.sec.gov`）共用一个桶 | `TODO-VERIFY(G1-US)`：本轮只做了单请求验证，未做限速压测 |
| 未填写邮箱 | 没有联系邮箱时**不发任何 SEC 请求**，抛 `CONFIG_REQUIRED`（`data.missing = ["secEmail"]`） | — |
| 被拒 | 403 → `SOURCE_UNAVAILABLE`，`data.reason = "SEC_FORBIDDEN"`，文案“SEC 拒绝了请求，请检查设置里的联系邮箱是否有效”；同时让该来源熔断 10 分钟 | — |
| 压缩 | 请求头带 `Accept-Encoding: gzip, deflate`（httpx 默认） | — |
| 条款 | 不得对 SEC 站点做超出公平访问的抓取；不得转存、再分发原文 | — |

## 3. HTTP 客户端（D-01）

所有网络访问（SEC、行情源、汇率源）走同一个 `sentinel.http.client.HttpClient`，由 D-01 实现：

| 能力 | 规格 |
|---|---|
| 超时 | 连接 5 秒，读取 20 秒，总计 30 秒 |
| 重试 | 共 3 次尝试，间隔 1、2、4 秒各乘一个 0.5–1.0 的随机系数；对 429、5xx（含 529）、连接错误、读取超时重试；4xx（429 除外）不重试；响应有 `Retry-After`（秒）时取 `max(退避, Retry-After)`，上限 60 秒 |
| 熔断 | 按“来源名”独立；连续 5 次失败（重试耗尽算 1 次）→ 打开 10 分钟，期间立即抛 `SOURCE_UNAVAILABLE`；到期后放行 1 个试探请求，成功则关闭，失败则再开 10 分钟；打开时发 `source.degraded` 通知 |
| 限速 | 按“来源名”配置的令牌桶（SEC：5 次/秒）；取不到令牌时阻塞等待，最长 30 秒，超过抛 `TIMEOUT` |
| 缓存 | 可选；用于 SEC 的 `GET`。键 = `sha256(url)`，文件放 `cache/http/`，同时保存 `ETag` 与 `Last-Modified`；再次请求时带 `If-None-Match` / `If-Modified-Since`，304 则用缓存。无 `ETag` 且 `Last-Modified` 缺失的响应不缓存 |
| 编码 | 以响应头的字符集解码；缺失时先试 UTF-8，再试 `windows-1252`；仍失败抛 `SOURCE_UNAVAILABLE` |
| 大小 | 单个响应最多读取 5 MB，超过截断并 `warn` |
| 取消 | 每次发请求前检查 `CancelToken` |
| 日志 | 记录 `source`、`method`、脱敏后的 URL、状态码、耗时、重试次数；**不记录响应体** |

| 核实 | **已验证（2026-11-02）**：字段顺序与样例一致，交易所取值含 `Nasdaq`、`NYSE`、`CBOE` 等；备选地址未测 |

### 4.2 导入规则

1. 只保留交易所属于 `{Nasdaq, NYSE, NYSE American, CBOE}` 的行（`OTC` 等丢弃）。交易所名统一成 `NASDAQ`、`NYSE`、`NYSE American`、`CBOE`。
2. `symbol` 规范化：转大写；类股的连字符改成点（`BRK-B` → `BRK.B`）；含空格或其他字符的跳过并计数。
3. `instrument_id = "us:" + symbol`。同一 `symbol` 出现多次（同一公司的多个证券类别）时，保留 `cik` 最小的那一行并 `warn`。
4. `cik` 保存为 10 位数字字符串（左补 0）。
5. 中文名与别名来自 `resources/aliases/us_zh.json`（4.3）。
6. 整个导入在**一个事务**里完成：`INSERT … ON CONFLICT (market, symbol) DO UPDATE` 更新非主键列；本次文件里没出现的旧标的把 `is_active` 置为 `FALSE`（不删除）。同时重建该批标的的 `instrument_alias`。
7. 刷新时机：应用启动后，若 `instrument` 表为空，或 `lastTickerRefreshAt` 距今 > 7 天，且不离线且已配置联系邮箱 → 后台刷新；失败不影响使用（用旧表），`warn` 日志。首次启动且没有邮箱、没有缓存时，搜索返回空结果并在界面提示“填写联系邮箱后才能下载标的表”。

### 4.3 中文别名表

`resources/aliases/us_zh.json`，由 D-02 创建：

```json
[
  { "symbol": "AAPL", "name_zh": "苹果", "aliases": ["苹果公司"] },
  { "symbol": "BRK.B", "name_zh": "伯克希尔", "aliases": ["伯克希尔哈撒韦", "巴菲特"] }
]
```

- 至少 100 条，覆盖常见的大型美股和在美上市的中概股。**人工整理，不得由模型批量生成**；评审抽查 10 条。
- `name_zh` 是主名；`aliases` 是其他叫法。
- 演示数据的虚构公司（[00](00-术语与约定.md) 1.4）的中文名**不**放在这个文件里，由演示数据载入器直接写入 `instrument`。

### 4.4 规范化与搜索（`instruments.search`）

规范化函数 `norm_query(s)`：NFKC → 小写 → 去掉所有空白与标点（保留字母、数字、汉字）。别名表里的 `alias` 列也用同一个函数。

搜索步骤（`query` 规范化后为 `q`，空串则 `INVALID_ARGUMENT`）：

1. 在 `instrument_alias` 里找所有 `alias` 满足下列条件之一的行，并按**得分**取最高：`alias = q` → 100（若 `kind = 'symbol'` → 120）；`alias` 以 `q` 开头 → 60（`kind = 'symbol'` → 80）；`alias` 包含 `q` → 30。
2. 仅 `is_active` 的标的。
3. 排序：得分降序，再 `symbol` 升序；取前 `limit`（默认 20，最大 50）。
4. 目标：10,000 个标的下 ≤ 300 ms（全表扫描即可，不需要额外索引）。

## 5. 披露（D-03）

### 5.1 列出披露

对每个“可扫描”的标的（04 的 8.4 查询）：

```text
GET https://data.sec.gov/submissions/CIK{cik 10 位}.json
```

形状（**已验证，2026-11-02**）：`filings.recent` 是一组等长数组，实际字段为
`accessionNumber`、`filingDate`、`reportDate`、`acceptanceDateTime`、`act`、`form`、`fileNumber`、`filmNumber`、`items`、`core_type`、`size`、`isXBRL`、`isInlineXBRL`、`isXBRLNumeric`、`primaryDocument`、`primaryDocDescription`。
样例（Apple 的 8-K）：`accessionNumber = "0000320193-26-000018"`，`filingDate = "2026-07-30"`，
`acceptanceDateTime = "2026-07-30T20:30:28.000Z"`（带 `Z` 的 ISO 8601 UTC），`items = "2.02,9.01"`，
`primaryDocument = "aapl-20260730.htm"`。`filings` 下另有 `files` 数组用于历史分页。

规则：

1. 只处理 `form ∈ {8-K, 8-K/A, 6-K}`，且 `acceptanceDateTime` 落在（水位线，`now`]（首次或指定 `from` 时落在（`from`，`now`]）。
2. `event_id = "us:" + accessionNumber`（保留连字符）；已存在于 `event_doc` 且 `content_status = 'full_text'` 的跳过抓取（但仍参与判定缓存检查）。
3. `published_at` = `acceptanceDateTime`（UTC）；`filing_date` = `filingDate`。
4. 主文档地址：`https://www.sec.gov/Archives/edgar/data/{cik 去前导0}/{accession 去连字符}/{primaryDocument}`。
5. 一个标的的 `submissions` 请求失败 → 该标的本次**跳过**，运行状态将是 `partial`，水位线**不推进**（ADR-012）。

```text
GET https://www.sec.gov/Archives/edgar/data/{cik}/{accession 去连字符}/{accession}-index.htm
```

| 文件 | 处理 |

### 5.3 提取正文

对每个要处理的文件 `GET` 其地址（走缓存），然后用 selectolax 转纯文本，函数 `html_to_text(html: str) -> str`（D-03 实现，纯函数，便于测试）：

1. 解析失败或结果为空 → `text_status = 'empty'`。
2. 删除 `<script>`、`<style>`、`<head>`、`<noscript>` 及注释。
3. 块级元素（`p div br li tr h1–h6 table section`）前后补换行；`<td>`/`<th>` 之间补 ` | `；`<br>` 变换行。
4. 取文本，应用 06 第 8 节的归一化（NFC、控制字符、空白折叠），并把 `\xa0`（不换行空格）当普通空格。
5. 去掉首尾空白。结果超过 200,000 字符则截断并 `warn`。
6. 内联 XBRL 标签（`ix:*`）只取其文本内容，不保留标签。

得到文本后：

1. 写 `event_file`（`text_status = 'extracted'`，`text`，`char_count`）。
2. 切段落（S-01），写 `event_passage`。
3. 全部文件都 `empty`/`failed` → `event_doc.content_status = 'title_only'`，并生成一个标题段落（`file_seq = -1`，`text = title`）。至少一个文件有文本 → `full_text`。网络层面失败 → `fetch_failed`（不写段落，该批失败）。

## 6. 日线行情与汇率（D-04）

### 6.1 行情源适配器接口

```python
@dataclass(frozen=True)
class Bar:
    trade_date: date
    open: float | None; high: float | None; low: float | None; close: float | None
    adj_close: float | None
    volume: int | None

class PriceSource(Protocol):
    name: str                                           # 写入 price_daily.source
    def fetch_daily(self, symbol: str, start: date, end: date) -> list[Bar]: ...
```

### 6.2 候选源（2026-11-02 预探针实测）

测试环境：macOS，中国大陆网络，单次请求，未做并发压测。

| 候选 | 实测结果 | 耗时 | 结论 |
|---|---|---|---|
| **腾讯行情** `web.ifzq.gtimg.cn` | 200，JSON；美股 `usAAPL`、港股 `hk00700`、A 股 `sh600519` 均返回日线 | 美股 1.4 s；港股 11.0 s；A 股 5.4 s | **选为主源** |
| **纳斯达克** `api.nasdaq.com` | 200，JSON；`AAPL` 返回 22 条历史记录，字段含日期、收盘、成交量、开盘、最高、最低 | 2.5 s | **选为美股备源** |
| Stooq CSV | 200，但返回的是 JS 验证页，不是 CSV | 0.9 s | 不可用 |
| Yahoo 图表接口 | 403，返回中文区域拦截页（`query1` 与 `query2` 相同） | 0.6 s | 不可用 |
| 东方财富 `push2his` | 200，但 `{"rc":102,"data":null}` | 0.1 s | 参数或网络受限，本轮不可用 |

腾讯接口形态（实测）：

```text
GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=usAAPL,day,,,10,qfq
→ {"code":0,"data":{"usAAPL":{"day":[["2026-10-30","346.72","344.63","349.19","334.35","67841555"], …]}}}
```

注意：

1. 行格式为 `[日期, 开盘, 收盘, 最高, 最低, 成交量]`，与常见 OHLC 顺序不同，解析时必须显式映射。
2. 复权键因市场而异：A 股返回 `qfqday`（前复权），美股/港股本次返回 `day`。解析器必须同时接受两种键，并由 G1-US 确认各市场 `day` 是否已复权；**未确认前不得把 `day` 当作 `adj_close`**。
3. 腾讯是非官方接口，无 SLA；必须走适配器 + 契约测试 + 熔断 + 缓存降级。
4. 港股本次耗时 11 s，超过文档 3 s 的目标；`PriceSource` 超时应单独配置（建议读取 30 s），并在界面显示“行情更新中”。

纳斯达克接口形态（实测）：

```text
GET https://api.nasdaq.com/api/quote/AAPL/historical?assetclass=stocks&fromdate=2026-10-01&limit=5
→ {"data":{"symbol":"AAPL","totalRecords":22,"tradesTable":{"rows":[{"date":"10/30/2026","close":"$344.63", …}]}}}
```

`close`/`open` 等字段带 `$` 前缀，需要去掉后再转数值；日期格式为 `MM/DD/YYYY`。

**G1-US 的选择标准**（逐条判定并记录）：

1. 对 5 个样例代码（`AAPL`、`MSFT`、`BRK.B`、`NVDA`、`KO`）各返回 ≥ 250 个交易日的日线；
2. 含复权收盘价（`adj_close`）；没有则必须能拿到拆股/分红信息，否则风险页要降级（04 第 3.5 节）；
3. 不需要密钥；
4. 从用户的实际网络可访问，单次请求 ≤ 3 秒；
5. 条款允许个人使用；
6. 返回的日期与美东交易日一致（不是 UTC 日期，也不是下一天）。

选定结论：

- **主源：腾讯行情**，覆盖美股、港股、A 股，为 v2 预留同一适配器。
- **备源：纳斯达克**（仅美股）。主源失败或字段异常时切换，并在 `price_daily.source` 记录实际来源。
- Yahoo、Stooq、东方财富本轮不作为候选；如后续网络环境变化，由 G1-US 重新实测后更新本节。
- 以上仅验证“能取到日线”，**尚未验证** 250 个交易日连续性、复权正确性、条款与限速；这些仍由 G1-US 完成并录制 fixture。

### 6.3 抓取规则

1. `prices.refresh` 对给定标的（缺省 = 所有未归档持仓）拉取从“库里最新日期 + 1 天”（库为空时取 3 年前）到“最近一个已收盘的交易日”的日线。
2. 每个标的一次请求；失败的计入结果的 `failed`，不影响其他标的；全部失败返回 `SOURCE_UNAVAILABLE`。
3. 落库前过滤：OHLC 非法、价格 ≤ 0 的行丢弃（04 第 9 节）；`INSERT … ON CONFLICT DO UPDATE`。
4. `holdings.list` 不触发网络请求，只读库里的最新两行。启动后若 `lastPriceRefreshAt` 距今 > 12 小时且在线，后台触发一次 `prices.refresh`。
5. 离线时 `prices.refresh` 返回 `SOURCE_UNAVAILABLE`，界面显示“数据截至 {最新交易日}”。

### 7.4 函数

位置：`core/sentinel/markets/us/calendar.py`。

```python
def is_trading_day(d: date) -> bool: ...            # 周一至周五且不在 holidays
def next_trading_day(d: date) -> date: ...          # 严格晚于 d 的下一个交易日
def prev_trading_day(d: date) -> date: ...          # 严格早于 d 的上一个交易日
def session_close(d: date) -> datetime: ...         # UTC；半日市为 13:00 美东
def market_state(now: datetime) -> MarketState: ... # open | pre | after | closed | holiday，并给出 next_open_at
```

- 日期超出 `years` 范围：按“周一至周五都是交易日”处理，并 `warn` 一次；界面在数据状态里提示“交易日历只到 2027 年”。
- 所有时区换算用 `zoneinfo.ZoneInfo("America/New_York")`（必须依赖 `tzdata`，[02](02-技术架构.md) 4.1）。
- `market_state`：非交易日 → `holiday`（周末也算，`closed` 与 `holiday` 的区别：交易日夜间/清晨是 `closed`，周末与节假日是 `holiday`）；交易日 `04:00–09:30` → `pre`；`09:30–收盘` → `open`；收盘至 `20:00` → `after`；其余 → `closed`。`next_open_at` 是下一个交易日的 `09:30` 美东换算成 UTC。
- 美东夏令时在 2026-11-01 结束（`04:00–09:30` 之类的边界要用本地时间判断，不能用固定 UTC 偏移）。测试必须覆盖 2026-03-08（开始）和 2026-11-01（结束）前后。

## 8. 失败矩阵

| 情形 | 行为 | 错误码 | 界面 |
|---|---|---|---|
| 离线 | 不发请求；用库里已有数据 | `SOURCE_UNAVAILABLE`（`OFFLINE`） | 顶栏“离线”徽标；数据状态写“数据截至 …” |
| 未填联系邮箱 | 不发 SEC 请求 | `CONFIG_REQUIRED` | 引导到设置页 |
| SEC 403 | 熔断 10 分钟 | `SOURCE_UNAVAILABLE`（`SEC_FORBIDDEN`） | “SEC 拒绝了请求，请检查联系邮箱” |
| SEC 429 | 退避重试；仍失败则 `RATE_LIMITED` | `RATE_LIMITED` | “请求过于频繁，约 N 秒后重试” |
| `submissions` 失败 | 跳过该标的；水位线不推进；运行 `partial` | `SOURCE_UNAVAILABLE` | 扫描页“N 只标的获取失败” |
| 某份披露正文失败 | 该批 `failed`；下次扫描重试 | `SOURCE_UNAVAILABLE` | 批次列表显示原因与“重试” |
| 解析出的正文为空 | 退回标题段落，`title_only` | — | 卡片标注“仅依据标题” |
| 行情源失败 | 用库里最新数据；`prices.refresh` 返回 `failed` | `SOURCE_UNAVAILABLE` | “行情源暂时无法访问，已使用 10 月 30 日的收盘价” |
| 行情返回非法数据 | 丢弃该行 | — | 日志 |
| 日历超出范围 | 按工作日处理 | — | 数据状态提示 |
