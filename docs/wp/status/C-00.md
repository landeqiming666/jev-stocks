## 新发现的问题与风险

- 现有分层测试没有把 `logging_setup` 视为免检基础模块，静态导入 `security.redact` 会被误判为越层，尽管 C-00 明确要求日志写前脱敏。为保持 `owns` 边界和分层测试不变，`logging_setup` 在首次格式化日志时按需加载脱敏器；未修改测试或其他工作包文件。建议后续工作包修正 `ALWAYS_ALLOWED` 检查逻辑，再恢复普通静态导入。
- 按 02 §11 的既定风险，32 位以上十六进制规则会同时遮蔽 32 位 `passage_id`；证据 ID 应从数据库获取，不从日志反解析。

## 给下游的补充信息

- `SentinelError.params` 同时用于文案渲染和 `to_wire().data` 的方法级字段，因此 `retryAfterSec`、`missing` 等既可在用户文案中出现，也可按契约进入错误数据。
- `INTERNAL` 的 `to_wire(request_id)` 会把 `requestId` 同时写入 `data` 和用户文案；调用方仍必须在请求上下文中传入非空 `request_id`。
- `render()` 对 `retryAfterSec`、`missing`、`requestId` 提供安全默认值，保证 15 个错误文案在无参数时也可渲染；其他缺失模板参数仍抛 `MessageKeyError`。
- 测试和临时探测均只使用 `tmp_path`/临时目录及假密钥，没有写入真实数据目录。
