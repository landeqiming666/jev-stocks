## API 与接入

```python
from sentinel.trading import PaperService, register_handlers
from sentinel.trading.rules import load_market_rules

service = PaperService(db, rules, clock=clock_provider)
register_handlers(dispatcher, service)
```

`db` 必须是已打开并迁移的 C-03 Database；`rules` 使用当前 P-04 MarketRules。
时刻由注入 clock 或统一 clock.now 获取。接入生产组合根由主 Agent/C-07 负责。

| RPC | 服务方法 | 结果模型 |
|---|---|---|
| `paper.accounts` | `list_accounts()` | PaperAccountsResult |
| `paper.createAccount` | `create_account(name, initial_cash, start_date)` | PaperAccountView |
| `paper.portfolio` | `portfolio(account_id)` | PortfolioView |
| `paper.order.place` | `place_order(OrderIntent(...))` | PaperOrderView |
| `paper.order.cancel` | `cancel_order(order_id)` | PaperOrderView |
| `paper.orders` | `list_orders(account_id, status=None, limit=50, cursor=None, idempotency_key=None)` | PaperOrderPage |
| `paper.advance` | `advance(account_id)` | AdvanceResult |
| `paper.reset` | `reset(account_id, confirm_text)` | OkResult |

Python 参数为 snake_case，线上只接受 JSON camelCase；显式 null、bool 数量、字符串数量、
浮点现金、科学计数法现金、错误日期和额外字段被拒绝。金额四位字符串，价格和平均成本六位字符串，
日期 YYYY-MM-DD，时刻 UTC Z。分页按 created_at DESC / order_id DESC；cursor 是上一页末行 orderId。

金额上限 `99999999999999.9999`，价格上限 `999999999999.999999`。
以独立 80 位、ROUND_HALF_UP Context 完成账本计算，不继承或修改调用方 trap、精度、舍入和 flags。
初始现金溢出/多于四位小数在写前 INVALID_ARGUMENT；成交、成本、市值或权益溢出整体回滚并 INTERNAL。
010 权威数量列实际为 INTEGER，累计持仓上限 2147483647；未擅自改为 BIGINT。

## 事务与历史语义

- 同键同参数返回已存订单当前状态，包括 rejected/filled/cancelled；不再冻结。
  同键不同参数或不同账户 CONFLICT，遵循 010 的全库唯一 idempotency_key。
- 参数错误不保存订单。业务拒单在单独一次 Database.write 中仅保存 rejected，COMMIT 成功后
  事务外抛 ORDER_REJECTED，带有效 orderId 和 reason；中文金额显示千分位/两位，data 金额保留四位。
- 买单冻结与订单同事务。成交前精确 release 原冻结，再通过原 tx 读取实际可用现金。
  等待无开盘价的 pending 单不产生 release；取消/超期/资金拒绝只释放一次。
- advance 的前置、所有卖单/买单、业务拒单、流水、持仓、时钟、结果模型与唯一快照共用一个 WriteTx。
  卖单优先，随后 created_at/order_id 升序；任一 SQL/程序/不变量错误回滚整个批次。
- 原 tx 的目标日存在性查询必须命中账户涉及标的的 D+1 行。涉及标的包含持仓和历史订单标的，
  以便清仓后仍可回放；无涉及标的时，以全库目标日 `instrument.market='us'` 的行情支持观察回放。
  有涉及标的时保持关联标的范围，不用其他标的的行情兜底；对应范围无目标日行返回 DATA_INSUFFICIENT。
  D+2 有价格不能替代 D+1。撮合只读 exact next_day open；估值只读 close <= clock_date。
  个别标的缺开盘价且其他涉及标的有目标日行时等待，满配置交易日数拒绝；缺当日收盘使用旧收盘并 warn。
- 清仓保留 quantity=0 行，卖出不改变 avg_cost。买单历史预估从当时 estimate_price 与原 reserve 恢复，
  不因行情刷新、成交/取消或当前费用配置变化而漂移。
- reset 先校验确认文字，再真实 db.backup("paper.reset")，要求返回文件存在且非空后才删除目标账户数据。
  备份与删除跨上下文共享当前 Database 的受保护 `_gate.lock`，覆盖同路径的其他句柄，防止删除未备份的新订单。
  删除失败整体回滚，备份保留；其他账户不变。真实备份以只读 Database 重开核对成交历史。
- Ledger 保留七项规定检查：fill_without_order、filled_order_without_fill、position_mismatch、negative_position、
  negative_cash、reserved_mismatch、equity_mismatch；另检查成交金额、可用现金、冻结引用、成交流水与账户引用。
  检查仅 SELECT，advance 在提交前检查，失败记录违规名并回滚。
