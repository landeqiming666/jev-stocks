## 交付内容

| 路径 | 职责 |
|---|---|
| `core/tests/integration/harness.py` | 真实子进程、NDJSON 行读取、请求/通知关联、超时、进程组清理 |
| `core/tests/integration/conftest.py` | 含空格与中文的数据目录、核心 fixture |
| `core/tests/integration/test_core_lifecycle.py` | 就绪、bootstrap、错误映射、关闭、取消、stderr |
| `core/tests/integration/test_demo_flow.py` | 演示载入、清单计数、证据、动作/重开、清除、未配置扫描 |
| `core/tests/integration/test_paper_risk_flow.py` | 账户、推进、风险、参数校验、重置确认 |
| `apps/desktop/e2e/real-core/fixture.ts` | 启动核心、Tauri IPC 模拟、轮询拉取输出 |
| `apps/desktop/e2e/real-core/demo-flow.spec.ts` | 六页真实数据、证据抽屉、交易推进、风险、设置 |
| `apps/desktop/e2e/real-core/failures.spec.ts` | 重启提示、失败重试、真实核心重启保留数据、未知方法 |
| `apps/desktop/e2e/real-core/playwright.config.ts` | 串行、30 秒、自动启动 Vite（1469） |

前端不使用 mock：Vite 以默认（Tauri）模式启动，页面通过 `app.store` 的 client 走
`rpc_send`；测试桥只模拟 Tauri 命令，不新增应用端口，也不替换业务数据。

## 实测

```bash
cd core && uv run pytest -q tests/integration
# 20 passed, 1 skipped（见下）
cd apps/desktop && pnpm e2e
# 10 passed (26s)
```

关键断言：`app.ready` 是核心第一条输出；演示清单 2 条待处理（0.93/0.78）+ 1 条待确认
（0.71），汇总 `pendingCount=3`；`decision.act` 后 2→1，`reopen` 后 1→2；`paper.advance`
2026-10-29→2026-10-30 且成交 1 笔；风险 6M 观测 ≥60、相关矩阵对角线 1.0；六页在
1440×900 与 1024×700 均无横向滚动；核心重启后仍见 2 条待处理。

**联调发现并修复的真实缺陷**：E-01 演示账本的买入流水 `refId` 指向订单而非成交、
日期比成交早一天，且缺少 `fee` 流水行，导致 `paper.advance` 触发
`LEDGER_INVARIANT_FAILED / fill_ledger_mismatch`。已修正 `resources/demo/paper.json`
并同步 manifest 哈希。
