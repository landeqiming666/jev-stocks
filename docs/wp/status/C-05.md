## 实现与交接

- 客户端消费真实 `core://status` 的 `{state,attempt}` 与 `core://message` 字符串。两个 listen 都建立后只执行一次无参数 `invoke("core_status")`；查询期间的新有效状态事件优先于快照，无轮询。
- `call` 在发送前设 pending、超时和 abort；监听建立期间的取消/超时不会发送请求。完成时移除 timer 和 abort listener，重启/失败/dispose 清空 pending；未知方法拒绝，未知 wire error 归一为 INTERNAL、retryable=false，并丢弃未知消息和 data。
- 超时和 abort 先完成本地拒绝，再发一次 `$/cancel`，防止同步取消响应抢走本地 TIMEOUT。传输异常使用 errors.ts 的固定中文文案；未知 ID、坏消息和 handler 异常按类别仅警告一次。
- call 的默认超时取 `METHOD_TIMEOUTS[method]`，调用方 timeoutMs 优先覆盖；app.ping 2 秒、app.shutdown 5 秒、scan.retryBatch 60 秒、settings.testConnection 20 秒。whenReady 默认仍为 30 秒。保留三个导出 constants，未来导出超时也由契约决定，不按方法名字猜测。调用方 params/idempotencyKey 不变。
- `getRpcClient()` 根据 VITE_RPC 选择真实或 mock；U-00 创建并持有一个实例，卸载时调用 `dispose()`。页面依赖 rpc/index.ts。
- `whenReady({timeoutMs,signal})` 等待 starting/restarting 到 ready，失败、取消、超时或 dispose 会拒绝。U-00 的 bootstrapApp 应先 await whenReady，再调用 app.bootstrap；两步共享 U-00 规定的总计 30 秒预算。
- mock 复用同一个真实客户端状态/取消/超时实现，支持 `setExample(method,name)`、`setDelay(ms)`、`injectNotification(name,params?)`。返回值经 JSON wire 复制，不改变生成的示例；包含 43 个页面状态和 6 个抽屉状态。加载、无账户、新账户的局部展示状态仍由页面负责，不能篡改契约示例。
- 生成器仅使用标准库，已由宿主 Python 3.9 执行。按 index 方法顺序和 $defs 顺序生成，保留 92 个原示例的数组顺序、名称与字段内容。支持 refs、嵌套 JSON pointer、enum、const、anyOf/oneOf/allOf、nullable、数组、对象与 additionalProperties；无 any 兜底。
- 生成前校验 methods/notifications 为非空、唯一、合法 RPC 名数组，errors.codes 为非空对象、错误码名有效、每个 retryable 严格为 bool。非法元数据或 schema 退出 2，所有旧文件保持原样。
- 生成器先构造全部输出、暂存同盘文件，再逐文件 os.replace。替换中途发生 OSError 时回滚已替换文件；不保证进程崩溃时跨文件原子，崩溃可能留下不同版本的多个文件。--check 逐字节发现漂移、退出 1 且不写文件；测试模拟只替换 types.ts 后中断，确认能发现 methods.ts/mock-data.ts 的旧版本。
