## 公开 API 与装配要求

入口为 `sentinel.scan.pending`，无需 P-02 initializer 或 ScanService：

```python
InboxService(db: Database, *, status_provider: StatusProvider)
StatusProvider = Callable[[SqlExecutor, datetime], StatusSnapshot]

service.list_inbox(*, limit=50, cursor=None) -> InboxPage
service.get_decision(decision_id: str) -> DecisionDetail
service.act(decision_id: str, action: ActionType, note=None) -> DecisionSummary
service.reopen(decision_id: str) -> DecisionSummary
register_handlers(registrar: HandlerRegistrar, service: InboxService) -> None
```

`StatusSnapshot` 必填 `source: SourceStatus`、`engine: EngineStatus`、`offline: bool`。
provider 每次列表读取时调用，必须返回当时实际运行状态；持久化数据读取使用传入 executor，
不能另开数据库快照、写事务或执行网络/模型请求。来源状态、最近成功时间和错误文案必须来自
实际数据源状态；引擎状态必须消费当前配置/密钥及实际 resolver 状态，不能默认填 `ok`。
该显式 provider 由主 Agent/C-07 装配，本包不反向导入 settings，也不调用未交付生产 API。

市场状态和下次开盘时间由统一时钟与 D-04 的已交付美股日历计算；预算使用同一快照内的
`setting.dailyTokenBudget` 及 UTC 当日全部引擎/模型的 `usage_daily.input_tokens + estimated_tokens`。
未设置预算时使用 04 §5 的真实配置默认值 2000000；损坏的设置/用量报错，不静默改成默认值。

四个 handler 注册 `inbox.list`、`decision.get`、`decision.act`、`decision.reopen`。
输入模型由真实 Dispatcher 按 alias-only、strict、extra-forbid 验证；结果使用 camelCase。
机器契约的 `inbox.list` 入参严格为 `{}`，其结果没有 `nextCursor`：`InboxPage.next_cursor`
是 Python 私有字段的只读属性，仅供内部 processed 分页，JSON 中不序列化。
`processedCount` 按本次实际返回数组计数，pending/uncertain 不随 processed 分页缩减。

公共中文注册表仍由主 Agent 合入 `sentinel.messages.inbox.MESSAGES`。
本包不修改 `messages/__init__.py`；错误键为 `inbox.decision_not_found`、`inbox.note_too_long`。
包内 RPC 测试显式装配这些真实本地模板，因此不把该测试当作公共注册已经交付。

## 行为与事务

- 清单一次 `Database.read()`，代表、三组、setup、lastScan、usage/预算全部来自同一快照。
- 代表按 `(thesis_id,event_id)` 分组，关系严重度、headline 逆序、passage.seq、decision ID 升序。
  跨版本只选一个代表；旧版本未决保留原 statement/killCondition 和当前版本，供界面显示逻辑已更新。
- 只显示代表的 overturn/weaken/uncertain。缺 kind、非法 kind、空白文本、句子越界、
  passage/title 携带不应有的偏移、缺原文件或损坏关联均排除并记录 INTERNAL；不选择较弱替代项，
  不生成证据、截断偏移或写回 decision。
- 详情按请求 decision ID 精确读取原行，包含旧版本快照和全部动作历史；归档逻辑/持仓不阻止追溯。
  ID 不存在返回 NOT_FOUND；存在但没有合法证据或关联损坏返回 INTERNAL，不构造占位详情。
- 列表过滤非 active/已归档逻辑与已归档持仓；已处理只显示 actedAt >= asOf - 30 days，历史不删除。
- act/reopen 仅追加 thesis_action。先验证原行，追加后在原 protected write tx 内重新读摘要；
  返回构造失败整次回滚。revise/exit_intent 不修改逻辑、持仓、判定、订单或账本。
- reopen 对无动作或最后为 reopen 的条目幂等。备注 Unicode strip、空串转 null、超过 200 码点
  返回 INVALID_ARGUMENT / field=note / max=200，错误前不写入。
- 同 timestamp 按 action ULID 排序；追加时在受保护事务中递增必要的 ULID 熵，避免随机 ULID
  让刚追加动作落在旧动作后面。跨 handle 并发结果分别看到自己的写入。
- processed cursor 为 canonical base64url(UTC actedAt|actionId)，按二元组严格小于翻页，
  保留微秒和同 timestamp 的所有记录；业务 ID、note、cursor 不进入 SQL 文本。
