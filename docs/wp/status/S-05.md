## 实现与事务

- `norm_text` 使用 NFC、CRLF/CR 转 LF、去首尾空白，内部空白保留。拒绝非法
  surrogate；模型收到原始段落，证据偏移始终基于原文，不用归一化文字定位。
- ADR-022 缓存键精确包含 engine/model/question set/两个文本哈希及
  thesis_id/thesis_version/passage_id。同字不同逻辑、不同事件段落以及恢复旧文字的
  新版本分别产生永久 decision 行。流水线从实际输入重新计算哈希，避免陈旧 hash
  导致错误复用。缓存与冲突胜出行严格核对实体、引擎、模型、问题集和数据形状。
- 只调用 `score_pairs`，返回数、唯一 pair 集合、version、model、kill_met 形状与
  实际/估算 token 标记均核对。2×2 中命中 1 对时只请求缺失 3 对；从不调用
  `score_event` 重建笛卡尔积。评分失败或第一事务前取消不落库。
- 同实例 process_batch 串行，等待锁期间每 20 ms 检查取消。不同实例的外部调用
  可能都已发生，冲突用 `ON CONFLICT(cache_key) DO NOTHING` 并通过同一 tx 读回。
  不覆盖已有 decision 的永久实体身份；已发生的调用仍计响应 token，不能宣称
  跨实例冲突为远端零计费。
- 每日预算合计 UTC 当日所有引擎/模型的 actual + estimated token，判断
  `used + reserve_tokens(raw) <= daily_budget`，20% 余量，没有第二个 90% 门槛。
- 网络、问题构造、分类及分句在写事务外。第一事务原子插入 decision 与评分 usage；
  tx 内读取自身未提交写入。第二事务只回写空证据并累加证据 usage；返回成功前
  同 tx 回读、复验每个代表的实体和合法证据。不使用 rawConnection。
- 代表按 overturn/weaken/uncertain、headline 降序、seq 升序、decision_id 升序。
  每个 thesis/event 仅一个代表请求证据；title_only 不请求模型；全文前 40 句，
  概率最高且 ≥0.3 选句，平票选最前。回切不符或概率低回退原段。
- 证据预算不足回退；仅 MODEL_ERROR/TIMEOUT/RATE_LIMITED 可回退并记警告。
  任意其他异常继续抛出。DuckDB 错误映射 INTERNAL，不回显原 SQL 或文本。
- 已提交评分后取消证据或第二事务失败，第一事务保留，整批不返回成功。重试命中
  已评分行后补合法整段/标题，不重新评分或请求证据。合法完整命中零请求、零 usage、
  零写事务；缺证据的完整命中仍零请求/零 usage，但以第二事务补证据。
- BatchOutcome 的 actual/estimated 分别包含本次已提交的评分和证据用量。
  usage_daily.requests 按规格计逻辑调用：一次 score_pairs +1，每次证据请求 +1，
  不是 SDK 内部 HTTP 尝试数。所有流水线日志包含 run_id/batch_id/event_id，不含正文。

## P-02 / P-03 API 交接

P-02 从 `sentinel.semantic.pipeline` 导入 `DecisionPipeline`、`BatchContext`、
`PassageRecord`、`BatchOutcome`；theses 使用既有 `semantic.base.ThesisInput`，
cancel 使用既有 CancelToken Protocol。构造：

```python
pipeline = DecisionPipeline(db, engine, model_id=model_id, daily_budget=daily_budget)
outcome = pipeline.process_batch(ctx, theses, passages, cancel)
```

theses 1..5 条，passages 非空，按 seq 取前 60；同一 ctx 只接受对应 event/instrument。
status 仅 succeeded。BUDGET_EXCEEDED/MODEL_ERROR/CANCELLED/INTERNAL 等均抛出，
由 P-02 决定 pending/failed/cancelled；本包不写 scan_batch 或发通知。
用当前配置重建/提供相应 engine 和 pipeline 的生命周期由 P-02/C-07 负责。

P-03 直接消费 006 decision/evidence 字段，按 04 §8.1 选择代表并过滤空证据。
`cache.DecisionRow` 与 DDL 同列，附带仅内存的 seq；`evidence.select_representative`
可复用排序。`evidence.valid_evidence` 可校验偏移；sentence 文字来自
`passage.text[start:end]`，passage/title 为整段且 start/end=null，前端按 Unicode
码点切片。尚未完成证据阶段的失败批可能已有评分行，不能把空证据代表展示为成功条目。

## 限制

跨实例不保证远端零重复调用，也不能撤回已消耗的外部 token。取消/数据库失败时按
两阶段规格只保留已提交的 usage；尚未提交的证据请求可能已产生外部费用。
重试采用整段/标题修复避免再次计费。S-04 真实引擎未在此独立树交付，jevdb 路径
仅以显式合成引擎验证 estimated 用量；未声称真实 JEVDB 推理通过。

既有 SemanticEngine Protocol 的可写 name 是两个 Literal 的并集，而真实 S-03
name 注解较窄；直接以具体类静态传入时 strict mypy 的属性不变性会报错。组合测试
在这个既有边界使用 `cast(SemanticEngine, engine)`；生产可消费既有返回
SemanticEngine 的 EngineSelection。未越权修改 S-02/S-03 类型注册。
