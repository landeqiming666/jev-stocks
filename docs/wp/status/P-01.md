## 实现

- 交付 `PortfolioService` 的全部 11 个 WP 公共方法与 `register_handlers`，八个真实 RPC 均注册严格参数及结果模型。
- RPC 使用 camelCase；内部 Python 模型支持 snake_case。真实 Dispatcher 使用主审提供的 `by_alias=True, by_name=False` 输入边界。
- 所有写用例在原 `Database.write()` 事务中检查、查询、写入并生成返回视图。标的的 active/us 检查不通过独立 D-02 读取事务。
- 新增和编辑逻辑同时写身份及不可变版本；第二条语句失败时整事务回滚。编辑使用 `UPDATE ... RETURNING`，不依赖 DuckDB rowcount；过期版本优先于同内容判断。
- 每标的最多五条 active 逻辑的检查在写事务内。归档幂等，持仓身份、逻辑版本、判定及处理记录保留。
- 数量和成本拒绝非有限、负值、越界及非契约 wire 格式。量化使用独立 Decimal context；计算市值允许超过数量/成本的 14 位整数上限。
- 文字先 strip，按 Unicode 码点计数；可选空文字转 null。哈希使用 NFC 与统一换行，保留内部空白。
- 列表依据 04 的 `price_daily.close`、同标的最新交易日和上一条日线计算价格及日涨跌；市值 HALF_UP 保留四位。
- 后续价格/判定/处理表缺失时返回 null 价格或零待处理计数，通过 catalog 判断是否存在。已有表的 SQL 错误不作为“缺表”吞掉。
- 判定按 04 §8.1 的逻辑/披露代表项及最新处理状态计数，归档逻辑排除；无逻辑优先 unguarded，待处理推翻/削弱 attention，其余 guarded。最新判定按时刻、ID 排序且保留旧版本判定。

## 主审补丁：最新价格异常

- 补丁基线为本包实现提交 `c0283f348798d0f19207cce78da7076d5f76b1b7`，单独本地提交。
- 主审发现真实 DuckDB 的最新 close 为负数、NaN 或 Infinity 时，市值计算先于结果模型校验，直接服务调用会泄出 ValueError 或 decimal.InvalidOperation。
- 仓储在选中 latest close 后、市值计算前检查有限且非负；异常直接抛 `InternalError(detail="invalid latest holding price")`，错误消息、data 和异常链不包含原价格。现有写事务负责回滚，不扩大 `_database_errors` 捕获范围。
- 保留 close=null、close=0、prev_close<=0 时 dayChangePct=null 的权威语义；非最新的旧坏价格不会触发最新价格检查。
- 新增 `core/tests/unit/portfolio/test_bad_prices.py`，共 30 个真实 DuckDB 用例。20 个坏价格查询/upsert 用例先失败，10 个合法语义用例先通过；修复后全部通过。
- upsert 测试覆盖原记录不存在、active 和 archived 三种状态；失败后整行与旧快照一致，包括 holding_id、quantity、avg_cost、note、created_at、updated_at 和 archived_at。测试时钟在失败写入前推进一天，确保更新时间回滚断言有效。
- 定向复跑：`uv run --offline pytest tests/unit/portfolio -q`，**207 passed in 4.86s**；日志 `/tmp/p01-bad-prices-targeted.log`。复现日志 `/tmp/p01-bad-prices-red.log`：**20 failed / 10 passed**。
