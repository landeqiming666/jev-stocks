## 待裁定：CR-U01-FIELD-REF

证据：U-01 §5.1 `count.value` 是 number，但 §6 第 3 步要求从文本执行 `Array.from(text.trim()).length`，规定测试又要求输入三个空格显示 0；§5.1 还要求“所有组件 forwardRef 到最外层可聚焦元素”，但 VerdictChip/Probability/Icon/Card/Heatmap 等原型根不是可聚焦元素。

建议裁定：

1. 保持 `FieldProps.count` 原 number 签名；单一子控件提供 string `value`/`defaultValue` 时从该文本 trim 后按 Unicode 码点计数，没有可读取文本时使用调用方 `count.value`。不加入 `text`/`max` 等新 props。Field 的 label、help/error、已有 describedby 合并关联同一个控件。
2. 所有组件仍 `forwardRef`。Button/Input/Textarea/SearchInput/Radio 的 ref 落到实际 button/input/textarea；非交互组件 ref 落到现有根元素，不为标签/图表增加 Tab 停靠点；Field/Segmented/Menu/Drawer/Modal ref 落到其根，必要的程序聚焦 fallback 使用 `tabIndex=-1`。Table 保留 wrap + table 结构，ref 建议落到 table 本体。

需要主 agent 明确这一语义解释；当前空实现未实现 count 推断与 ref，不能将其当成已冻结契约。
