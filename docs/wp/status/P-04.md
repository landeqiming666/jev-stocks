## 规范与实现

已完整读取 P-04 及 §2 引用的 00 §4/§5、08 §1/§3–§7、05 §3/§4/§5.7/§7.3/§8、04 §3.10；另读 P-05，明确事务、冻结释放和拒单持久化责任。

- 实现只使用标准库和 C-00 错误对象，不新增依赖。`load_market_rules(Path)` 是唯一文件读取入口；计算函数不读数据库、网络、时钟或环境变量，不修改传入对象。
- TOML 小数必须是字符串；整数可无损转换为 Decimal。二进制浮点、bool、缺失字段、非法市场/币种、NaN/Inf、负费率和非法限制均在入口拒绝。配置错误统一 `InternalError`。
- 滑点要求 `0 <= bps < 10000`，避免只做多卖出价格变负；佣金百分比为 0–100；佣金最低额和 TAF 上限必须能精确表示为分。TAF 非零但上限为零拒绝启动。
- 价格 `ROUND_HALF_UP` 到 6 位，金额到 4 位；费用拆分到 2 位，SEC/TAF 使用 `ROUND_UP`。订单级 `fee` 与 `required` 为 4 位，FeeBreakdown 三项及 total 为 2 位。
- 金额入口只接受非负有限 Decimal，金额最多 4 位有效小数（允许额外尾零）；数量严格为正整数，bool 不视作整数。held/pending_sell/waited_days 只接受非负整数。
- 先完成类型与结构校验，再按 NO_PRICE → 买单资金 → 卖单可用持仓返回首个业务拒单。零价/缺价是业务缺价，负价与非有限值是参数错误。
- 买单预估不增加安全余量；资金与持仓精确相等均通过。撮合只使用已释放冻结后的可用现金，不重复加 reserved_cash。
- 无开盘价时，`waited_days + 1 >= max_wait_trading_days` 拒单；默认上限 5，传入 3 本次仍 pending，传入 4 本次为第五天拒单。
- 请求摘要只包含账户、标的、方向、数量和订单类型，UTF-8 SHA-256 小写 64hex，不包含幂等键或日期。固定向量：`efda657dd51faa14051d5566d5de50b2684a5bd32ed59e2b196e766fa77e49d1`。
- 独立 Decimal Context 保证调用方修改精度、舍入或 Inexact trap 不改变规则结果；不修改调用方的 Context。
- 全部结果为 frozen dataclass；Reject.data 是复制后的只读映射，包含 `reason` 与 `retryable=false`。业务拒单返回对象，不抛 ORDER_REJECTED。

## P-05 接口交接

Python 字段统一 snake_case。OrderIntent 的六个构造字段为 `account_id, instrument_id, side, quantity, order_type, idempotency_key`；MarketSnapshot 为 `clock_date, close, max_order_quantity`。意图字段参数错误使用对应 RPC 字段名（accountId/instrumentId/orderType/idempotencyKey）；函数显式数值参数使用函数名（available_cash/open_price/pending_count 等）。

| 接口 | 返回和接入约定 |
|---|---|
| `MarketRules()` / `load_market_rules(path)` | 默认监管费 0、verified=false；`rules.fee_config` 或 `FeeConfig.from_rules(rules)` 获取费用配置 |
| `validate_parameters(intent, pending_count, rules)` | 成功 None；参数错误 UserError(INVALID_ARGUMENT)，field 指向实际输入；P-05 先完成账户/幂等/标的步骤 |
| `precheck(...)` | 买单成功 estimate 非空；卖单成功 estimate/reject 均为空；业务拒单仅 reject 非空 |
| `estimate_buy(...)` | BuyEstimate.price/amount/fee/required/fees；required 为完整冻结额 |
| `calculate_fees(...)` | FeeBreakdown.commission/sec/taf/total；total 为实际 dataclass 字段，可用 asdict 取出 |
| `match_at_open(...)` | filled 时 price/amount/fee/fees 非空；pending/rejected 没有成交金额；reject_code 是 reject.code 的只读属性 |
| `request_hash(account_id, intent)` | 账户需与 intent.account_id 相同；禁止 ID 含分隔符；先用 validate_parameters 校验配置相关数量上限 |

`waited_days` 是本次撮合之前的无价等待天数。P-05 若按创建日至本次交易日的日历跨度计算，调用时传入“不含本次”的计数；pending 返回的 waited_days 已加一。有开盘价即尝试撮合，即使此前已等到上限，不按无价分支取消。

`reserved_cash` 在纯函数中只验证，不自行释放或加到现金；P-05 必须在事务中释放冻结，并传入释放后的 available_cash_after_release。撮合、拒单保存、现金与持仓更新、时钟推进均由 P-05 负责。拒单先持久化，事务外再构造 UserError(ORDER_REJECTED)，不得在保存事务内抛出导致回滚。

Reject.code 是六种细分原因，RPC 顶层 code 应由 P-05 设置为 ORDER_REJECTED。`dict(reject.data)` 可 JSON 保存；映射值只含字符串、整数、bool，金额字符串保持 4 位。不要直接对含 MappingProxyType 的 Reject 使用 dataclasses.asdict；P-05 应按字段组装视图、拷贝 data、加入已保存的 orderId，并用 message_key 渲染中文。
