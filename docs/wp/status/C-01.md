## 实现行为

- 请求要求四个字段全部存在，`params` 必须为对象，空对象合法；版本、ID、方法名、类型和 extra 字段严格验证。拒绝重复 JSON key、非法 UTF-8、surrogate、NaN 和 Infinity。上限按 UTF-8 字节计数。
- reader 使用传入 BinaryIO 的 `readline(limit + 1)`。超限后分块丢弃该行的全部剩余内容，继续读下一整行；从首 64 字节恢复顶层 ID，能恢复时返回 `INVALID_ARGUMENT`。不会把 `params.id` 错当成请求 ID。
- reader 直接处理 ping、cancel 和 shutdown。普通请求进入固定四个 daemon worker。用连接内已使用 ID 集合和带锁的 in-flight 状态保证一个 ID 最多提交一次响应；重复 ID 不执行、不替换 token、不产生第二条响应。完成后释放状态及 token，仅保留已使用 ID。
- 只有注册 `cancellable=True` 才置位 token 和立即返回 `CANCELLED`。默认写操作不置位、不产生取消响应，正常返回一次结果；排队任务取消后不再执行，晚到 worker 结果丢弃。
- 单 writer、1024 条有界队列、逐条 flush，处理短写。通知满队列等待最多约一秒后可丢弃；响应持续等待消费者，不采用通知丢弃策略。传输断开或关闭期限内无法入队时显式记录失败并停止服务。
- 分发使用已锁定 pydantic 的严格验证和 `extra="forbid"`，模型结果按 JSON 模式与 alias 输出。错误按 C00 实际接口调用 `to_wire(request_id)`；未预期异常只记录异常类型、请求 ID 和方法，不记录异常正文。结果或错误数据无法序列化时仍映射到一次 `INTERNAL` 响应。
- shutdown 的 ok 响应先入 writer 队列，再启动关闭。正常关闭排空 worker 最多三秒；force 不等待 worker。writer 在有界收尾时间内冲刷队列。逾期未完成的可取消任务返回 `CANCELLED`；不可取消任务返回 `INTERNAL` / `SHUTDOWN_TIMEOUT`，不误报取消。
- watchdog 每两秒调用平台存活检查；构造函数保留全部公开参数，新增可选 `process_alive` 回调便于测试注入。父进程不存在时退出码为 0。
- CLI 为 writer 复制 stdout fd，然后将 fd 1 与 Python stdout 转向 stderr。输入使用独立、无标准缓冲锁的二进制 fd，避免 reader 阻塞导致解释器收尾永久等待。

- MethodSpec.timeout_ms 保留为公开注册元数据；本包不抢占 Python handler 的执行线程。执行超时需要方法自身或客户端管理。ping_timeout_s / cancel_deadline_ms 保留配置接口，控制请求通过直通路径实现响应时限。
- 同进程内无法安全杀死不合作的 handler；逾期关闭后 daemon worker 可能继续持有调用栈，进程退出时结束。不可取消 mutation 可能已提交或稍后提交，因此逾期响应明确为 INTERNAL，不承诺回滚。写事务与合作式取消检查仍由业务处理器负责。
- 200 ms 控制响应以输出通道可写为前提；对端永久不读或断管时无法保证送达。此时记录 writer 失败/flush_timeout 并有界退出；不会声称已送达。嵌入式调用方应提供 writer 专用 BinaryIO，进程 stdout 的 fd 重定向由 CLI 入口负责。
- 阻塞输入关闭在 daemon closer 中执行，避免 BufferedReader.close 的读锁拖住 stop；CLI 使用 raw fd。自定义输入若 close 不合作，可能遗留 daemon reader，但不会拖住进程退出。

参数模型的 ValidationError 在入参校验处仍映射 INVALID_ARGUMENT，携带首个错误字段，不执行 handler。合法入参之后发生的 ValidationError（包括 handler 构建结果模型失败和 result_model 校验失败）由统一的内部异常路径映射 INTERNAL，携带 requestId。日志仍只记录异常类型与固定请求关联字段，不输出校验详情、输入或非法结果正文。

register 现在要求 timeout_ms 为严格正整数：拒绝 bool、浮点、字符串、None、零、负数、NaN 和正负 Infinity；非法注册不能覆盖已有 MethodSpec。MethodSpec 的公开文档明确 timeout_ms 仅供客户端或方法自身管理超时，不限制 server 线程，不执行线程抢占或取消。

新增回归验证五类非法返回值的 INTERNAL 响应及日志字段、handler 内部抛出的 ValidationError、十一类非法 timeout、非法 replace 保留原注册。既有入参类型错误回归增强为断言 handler 未被调用；真实线程 server 回归设置 timeout_ms=1，handler 在 50 ms 后仍等待释放，随后正常返回结果。
