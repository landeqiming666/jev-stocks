- `Database`、`SqlExecutor`、`WriteTx`、`MigrationReport`、`check_integrity`，遵循 C-03 §5.1 及主审专项裁定：`WriteTx.execute(...) -> WriteTx`，执行后返回 self。

- `001_core.sql` 按 04 §3.1 逐字复制，测试直接与权威文档比较 UTF-8 字节，保留中文注释、LF 和末尾换行。`schema_version` DDL 同样使用 04 §2.1。
- 每个 read/write 上下文创建并关闭独立的真实 DuckDB cursor。按数据库绝对路径共享进程内 RLock，整个上下文持锁，覆盖多个 Database 句柄的读写互斥。
- 线程本地记录 read 深度和 write 状态；禁止 read 内进入 write、嵌套 write、手写 BEGIN/COMMIT/ROLLBACK，以及在 read 内借用既有 tx 写入。executor 跨线程或退出上下文后使用会报错。
- read 先解析完整 SQL 的所有语句，只接受 SELECT；原生 `BEGIN TRANSACTION READ ONLY` 再拦截 `SELECT nextval(...)` 等隐藏写入。read 的 execute 返回受保护的 executor，链式调用也不会泄露原生可写 cursor。
- write 正常提交，异常回滚并重抛原异常。记录首次 DuckDB SQL 失败；即使调用方捕获了 SQL 异常，也在退出时回滚并重新抛错，防止 aborted transaction 的 COMMIT 静默回滚造成误报成功。
- executor 的 fetchone/fetchall 对 DuckDB 无时区 TIMESTAMP 补 UTC，包括 WriteTx 链式 fetch；execute 不泄露原生连接，返回对象没有 commit/rollback/cursor/connection 公共接口，链式 execute 仍受事务边界保护。参数及 executemany 行原样绑定。
- 迁移发现检查编号、名称、重复、目录、UTF-8、缺失已应用文件、名称变化及 SHA-256；CRLF/CR 规范成 LF 后计算 SHA。读取上限 2,097,152 字节，按版本升序补所有未应用版本，包括低于当前最大值的编号。
- SQL splitter 支持单双引号、双写引号转义、E 字符串反斜杠转义、美元引号、行注释、嵌套块注释；分号只在语句外切分。仅允许 CREATE TABLE/INDEX/VIEW（含 UNIQUE INDEX）与 INSERT，拒绝破坏性 SQL 和非契约 CREATE。
- 每个迁移文件独立事务，DDL 与版本记录一起提交。任意后续文件失败时，关闭同路径所有已打开句柄，将批次起始备份完整复制到同目录临时文件，flush/fsync 并关闭后才 replace 原库；不会留下前面成功的迁移。复制或同步失败保留原文件；成功替换后去掉失败库 WAL，避免恢复后重放升级内容。
- 全新库失败只删除本次 open 原先不存在的主文件/WAL；原有库即使尚无业务表也备份恢复。任一句柄提交了数据后，其他句柄不得再把库当成可删除的全新库。

## DuckDB 1.4.3 实证与文档矛盾

1. **独立 cursor 的读取范围已由主审裁定。** 原生 `connection.cursor()` 使用独立事务，不与主连接/其他 cursor 共享未提交数据。真实测试 `test_real_duckdb_cursor_transaction_is_independent`：writer BEGIN 后插入 1，writer SELECT 得到 `[(1,)]`，另一 cursor SELECT 得到 `[]`，ROLLBACK 后无行。主审明确：write 内 `db.read()` 只读已提交快照；需要读取未提交数据，必须传入当前 tx 作为 SqlExecutor。专项回归同时验证两种读取结果及 UTC fetch。

2. **原生返回类型的逃逸问题已按主审批准修复。** 首版因原 §5.1 的返回类型要求暴露原生连接；专项补丁将返回类型收紧为 `WriteTx` 并返回 self，无原生连接公共返回值。回归验证返回值无法 commit/rollback、禁止链式 SQL COMMIT/ROLLBACK/BEGIN、上下文结束后失效、异常确实回滚、链式 fetch 返回带 UTC 的 datetime。未使用类型伪装或动态导入。

3. **备份新旧排序。** C-03 §4/§5.1/§6 和 04 §2 的“按文件名保留”会让 `v999` 的旧库胜过 `v1` 的新库，也会使同秒不同 label、`-10` 与 `-2` 排错。按本次明确要求采用实际 UTC 时间及同秒生成顺序；反向版本、反向 label、12 次同秒调用均有真实测试。

4. **全新库定义。** open 已创建 schema_version 后文件大小非零，不能再仅以 stat 判断“新装空库”。按本次明确要求追踪是否本次创建以及是否有成功写入。已有空库保留起始 schema_version，全新库失败安全删除本次生成文件。

5. **04 §1 TODO-VERIFY(C-03) 的确切索引事实。** 无外键时同一事务 DELETE(id=1) 再 INSERT(id=1) 成功；两行 `UPDATE id=id+1` 也成功；2049 行同类 UPDATE 在 `id=2048` 报 Duplicate key。父行被外键引用后，更新父主键或删除父行均报 foreign key constraint。仍遵循业务禁止更新主键/UNIQUE 及不声明外键的红线；没有为此修改权威 DDL。

## 交接与复用经验

- 失败迁移后所有同路径句柄保持关闭；需要审计恢复结果时显式重新 open。该行为避免陈旧引擎状态/WAL 重放。
- write 内只读函数使用 tx；db.read 用于读取已提交快照，不应用来确认当前 write 刚写入的数据。
- read_only 只读取已经初始化的库，不建目录/表；write/migrate/CHECKPOINT 备份需要可写连接。
- 独立 backup_database 的外部原生连接调用方应确保没有非托管并发写入；托管 Database 路径有共享锁及关闭连接流程。进程间单实例锁由启动层负责，不在本包重复实现。
