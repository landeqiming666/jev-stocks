## 主审集成事项与限制

1. 生产 FeedbackHost 挂载与 full gate 由主 agent 完成。本包 production build 是原生产入口的编译验证；不能将产物大小或 mock 浏览器称为已完成生产挂载。
2. React 19 默认 root callback 会打印原始异常。集成 createRoot 必须使用导出的 feedbackRootOptions（或等价白名单安全回调）；仅包裹 ErrorBoundary 不足以防 React 默认 console 泄露。自有开发入口已使用该配置并用浏览器 console 实测未知异常不泄密。本包不改 main。
3. 基线 AppShell 自带离线横幅。真实组合浏览器明确断言当前两条（.l-banners 和 .c-feedback-banners 各一条），没有把重复计作最终生产验收。主 agent 承诺在挂载时移除旧横幅；届时须把 shell 组合断言改为一条，再跑该路径与完整业务根。现有数据源降级/config/engine 横幅继续由 shell 负责。
4. 单个 FeedbackHost 正常使用约定为 `<AppShell><FeedbackHost><PageFrame>…</PageFrame></FeedbackHost></AppShell>`；可以复用 AppShell 提供的 #feedback-root。集成根负责 onCoreRetry 的实际生命周期动作，尚未验收真实核心 failed→用户重启的闭环。
5. Tauri/core 真进程、Windows 实机、完整业务根路由、真实数据源/模型、最终 shell 单条横幅与完整 GUI E2E 未验收。没有新 common 键需求；本包文案只在 feedback.ts，未修改 common/index。
6. 没有 spawn、新 worktree、push、main/ref 修改、锁修改、其他包/RPC 修改、知识库或个人日志写入。知识库沉淀按本次用户禁止写入的指令省略。
