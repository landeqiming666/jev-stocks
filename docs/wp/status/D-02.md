## 实现与接口

- `SecTickerSource(http, *, email_provider=None)` 每次 fetch 重新读取当前设置。缺少有效邮箱时先抛 `CONFIG_REQUIRED`，`data.missing=["secEmail"]`，不会调用 HTTP。配置后实际头为 `Sentinel/<sentinel.__version__> <email>`；没有默认用户邮箱。邮箱缺省/空白/非法、修改立即生效均已验证。
- source 要求 fields 精确等于 `["cik", "name", "ticker", "exchange"]`，每行 list 长度恰为 4；错误整批 `SOURCE_UNAVAILABLE/TICKER_SCHEMA`。source 不映射交易所、不丢行，只把 CIK 转为文本承载；非法 CIK 仍保留到 repository 计数。D-01 的 RATE_LIMITED、DECODE_FAILED 等 SourceError 原样传播。
- repository 统一映射四个交易所；非法交易所计 skipped_exchange，非法代码/CIK 计 skipped_symbol。代码 strip/upper、`-` 改 `.`，规范代码为 `[A-Z0-9]+(?:\.[A-Z0-9]+)*`，拒绝空串、引号、空白、百分号、下划线及首尾/连续点。CIK 仅接受 1..9999999999 的普通整数或 1..10 位 ASCII 数字文本，存为十位；bool、零、负数、浮点、NaN/Inf、溢出、Unicode 数字、带空白和超过十位文本均拒绝。
- 同规范 symbol 保留最小十位 CIK，同 CIK 保留先出现行，记录重复 warn。25 行 fixture 的完整计数为 `total=25, kept=13, skipped_exchange=2, skipped_symbol=9, duplicates=1, deactivated=0`，且 total 等于 kept 与三类跳过/重复之和。
- 资源读/校验在事务前，所有 instrument 非键列更新、旧 US 标的软下线、本批别名重建、`setting.lastTickerRefreshAt` 更新在同一个 Database.write 中；水位使用共享 `clock.to_iso` 的 UTC Z 格式。没有 instrument DELETE。inactive 行及其旧别名保留，搜索过滤 inactive。测试中模拟持仓依赖仍存在。
- 同标的同规范 alias 只保留第一次 kind：symbol、name_zh、name_en、alias。搜索用绑定参数的 contains/starts_with，实现 07 的包含/前缀语义，避免 LIKE 通配符；按 instrument_id 聚合 max(score)，分值 120/100/80/60/30，排序 score 降序、symbol 升序。query 原串 1..64，norm 空拒绝；limit 默认 20、1..50，拒绝 bool/浮点/字符串。SQL 不拼接查询文本或代码。
- `InstrumentService.search(query, limit=20)` 仍返回 `list[SearchHit]`。`SearchParams(query, limit=20)` 校验入参；`SearchResult.from_hits(hits).to_wire()` 返回 `{items: Instrument[]}`。领域字段保持 snake_case，wire 字段精确为 instrumentId/market/symbol/name/nameZh/exchange/currency/isActive；CIK 与 score 不泄露到 05 的结果结构。没有注册 RPC，由 C-07 负责。
- `repo.get(instrument_id)` 返回包括 inactive 在内的 Instrument 或 None，SQL 参数绑定；P-01 应在持仓操作前验证标的存在、市场及 active 状态。本包不写持仓。新增 `repo.is_empty()` 供服务检查 US 表为空。
- 构造兼容 `InstrumentRepository(db)`；默认资源位置基于模块文件定位仓库资源，不依赖 cwd。兼容注入 `resource_dir=<资源根>/aliases/us_zh.json` 的根目录或 `alias_path=<文件>`，二者互斥。含空格/中文路径已通过测试。未来 C-07 打包必须注入资源根。资源在构造和每次导入前校验，缺失、损坏、shape/类型错误、canonical symbol 重复为 INTERNAL。显式空别名数组资源合法，生产文件另验 >=100。
- ensure_fresh 在 offline/has_sec_email=False 时不 fetch；注入 aware clock，表为空、水位不存在或严格 `now-last > 7天` 才刷新，恰等于七天不刷新。04 设置默认的 JSON null 水位视为未刷新。source SourceError 和设置并发清空导致的 CONFIG_REQUIRED 只 warn，用旧表。坏资源/水位/数据库错误及其他内部错误传播，不被当成网络降级吞掉。
- **空响应区别**：service 网络 fetch 返回 [] 时仅 warn，既不 replace，也不推进水位，首次空响应也不伪造刷新成功。repository 显式 `replace_from_sec([])` 是合法全量替换：把已有 US 标的软下线并推进水位。两种语义已分别测试。
