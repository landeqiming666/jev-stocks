## API 与装配

`sentinel.quant` 导出 `HoldingPoint`、`PricePoint`、`RiskInput`、`RiskResult`、
`build_risk_input`、`compute_risk`、`RiskService`、`register_handlers`。

```python
build_risk_input(holdings, prices, window, min_observations=60,
                 *, calendar, as_of) -> RiskInput
compute_risk(data, *, shrinkage_alpha=0.1,
             singularity_ratio=1e-12) -> RiskResult
RiskService(db, *, calendar, clock=sentinel.clock.now)
service.compute(scope, window, currency) -> RiskResult
register_handlers(registrar, service) -> None
```

- `calendar` 使用真实 D-04 的 `is_trading_day`、`prev_trading_day`、`latest_closed_day`。
- `clock` 是返回带时区 datetime 的可注入 callable；服务先转 UTC，再取市场最近已收盘日，读数不超过该日期。
- `RiskInput` 在 WP 基础字段之外显式携带 `as_of/from_date/window_label`，及默认 60 的 `min_observations`、有效收益日期、警告、剔除项；纯函数不自行读取时间或数据库。
- `PricePoint` 保留 WP 字段，并追加可选 `source=None`。服务从真实 `price_daily.source` 注入来源；一个一日收益的两端来源不同则无效，不拼接来源切换日。
- 注册一个真实 `risk.compute` handler，参数和结果模型均交给现有 Dispatcher；线上仅接受 scope=holdings、三个 window、currency=USD。额外字段、内部测试门槛、错误标量类型均拒绝。
- 所有业务中文集中在自有 `messages/risk.py`。`RiskDataInsufficient` 通过本包模板生成 wire 文案与 observations/required，公共 initializer 尚未合并风险目录时也不产生 missing-message 回退。

## 数值与数据边界

- 保留真实 `Decimal(18,4)` 数量，包括 `0.0001`、`0.1250`；市值在独立 60 位 Decimal context 中相乘、求和，仅权重最终转 float64。quantity=0 只进入 excluded，归档持仓不查询。
- 估值一律取窗口终点的原始 close。收益率按窗口内所有参与标的统一使用 adj_close；任一 adj_close 为 NULL 时整体回退 close，NaN/inf/非正价作为无效端点。
- 估值终点采用 08 §8.1 的真实共同最新有价日；通常等于各最新日的最小值，该上界某标的内洞时退到共同有价日，保留该标的权重。没有任何有效基线的标的才剔除。
- 先逐资产按相邻市场交易日计算一日收益，再取有效日期交集。缺价日与下一交易日均不能产生该资产收益，不压缩跨多日收益。
- 生产门槛固定 60；四日文档样例只通过纯函数输入的显式测试参数降低门槛。样本不足不返回任何风险指标，也不写审计。
- 零方差列保留在 R、权重、协方差、相关标的映射中；对应非对角相关为 null，对角强制 1.0。SVD 只处理非零方差列，loadings 省略零方差标的；全部零方差时 explained/loadings 为空。
- 样本协方差 ddof=1，年化固定 252，与窗口标签和实际覆盖年数无关；收缩为 alpha=0.1，条件数阈值为 1e-12。
- SVD 符号严格以实际最大绝对值为正；精确并列取 symbol 首列。载荷排序仅将 1e-12 级舍入并列按 symbol 排列，输出值保留未舍入 float。解释比例总和仅修正浮点舍入超过 1 的尾项。
- 最大回撤含初始净值 V0=1；对数净值实现避免长窗口 cumprod 溢出。必填指标无法有限表示时抛错误，不伪造 0；可空条件数与相关格使用 null。
- 警告顺序为未复权、奇异、单持仓、行情落后、三年覆盖不足，之后附零方差说明，同文案去重。
- “比最小最新日终点更旧”的行情警告在该终点定义下不可触发，因此以注入时钟的最近已收盘日计算超过三个市场交易日的落后；测试固定时钟验证该行为。

## 审计与迁移

- 本包创建 `011_risk.sql`，与 04 §3.11 SQL 块逐字一致，未修改其他迁移编号。
- 持仓与行情在同一 `Database.read()` 事务内读取并物化，退出只读快照后执行 build、NumPy、模型转换、JSON 与输入哈希。计算不持 read/write 锁，允许并发订单、扫描和持仓更新。
- 所有 audit 参数与 ID 在无锁阶段准备完毕，最后短 `Database.write()` 仅执行一条 risk_run INSERT；只有事务提交成功才返回结果，写入失败仍映射 INTERNAL。
- 取数后的数据库变化不会修改已物化的 HoldingPoint/PricePoint、计算矩阵或已保存输入。审计绑定读取时的快照与 input_sha256，不要求计算期间锁定当前持仓。
- `result_json` 使用 `model_dump(mode="json", by_alias=True)` 与 `json.dumps(allow_nan=False)`，实际与 Dispatcher 返回逐字段相等。
- `params_json` 包括固定算法版本 `p06-risk-v1`、收缩、奇异阈值、年化、门槛、价格基线、时钟、行情截止，以及数量字符串、原 close、权重、日期、收益矩阵、来源和输入 SHA-256，可按保存矩阵复核结果。
- 迁移测试只在临时 DuckDB 复制实际 001/002/003/005/011，不补造他包表；核对自身 DDL、schema_version=11 的名称/checksum、重复迁移幂等，不假设整个仓库最高版本必须等于 11。
