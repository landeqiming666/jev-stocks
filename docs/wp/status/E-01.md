## 交付内容

- `resources/demo/` 提供 7 个确定性 fixture：6 家虚构公司及 18 条别名、5 条持仓、6 条逻辑与 6 个版本、6 份披露及文件/段落、12 条判定、2 条处理记录、1 次扫描与 6 个批次、1,560 行日线、模拟账户/流水/订单/成交/持仓/权益快照、1 条风险审计。
- `manifest.json` 固定版本、起止日期、六类计数、待处理 3/待确认 1、待处理顺序 `ZZAR/ZZCL/ZZEN` 和 7 个文件 SHA-256。载入器在构造时校验版本、计数、文件清单、哈希和主键唯一性。
- `012_demo.sql` 与 `docs/04-数据模型.md` §3.12 逐字一致。`demo_row(table_name, pk_json, inserted_at)` 是唯一允许物理删除演示行的登记簿。
- `loader.py` 按 `instrument → holding → thesis → thesis_version → event_doc → event_file → event_passage → decision → thesis_action → scan_run → scan_batch → price_daily → paper_account → cash_ledger → paper_order → fill → position → equity_snapshot → risk_run` 顺序写入；每行同步登记排序键 JSON。价格另校验 6 个代码 × 260 个共同交易日、每日 6 行、日期严格升序。
- `service.py` 在单个 `Database.write()` 内完成载入和计数复核；`ALREADY_LOADED`、`REAL_DATA_PRESENT` 均在任何写入前拒绝。清除按登记簿逆序删除，`setting.demoDataLoaded` 最后改回 `false`，再清空登记簿；残留 `source=demo`/`is_demo` 行时整批回滚并记录表名。
- `rpc.py` 只注册合同既有的 `demo.load`、`demo.clear`，参数空对象、`extra=forbid`，结果分别为 `loaded/counts` 与 `ok`。未新增 RPC 方法或字段。
- `scripts/load_demo.py` 使用平台 `file_lock(data_dir/"core.lock")`；核心占用时退出码 2。支持 `--clear`、`--dry-run`、`--json`、`--data-dir`；资源只读，不创建 HTTP 客户端。
