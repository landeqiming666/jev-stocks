## 实现与边界

- 8 个数据库 setting 键有严格模型与缺省值；损坏 JSON、非有限 JSON、非法已存类型均报 INTERNAL。Settings wire 是 8 字段，Bootstrap wire 是完整 10 字段；refresh 时间只在内部读取，语言与五项 MVP-0 外联说明只读。
- Patch 使用 strict / extra=forbid，整数拒绝 bool、字符串与 null；engine/email 先 Python strip 再验证；空邮箱转 null，合法邮箱上限 120 码点。
- 整个 patch 在写入前验证；变化键使用一次注入 clock，原子事务内再次比较已有 JSON 值，no-op 不刷新时间。第二条写入失败时第一条也回滚。事务内没有钥匙串、网络或 probe 调用。
- SecretStore protocol、MemorySecretStore 与 keyring 系统 provider adapter 已实现。密钥先 strip，再校验 1..512 码点、无内部空白。读取旧值、替换与清除前登记脱敏；清除幂等且不清空本进程登记。敏感 provider/domain 异常统一改成固定 INTERNAL，不把异常 message、params 或 secret 传到 wire/log。没有注册任何密钥读取 RPC。
- 连接检查缺配置时不执行 probe，missing 顺序固定为 jevKey、secEmail；检查顺序 Jev、SEC、JEVDB。单项异常变成单项 false，并继续后续检查。probe 自由文本不直接回传，使用本包安全文案。JEVDB false 可允许日常 direct fallback，文案明确最终 I-02 真实 JEVDB 验收仍是硬门槛。
- 七个 handler 注册到真实 C-01 Dispatcher，参数与结果均严格验证；结果错误为 INTERNAL。注册前检查七个方法的重复，避免常规启动注册中途发生重复错误而留下半注册；未修改 Dispatcher 接口。
