## 实现行为

- `SourcePolicy` 是不可变数据类，提供 SEC / 腾讯 / 纳斯达克默认策略、线程安全注册与查询、未知来源告警一次、数值边界验证。后续注册腾讯读取 30 秒策略，对已创建客户端也生效。
- `get`、`get_text`、`get_json` 使用显式类型参数；`CancelToken` 为结构化 Protocol，无 RPC 依赖；另提供 `close` 和上下文管理器释放 httpx 连接池。
- 默认最多三次网络尝试。429、500–599（含 529）、ConnectError、ConnectTimeout、ReadTimeout 重试。退避为 1、2 秒乘 0.5–1.0 随机系数；数字 Retry-After 取较大值并 cap 60 秒；日期、负数、非有限值按零处理并告警。
- 默认时钟下，同一来源跨 HttpClient 实例共享令牌桶和熔断器；不同来源独立。注入相同 monotonic 时钟的客户端同样共享状态，不同测试时钟隔离。SEC 初始容量 5，持续补充 5 次/秒。令牌等待使用浮点 monotonic，等待不持锁，每次重试重新取令牌并检查取消、离线与熔断。
- 重试耗尽只记一次来源失败；连续五次失败打开 600 秒，半开最多一个调用，探测内部重试仍属于同一个许可。成功关闭，失败重开。闭合状态的非 429 4xx 不计失败。SEC 403 不重试，立即强制打开，reason 为 SEC_FORBIDDEN。许可代数防止迟到成功关闭已强制打开的熔断器。
- `on_degraded(source, 600.0)` 在打开时通知；回调异常只记录固定事件，不掩盖来源错误或记录异常内容。
- 离线、调用前取消和熔断打开不发 transport。退避与令牌等待在携带 CancelToken 时按至多 50 ms 的片段检查；正在阻塞的 transport 也可由调用线程及时返回 CANCELLED。
- GET 条件缓存保存 ETag、Last-Modified、响应头、获取时间及正文摘要。缓存上下文包括来源和调用者请求头，防止同 URL 的不同来源或请求变体串用。304 使用请求开始时的不可变快照；孤立 304 在最多三次预算内去掉验证器重取。304 更新元数据时比较原快照，避免迟到响应覆盖较新的清单。
- 缓存读取验证 JSON、URL、验证器、头部、时间、正文长度与 SHA-256。缺失、损坏的缓存失效后无条件重取；无验证器或被截断的响应不缓存。临时文件 fsync 后原子 replace，只有完整清单提交后读者才看到新正文。
- 流式接收保留最多 5,242,880 字节，超限截断并固定事件告警、关闭流。编码以响应头 charset 为准；缺 charset 严格尝试 UTF-8、cp1252；禁止使用 httpx 默认 UTF-8 replace。截断处的未完整字符不返回半截文本；真实解码失败映射 DECODE_FAILED，JSON 解析失败映射 INVALID_JSON。
- HTTP 日志包含所有 02 §11 固定字段以及 source、method、脱敏 URL、status、attempts、from_cache。URL 去掉敏感 query、userinfo、fragment，不记录正文或异常正文。httpx/httpcore 日志级别设为 WARNING，关闭会暴露原始 URL/请求头的 INFO/DEBUG 详情；保留 Sentinel 的结构化 HTTP 日志。

## 规格冲突与需主 agent 裁定事项

1. **30 秒与 Retry-After 60 秒冲突**：已在开工时报告。真实实现为每次网络 attempt 30 秒预算，包含连接、响应头、chunk 读取和响应关闭；连接/读取分别最多 5/20 秒。令牌等待和可取消退避各自独立，整个 get 不承诺总计 30 秒。测试在单次 29.999 秒成功、30.000/30.001 秒 TIMEOUT；三次各 30 秒加 0.5/1 秒退避累计 91.5 秒；429 等待 60 秒后第二次成功的 elapsed_ms 为 60000。建议将 07 §3 与 D-01 文案改为“每次网络 attempt 总预算”。
2. **缓存两个固定文件与一致原子提交冲突**：独立 replace `<key>.body` 与 `<key>.meta.json` 无法构成一个原子事务。采用 `<sha256(url)>.<sha256(body)>.body` 不可变正文，以及原子替换的 `<sha256(url)>.meta.json` 清单；清单增加 context、sha256、headers，保留 url、etag、last_modified、fetched_at。建议主 agent 更新物理布局规格。旧正文代际保留，避免并发读者/写者看到不完整配对；当前未实现清理/TTL。
3. **C-00 分层检查冲突**：第一次全量回归为 82 passed、1 failed，因为 logging_setup 同时在 ALWAYS_ALLOWED 和 LAYER_RULES 中，而 violations 没有扣除 ALWAYS_ALLOWED。没有改动该测试，没有用 importlib 绕过。D-01 新增 telemetry.py，通过标准库 logger 写相同记录结构，使用 C-00 已配置的 JSON formatter 和统一脱敏；建议主 agent 在后续工作包修正检查器并决定是否统一到 C-00 log_event。
4. **max_attempts 范围冲突**：D-01 §5.2 允许 1–4，但本次任务明确要求最多三次，因此策略验证限制为 1–3；新增 max_attempts=4 被拒绝的测试。
5. **半开失败与非 429 4xx 不计数**：闭合状态遵循不计数规则；实际半开 HTTP 探测失败（包括 405）重新打开 10 分钟，遵循 §3 的半开失败规则。取消/离线/令牌等待失败释放半开许可，不算网络探测失败。建议将 §6 的非 429 4xx 规则补充为“闭合状态”。
6. **公开方法扩展**：按任务要求及既有 §6 实现 record_failure(force_open=True)。额外接受内部 permit，返回布尔值表示本次是否打开，供通知回调使用；原来的无参调用兼容。get_text/get_json 使用显式 headers/cancel/use_cache 类型参数，替代宽泛 kwargs，保持公开调用功能。

## 风险、交接与边界

- 同步 httpx 不能强行中断任意阻塞的底层 transport。调用线程按 deadline 返回 TIMEOUT / CANCELLED；worker 在底层阻塞结束后检查停止标记并关闭流，迟到结果不会写缓存或改熔断。标准连接/读取超时仍为 5/20 秒；无视超时的自定义 transport 可能留下暂未退出的 daemon worker。已用阻塞 MockTransport 验证调用方提前退出及迟到结果被丢弃。
- cache_dir 是缓存根目录，正文和清单写在其 http/ 下；cache_dir=None 时无磁盘缓存。源适配器应复用 HttpClient 并在应用退出时 close。未增加邮箱配置检查，D-02/D-03 按其契约负责 CONFIG_REQUIRED。
- 仅使用已有 httpx 与标准库。锁文件已有 typesafe-sdk 间接依赖 tenacity，离线 sync 会安装它；本工作包没有导入/使用 tenacity，也未改动 pyproject.toml 或 uv.lock。
