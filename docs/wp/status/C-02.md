## 实现行为

- `install` 使用 bridge 插件的 Ready 事件，保留 WP-00 的窗口 setup、窗口尺寸、平台初始化脚本和 single-instance 插件。已核对锁定 Tauri 源码：Ready 先执行原 Builder setup 再通知插件；因此核心启动在窗口装配之后。启动失败发 failed 状态并保留外壳。已提取 `emit_core_event`、`start_state`、`on_ready`、`on_exit`，同一 invoke_handler 仍只注册 rpc_send/open_external，保留原装配顺序和事件语义。
- `runtime_context()` 在 `generate_context!()` 之后设置 `csp` 和 `dev_csp`，`run()` 实际传入这个 context。两种模式使用规范的 CSP 原文；没有 eval、远程脚本或远程字体。
- 配置命令按 ASCII 空白拆分并拒绝引号；`std::process::Command` 直接启动。数据路径、资源路径、父 PID、日志级别分别作为 argv 传入；设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`。每一次 spawn 的命令均调用 `Platform::prepare_core_command`。
- stdin 发送 frame 上限为 1,048,576 UTF-8 字节，包含 writer 追加的一个 LF；raw line 最大 1,048,575 字节，raw 1,048,576 在写入前拒绝，与 C-01 既有 cap 一致。拒绝 CR/LF 注入和前端伪造的 rs- ID。stdout reader 保留原独立接收语义：LF 之前的 raw 字节数可达 1,048,576（含 LF 的物理 frame 可为 1,048,577）；超限整行丢弃直到换行再恢复，仍按原逻辑移除尾 CR。普通非 JSON 原文仍转发。stderr 持续排空但不转发到前端。未修改接收算法或 C-01 frame cap，规范澄清由主 agent 负责。
- 内部响应依据解析后的 JSON 顶层 id 分类；字段顺序、空格均不影响。所有 rs- ID，包括未知和过期 ID，均不泄漏到 core://message。当前代际以外的管道事件被丢弃。
- 独立有界 stdin writer 和监督线程防止 pipe 写入背压卡住心跳与退出。正常 heartbeat 5 秒、超时 2 秒，连续三次失败重启；开发启动等待 60 秒。测试注入短计时，真实进程验证相同算法。
- 重启预算按桥接会话累计，最多三次，退避 1/2/4 秒。ready 对外仍使用 attempt=0，但不会重置内部累计预算。真实 EOF、崩溃、启动超时、写故障均进入状态恢复。
- 用户关闭标记和 spawn 共用锁，关闭后禁止再 spawn。发送内部 app.shutdown，等 3 秒后经 Platform::kill_process_tree 清理，wait/reap 直接子进程，清空内部 pending，释放 writer，排空事件并回收 I/O 线程。若上游未清理继承管道的后代，线程回收有界并记录 PIPE_NOT_CLOSED；平台前置修复后孤儿回归通过。
- 生产 `open_external` 先校验 URL，然后 `spawn_blocking` 调用 `Platform::open_external`。Mac 使用 `/usr/bin/open`，完整原 URL 为唯一 argv，不执行 shell；stdin/stdout/stderr 均置空。返回实际 I/O 种类、系统错误码或退出状态，原始错误正文在平台边界被丢弃，避免泄漏 URL/credentials。任务异常/取消也不输出 panic 正文。
- `open_external_with` 为生产函数和回归共用的注入接缝，校验失败不会调用 opener。FakeOpener 验证成功、精确单 argv 和失败；Mac 平台测试检查真实生产装配 helper 的固定路径、唯一完整 URL 参数及文件可执行权限，不执行 open，不打开用户浏览器。
- rpc_send 的 spawn_blocking 任务异常、取消及其他任务错误均映射固定安全文案；不使用 JoinError.to_string，不返回请求/panic 正文。正常 BridgeError 的用户文案保持原样。
