# 00 术语与约定

> 版本：v2.0 · 2026-11-02 · 状态：已定稿
> 全部文档、契约、代码共用的词汇和规则。其他文档与本文冲突时，以本文为准。

## 1. 文档写法

### 1.1 要求强度词

| 词 | 含义 | 违反的后果 |
|---|---|---|
| 必须 / 禁止 | 硬性要求，每条都能被测试或检查脚本验证 | 验收不通过 |
| 应该 | 默认照做；有充分理由可以偏离，但要在 PR 描述里写明理由 | 评审时要求说明 |
| 可以 | 可选 | 无 |

文档里不写“等”“适当”“尽量”。需要范围时给出确切数字或枚举。

### 1.2 文档头部

每份 `docs/*.md` 在 H1 之后紧跟一段引用块，必须包含 `版本` 和 `状态`：

```markdown
# 06 语义判定与 Jev

> 版本：v2.0 · 2026-11-02 · 状态：已定稿
```

`状态` 只有两个取值：`已定稿`、`待重写`。`待重写` 的文档内容是旧稿或占位，不可据此开发。`python3 scripts/check_docs.py --strict` 会把它当作错误。

### 1.3 外部事实

- 没有亲自核实过的外部接口、字段、费率、日期，必须写成 `TODO-VERIFY(<工作包ID>)`，并由该工作包负责核实后改写。
- 引用外部来源要写 URL 和访问日期。本套文档的来源访问日期均为 2026-11-02。
- 禁止在文档、界面或日志里声称“已验证”，除非有对应的测试或录制数据。

### 1.4 虚构示例数据

文档、原型、测试和演示里的示例一律使用下表的虚构公司，不使用真实公司的名字编造事件。代码 `ZZ` 开头，与真实上市公司无关。演示数据脚本写入前必须检查这些代码是否与 SEC 标的表冲突，冲突就报错。

| 代码 | 公司（虚构） | 典型用途 |

## 2. 术语表

同一个概念在文档、契约、代码、界面里只用一个词。

| 中文（界面用词） | 英文 | 代码标识 | 定义 |
|---|---|---|---|
| 投资逻辑 | thesis | `thesis` | 用户对一只股票写下的一条可检验判断，1–500 字 |
| 失效条件 | kill condition | `kill_condition` | 用户认为逻辑被推翻的情形，可选，≤ 300 字 |
| 逻辑版本 | thesis version | `thesis_version` | 每次编辑生成一个不可变的新版本；判定只针对具体版本 |
| 披露事件 | event | `event_doc` | 一次监管披露，对应一份 8-K 或 6-K（一个 accession number） |
| 披露文件 | event file | `event_file` | 一个披露事件里的一份文档：主文档、EX-99.1 附件等 |
| 段落 | passage | `event_passage` | 披露文件正文切出的片段，≤ 1200 字符，判定的最小文本单位 |
| 句子 | sentence | `sentence` | 段落内切出的句子，用来定位证据 |
| 判定 | decision | `decision` | 对一对（逻辑版本，段落）得出的结论：关系 + 五个概率 + 引擎信息 |
| 关系 | relation | `relation` | `none` 无关 · `support` 支持 · `weaken` 削弱 · `overturn` 推翻 · `uncertain` 待确认 |
| 概率 | probability | `probability` | Jev 回答某个 Noul 问题“是”的概率，0–1。**界面和文档禁止称为“置信度”**，因为 Jev 的 Choice/Score 另有一个 `confidence` 字段，含义不同 |
| 证据 | evidence | `evidence` | 支持某个判定的原文句子（句子序号 + 字符偏移） |
| 待处理清单 | inbox | `inbox` | 所有尚未处理的“推翻 / 削弱 / 待确认”判定，今日页的主体 |
| 处理 | action | `thesis_action` | 用户对判定的回应：`still_valid` 仍然成立 · `revise` 修正逻辑 · `exit_intent` 准备卖出 · `ignore` 忽略 |
| 扫描运行 | scan run | `scan_run` | 对一个市场的一次“抓取 + 判定”，有状态机 |
| 扫描批 | scan batch | `scan_batch` | 一次运行内的最小判定单元：一个标的 × 一个披露事件。一批失败不影响其他批 |
| 水位线 | watermark | `watermark` | 某市场上次成功扫描覆盖到的时间点；下次扫描从这里开始 |
| 引擎 | engine | `engine` | 调用 Jev 的方式：`jevdb`（DuckDB 扩展）或 `jev_direct`（官方 SDK 直连） |
| 模型 ID | model id | `model_id` | 固定的 Jev 版本号，如 `jev-1.14.0`。**禁止使用别名 `jev-latest`**，别名会随新版本变化而改变答案 |
| 问题集 | question set | `question_set_version` | 发给 Jev 的全套英文问题和阈值的版本号，改动必须升版并重跑评测 |
| 持仓 | holding | `holding` | 用户登记的真实持仓，数量为 0 表示“只关注” |
| 模拟账户 | paper account | `paper_account` | 与真实持仓分离的纸面账户 |
| 回放时钟 | replay clock | `clock_date` | 模拟账户当前所处的模拟交易日；撮合和估值只读取 `trade_date ≤ clock_date` 的行情 |
| 模拟持仓 | position | `position` | 模拟账户内的持仓 |
| 共同交易日 | common trading days | — | 一组标的全部有价格的交易日，风险计算只用这些日子 |

## 3. 标识符与命名

### 3.1 业务 ID

| ID | 格式 | 例子 |
|---|---|---|
| `instrument_id` | `<market>:<symbol>`，symbol 大写；类股用 `.` 分隔 | `us:AAPL`、`us:BRK.B` |
| `event_id` | `us:<accession>`，accession 保留连字符 | `us:0001234567-26-000123` |
| 其他实体 ID | ULID（26 字符，按时间排序），由 `sentinel/ids.py` 的 `new_id()` 生成，不引入第三方库 | `01JC8Z5V3Q7M2N4P6R8T0W2Y4A` |
| `passage_id` | `sha256(event_id|file_seq|start|end)` 的前 32 位十六进制，确定性 | — |
| RPC 请求 `id` | 客户端生成的字符串，≤ 64 字符，同一连接内唯一 | `r-17-k3j9` |

确定性 ID 的完整定义在 [04-数据模型.md](04-数据模型.md)。SEC 的 `BRK-B` 这类写法由市场适配器转换为 `BRK.B`，核心逻辑里只出现规范写法。

### 3.2 代码命名

| 对象 | 规则 |
|---|---|
| 数据库表和列 | `snake_case`，表名单数；避开 SQL 关键字（所以是 `paper_order` 而不是 `order`） |
| RPC 方法名 | `<域>.<动作>`，动作用 camelCase：`thesis.create`、`paper.order.place` |
| RPC JSON 字段 | `camelCase` |
| Python | PEP 8；模块 `snake_case.py`；类 `PascalCase` |
| TypeScript | 变量和函数 `camelCase`；类型和组件 `PascalCase`；组件文件 `PascalCase.tsx`；其余文件 `kebab-case.ts` |
| CSS 类名 | 全局 CSS，前缀区分：`c-` 组件、`l-` 布局、`p-` 页面、`u-` 工具、`is-` / `has-` 状态。例：`c-verdict-chip`、`is-active` |
| CSS 变量 | `--kebab-case`，定义在 `tokens.css` |
| 平台层目录 | 平台差异只允许放在这里，其余目录禁止出现平台判断（见 [ADR-016](decisions.md)）：`core/sentinel/platform/`、`apps/desktop/src-tauri/src/platform/`、`tauri.<平台>.conf.json`、`apps/desktop/src/styles/platform-<平台>.css`、`packaging/<平台>/`、`scripts/*.ps1`、`.github/workflows/ci-<平台>.yml` |
| 分支 | `wp/<工作包ID>`，例：`wp/C-03` |
| 提交信息 | `type(scope): summary`，type 取 `feat` `fix` `test` `docs` `chore` `refactor`；scope 用工作包 ID 小写，例：`feat(c-03): add migration runner` |

### 3.3 语言

| 内容 | 语言 | 位置 |
|---|---|---|
| 界面文案、错误 `message` | 简体中文 | `apps/desktop/src/i18n/zh-CN.ts`、`core/sentinel/messages.py`，组件和业务代码里禁止散落长文案 |
| 发给 Jev 的问题文本 | 英文 | 只在 `core/sentinel/semantic/questions.py` |
| 代码标识符、日志、测试名、提交信息 | 英文 | — |
| 代码注释、docstring | 中文，只解释“为什么” | — |

### 3.4 工作包 ID、平台与车道

工作包文件头部的 `platform` 和 `lane` 取值固定（`scripts/check_docs.py` 会检查）：

| `platform` | 含义 | 约束 |
|---|---|---|
| `shared` | 跨平台共享代码 | macOS 与 Windows 都必须通过测试；代码里不得出现平台判断 |
| `macos` | macOS 专属 | 只改平台层的 macOS 文件 |
| `windows` | Windows 专属 | 只改平台层的 Windows 文件；`lane` 必须是 `windows` |

| `lane` | 谁做 | 典型工作包 |
|---|---|---|
| `core` | macOS 主线 | 骨架、RPC、存储、设置、HTTP 基础设施 |
| `data` | macOS 主线 | 标的、SEC 抓取、行情、模拟交易、风险 |
| `semantic` | macOS 主线 | 分句分段、引擎、判定流水线、扫描、评测 |
| `ui` | macOS 主线 | 前端骨架、组件、各页面 |
| `integration` | macOS 主线 | 联调与验收 |
| `windows` | Windows 的一个人 | 以 `W-` 开头 |

ID 前缀：`WP-00` 骨架；`G0-`、`G1-` 技术闸门探针；`C-` 核心运行时；`D-` 数据；`S-` 语义；`P-` 产品功能；`U-` 界面；`E-` 演示数据与评测；`I-` 联调；`M-` macOS 专属；`W-` Windows 专属。

## 4. 时间、日期、金额、数值

| 类别 | Python | DuckDB | JSON（RPC / 契约） |
|---|---|---|---|
| 时刻 | `datetime`（带 UTC 时区） | `TIMESTAMP`（UTC） | ISO 8601 且以 `Z` 结尾：`2026-11-02T13:30:00Z` |
| 交易日 | `date` | `DATE` | `YYYY-MM-DD`，按交易所本地日期；美股用 `America/New_York` |
| 货币金额：现金、成本、费用、权益、盈亏 | `Decimal` | `DECIMAL(18,4)` | 十进制字符串：`"1234.5600"` |
| 成交价、限价 | `Decimal` | `DECIMAL(18,6)` | 十进制字符串：`"187.250000"` |
| 行情价格（OHLC）、汇率、收益率、权重、概率、波动率 | `float` | `DOUBLE` | number |
| 数量 | `int` | `BIGINT` | number（整数） |
| 币种 | `str` | `VARCHAR(3)` | ISO 4217 大写，MVP-0 只有 `USD` |

规则：

1. **所有时刻在内部一律是 UTC**，界面按用户本机时区显示；交易日和市场状态按交易所时区。
2. **金额禁止用浮点累计**，所有现金和账本运算用 `Decimal`。金额默认 `ROUND_HALF_UP` 到 4 位，特例（如监管费向上取整到分）在 [08-模拟交易与风险.md](08-模拟交易与风险.md) 写明。
3. 概率保留原始 `float`，界面显示两位小数；比例（权重、收益率）界面显示一位小数的百分比。
4. 禁止使用本机“当前时间”做业务判断。所有代码从统一的 `clock.now()` 取时间，测试通过环境变量 `SENTINEL_CLOCK` 固定它。

## 5. 环境变量

| 变量 | 用途 | 谁设置 |
|---|---|---|
| `SENTINEL_DATA_DIR` | 数据目录。开发和测试必须指向临时目录，**测试禁止写真实数据目录** | 开发者 / 测试脚本 |
| `SENTINEL_CORE_CMD` | Rust 启动核心进程的命令，默认 `uv run --project core python -m sentinel` | 开发者 |
| `SENTINEL_LOG_LEVEL` | `debug` / `info` / `warn`，默认 `info` | 开发者 |
| `SENTINEL_CLOCK` | 固定“当前时间”（ISO 8601），仅测试用 | 测试 |
| `SENTINEL_OFFLINE` | 设为 `1` 时禁止一切外联，任何网络调用直接抛 `SOURCE_UNAVAILABLE` | 测试 |
| `TYPESAFE_API_KEY` | 官方 SDK 读取的 Jev 密钥 | 核心进程启动引擎时从钥匙串注入；开发模式允许从环境读取 |
| `JEV_API_KEY` | JEVDB 扩展读取的同一把密钥 | 同上 |

密钥永远不写入日志、数据库、诊断包、测试数据。
