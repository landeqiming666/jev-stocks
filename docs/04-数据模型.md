# 04 数据模型

> 版本：v2.0 · 2026-11-02 · 状态：已定稿
> 单文件 DuckDB 1.4.3（ADR-005）里的全部表、迁移规则、核心查询。命名、时间、金额格式见 [00](00-术语与约定.md) 第 3、4 节。
> 本文的 DDL 是**权威来源**：工作包创建迁移文件时必须逐字使用这里的表结构；要改，先走变更申请。

## 1. 总则

| # | 规则 |
|---|---|
| 1 | 表名、列名 `snake_case`，表名单数，避开 SQL 关键字（所以是 `paper_order`，不是 `order`） |
| 2 | 时刻用 `TIMESTAMP`（UTC，无时区），日期用 `DATE`（交易日按交易所本地日期）。Python 里读出后立即补上 `tzinfo=UTC` |
| 3 | 货币金额（现金、成本、费用、权益、盈亏）用 `DECIMAL(18,4)`；成交价、限价用 `DECIMAL(18,6)`；行情 OHLC、概率、权重用 `DOUBLE` |
| 4 | 所有业务 ID 的格式见 [00](00-术语与约定.md) 3.1：实体 ID 是 ULID（`VARCHAR`），确定性 ID 是十六进制摘要 |
| 5 | **不声明 `FOREIGN KEY`**。关联完整性由仓储层保证，并由第 7 节的完整性检查兜底。原因：DuckDB 对带索引列的 `UPDATE`、以及同一事务内“删除再插入同一个键”有已知限制，外键会放大这些限制（`TODO-VERIFY(C-03)`：C-03 写测试复现并记录确切行为） |
| 6 | **禁止 `UPDATE` 主键列和 `UNIQUE` 列**。要改键就新增一行，旧行打上 `archived_at` |
| 7 | **用户数据禁止物理删除**，用 `archived_at` 或状态位。例外只有第 6 节列出的几种，且都需要确认文字或明确的用户操作，并先自动备份 |
| 8 | 所有写操作在 `Database.write()` 事务里完成；事务内**不得**做网络请求或调用模型（[02](02-技术架构.md) 7.3） |
| 9 | 迁移文件只增不改。已应用的迁移被改动会在启动时被检测到并拒绝启动（第 2 节） |
| 10 | 注释写中文，说明“为什么”；DDL 里的 `--` 注释是规范的一部分，创建迁移文件时保留 |

## 2. 迁移

### 2.1 文件与编号

位置：`core/sentinel/storage/migrations/NNN_<名称>.sql`，`NNN` 三位数字。**编号在本文预先分配给具体工作包**，工作包只创建自己的那一个文件，因此并行开发不会撞号。

| 编号 | 文件 | 创建它的工作包 | 包含的表 |
|---|---|---|---|
| 001 | `001_core.sql` | C-03 | `setting` |
| 002 | `002_instrument.sql` | D-02 | `instrument`、`instrument_alias` |
| 003 | `003_portfolio.sql` | P-01 | `holding`、`thesis`、`thesis_version` |
| 004 | `004_filings.sql` | D-03 | `event_doc`、`event_file`、`event_passage` |
| 005 | `005_prices.sql` | D-04 | `price_daily` |
| 006 | `006_decision.sql` | S-05 | `decision` |
| 007 | `007_action.sql` | P-03 | `thesis_action`、视图 `v_last_action` |
| 008 | `008_scan.sql` | P-02 | `scan_run`、`scan_batch`、`watermark` |
| 009 | `009_usage.sql` | S-02 | `usage_daily` |
| 010 | `010_paper.sql` | P-05 | `paper_account`、`cash_ledger`、`paper_order`、`fill`、`position`、`equity_snapshot` |
| 011 | `011_risk.sql` | P-06 | `risk_run` |
| 012 | `012_demo.sql` | E-01 | `demo_row` |

`schema_version` 表**不在任何迁移文件里**，由迁移执行器自己在启动时 `CREATE TABLE IF NOT EXISTS` 创建（先有它才能记录迁移）：

```sql
CREATE TABLE IF NOT EXISTS schema_version (
  version    INTEGER PRIMARY KEY,
  name       VARCHAR NOT NULL,
  checksum   VARCHAR NOT NULL,       -- 迁移文件内容（UTF-8，换行统一为 \n）的 sha256 十六进制
  applied_at TIMESTAMP NOT NULL
);
```

### 2.2 执行规则（C-03 实现）

1. 读取 `migrations/` 下所有 `NNN_*.sql`，按编号升序。文件名不符合 `^\d{3}_[a-z0-9_]+\.sql$` 的报 `INTERNAL`。编号重复报 `INTERNAL`。
2. 读取 `schema_version` 里已记录的版本集合。
3. **对每个已记录的版本，重新计算对应文件的 sha256，与记录的 `checksum` 比较**；不一致（迁移被改过）或文件缺失，拒绝启动，报 `INTERNAL`，日志写明哪个文件。
4. **应用“所有尚未记录的迁移”，按编号升序**。注意这不是“编号大于当前最大值”：并行开发时低编号迁移可能比高编号迁移更晚合并，必须能补上。各迁移之间没有 DDL 依赖（不使用外键，视图只引用同一文件里的表），所以乱序应用是安全的。
5. 如果有待应用的迁移，**先备份**：把 `sentinel.duckdb` 复制到 `backups/sentinel-v<当前最大版本>-<UTC时间戳>.duckdb`，保留最近 3 份。数据库为空（新装）时不备份。
6. 每个迁移文件在**一个事务**里执行（DuckDB 支持事务性 DDL）：按 `;` 切分语句依次执行，最后插入 `schema_version` 一行。切分时必须忽略 `--` 注释和字符串字面量里的分号。
7. 任一迁移失败：回滚该事务，用备份还原数据库文件，以 `INTERNAL` 终止启动，错误信息写明文件名与失败语句。
8. `app.bootstrap.dbSchemaVersion` 返回已记录的最大版本号。

### 2.3 迁移文件的写法要求

- 只含 `CREATE TABLE`、`CREATE INDEX`、`CREATE VIEW`、`INSERT` 初始数据；**禁止** `DROP`、`ALTER ... DROP`、`DELETE`、`UPDATE`。需要改表，新增一个更大编号的迁移。
- 每张表、每列都要有中文注释；枚举列的取值写在注释里。
- 文件末尾以换行结束，使用 LF。

### 3.3 `003_portfolio.sql` · P-01

```sql
-- 用户登记的真实持仓。quantity = 0 表示"只关注"。重新添加已归档的标的时，清空 archived_at 并更新其余列。
CREATE TABLE holding (
  holding_id    VARCHAR PRIMARY KEY,
  instrument_id VARCHAR NOT NULL UNIQUE,

  avg_cost      DECIMAL(18,4),               -- 可空

  updated_at    TIMESTAMP NOT NULL,
  archived_at   TIMESTAMP

-- 投资逻辑。具体文字在 thesis_version 里；这里只放身份、状态和乐观锁用的当前版本号。
CREATE TABLE thesis (
  thesis_id       VARCHAR PRIMARY KEY,
  instrument_id   VARCHAR NOT NULL,
  status          VARCHAR NOT NULL,          -- active | archived
  current_version INTEGER NOT NULL,          -- 乐观锁：UPDATE ... WHERE current_version = :expected
  created_at      TIMESTAMP NOT NULL,
  updated_at      TIMESTAMP NOT NULL,
  archived_at     TIMESTAMP
);
CREATE INDEX idx_thesis_instrument ON thesis (instrument_id, status);

-- 逻辑的每个版本，不可变。
CREATE TABLE thesis_version (
  thesis_id      VARCHAR NOT NULL,
  version        INTEGER NOT NULL,           -- 从 1 开始，每次编辑 +1
  statement      VARCHAR NOT NULL,           -- 1..500 字（Unicode 码点，去首尾空白后计数）
  kill_condition VARCHAR,                    -- ≤ 300 字，可空
  content_hash   VARCHAR NOT NULL,           -- 见第 4 节，判定缓存键的一部分
  created_at     TIMESTAMP NOT NULL,
  PRIMARY KEY (thesis_id, version)
);
```

### 3.7 `007_action.sql` · P-03

```sql
-- 用户对判定的处理记录。只追加，不修改。清单状态由"最新一条记录"决定。
CREATE TABLE thesis_action (
  action_id   VARCHAR PRIMARY KEY,           -- ULID，同一时刻按它排序
  decision_id VARCHAR NOT NULL,
  action      VARCHAR NOT NULL,              -- still_valid | revise | exit_intent | ignore | reopen
  note        VARCHAR,                       -- ≤ 200 字

);

CREATE VIEW v_last_action AS
SELECT decision_id, action, note, created_at AS acted_at
FROM thesis_action
QUALIFY ROW_NUMBER() OVER (PARTITION BY decision_id ORDER BY created_at DESC, action_id DESC) = 1;
```

### 3.10 `010_paper.sql` · P-05

```sql
-- 模拟账户。clock_date 是回放时钟（ADR-013）：撮合与估值只读 trade_date <= clock_date 的行情。
CREATE TABLE paper_account (
  account_id    VARCHAR PRIMARY KEY,
  name          VARCHAR NOT NULL UNIQUE,     -- ≤ 30 字
  base_currency VARCHAR NOT NULL,            -- USD
  initial_cash  DECIMAL(18,4) NOT NULL,
  start_date    DATE NOT NULL,
  clock_date    DATE NOT NULL,
  is_demo       BOOLEAN NOT NULL DEFAULT FALSE,
  created_at    TIMESTAMP NOT NULL,
  archived_at   TIMESTAMP
);

-- 现金流水，只追加。余额由流水汇总得出，不单独存储，避免出现两个"真相"。
--   现金      = SUM(amount) 其中 entry_type IN ('deposit','buy','sell','fee')
--   冻结资金  = -SUM(amount) 其中 entry_type IN ('reserve','release')
--   可用现金  = 现金 - 冻结资金
CREATE TABLE cash_ledger (
  entry_id   VARCHAR PRIMARY KEY,
  account_id VARCHAR NOT NULL,
  entry_date DATE NOT NULL,                  -- 模拟日期
  entry_type VARCHAR NOT NULL,               -- deposit | buy | sell | fee | reserve | release
  amount     DECIMAL(18,4) NOT NULL,         -- 正数增加，负数减少
  ref_id     VARCHAR,                        -- order_id 或 fill_id
  created_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_cash_ledger_account ON cash_ledger (account_id, entry_date);

CREATE TABLE paper_order (
  order_id           VARCHAR PRIMARY KEY,
  account_id         VARCHAR NOT NULL,
  instrument_id      VARCHAR NOT NULL,
  side               VARCHAR NOT NULL,       -- buy | sell
  quantity           INTEGER NOT NULL,
  order_type         VARCHAR NOT NULL,       -- market_open（v1 增加 limit）
  status             VARCHAR NOT NULL,       -- pending | filled | rejected | cancelled
  reject_code        VARCHAR,                -- 见 08 第 4 节的拒单原因码
  reject_message     VARCHAR,
  created_clock_date DATE NOT NULL,          -- 下单时账户的模拟日期
  estimate_price     DECIMAL(18,6),          -- 下单时的估算价 = 收盘价 × (1 + 滑点)
  reserved_cash      DECIMAL(18,4),          -- 买单冻结的资金，成交/取消/拒绝后清空
  idempotency_key    VARCHAR NOT NULL UNIQUE,
  request_hash       VARCHAR NOT NULL,       -- 其余下单参数的摘要，用于识别"同键不同参数"
  created_at         TIMESTAMP NOT NULL,
  updated_at         TIMESTAMP NOT NULL
);
CREATE INDEX idx_paper_order_account ON paper_order (account_id, status, created_at);

CREATE TABLE fill (
  fill_id      VARCHAR PRIMARY KEY,
  order_id     VARCHAR NOT NULL,
  filled_on    DATE NOT NULL,
  price        DECIMAL(18,6) NOT NULL,       -- 开盘价 × (1 ± 滑点)
  quantity     INTEGER NOT NULL,
  amount       DECIMAL(18,4) NOT NULL,       -- price × quantity
  fee          DECIMAL(18,4) NOT NULL,
  slippage_bps DOUBLE NOT NULL,
  created_at   TIMESTAMP NOT NULL
);

CREATE TABLE position (
  account_id    VARCHAR NOT NULL,
  instrument_id VARCHAR NOT NULL,
  quantity      INTEGER NOT NULL,            -- 清仓后保留 0，界面隐藏
  avg_cost      DECIMAL(18,6) NOT NULL,      -- 含买入费用的加权平均成本
  updated_at    TIMESTAMP NOT NULL,
  PRIMARY KEY (account_id, instrument_id)
);

-- 每个模拟日收盘后的权益快照，用于权益曲线（v1）和一致性检查。
CREATE TABLE equity_snapshot (
  account_id      VARCHAR NOT NULL,
  snapshot_date   DATE NOT NULL,
  cash            DECIMAL(18,4) NOT NULL,
  positions_value DECIMAL(18,4) NOT NULL,
  equity          DECIMAL(18,4) NOT NULL,
  PRIMARY KEY (account_id, snapshot_date)
);
```

### 3.11 `011_risk.sql` · P-06

## 4. 确定性标识与哈希

所有哈希用 SHA-256，输入是 UTF-8 字节，输出小写十六进制。文本在计算前做同一种规范化 `norm()`：`unicodedata.normalize("NFC", s)`，`\r\n` 和 `\r` 统一为 `\n`，**首尾**空白去掉，内部空白保持原样。

| 名称 | 公式 | 长度 |
|---|---|---|
| 逻辑版本 `content_hash` | `sha256(norm(statement) + "\n---\n" + norm(kill_condition or ""))` | 64 |
| 段落 `content_hash` | `sha256(norm(passage_text))` | 64 |
| `passage_id` | `sha256(f"{event_id}\|{file_seq}\|{start_offset}\|{end_offset}")` 的前 32 位 | 32 |
| 判定 `cache_key` | `sha256(f"{engine}\|{model_id}\|{question_set_version}\|{thesis_content_hash}\|{passage_content_hash}")` | 64 |
| 订单 `request_hash` | `sha256(f"{account_id}\|{instrument_id}\|{side}\|{quantity}\|{order_type}")` | 64 |

注意：`cache_key` 里的 `model_id` 是**响应里返回的** `model` 字段（实际应答的版本），不是配置里的别名。引擎不同则缓存分开，保证评测按引擎独立。

## 8. 核心查询（参考实现）

下面的 SQL 是行为的权威定义；仓储层可以改写成参数化形式，但结果必须一致。`:name` 是命名参数，**一律用参数绑定，禁止字符串拼接**。

### 8.1 待处理清单（`inbox.list` 的数据来源）

清单的一条 = 一个（逻辑，披露）对里最有代表性的判定：严重度最高（推翻 > 削弱 > 待确认），再按 `headline` 降序，再按段落序号升序。

```sql
WITH ranked AS (
  SELECT d.*,
         ROW_NUMBER() OVER (
           PARTITION BY d.thesis_id, d.event_id
           ORDER BY CASE d.relation WHEN 'overturn' THEN 0 WHEN 'weaken' THEN 1 ELSE 2 END,
                    d.headline DESC, p.seq ASC
         ) AS rk
  FROM decision d
  JOIN event_passage p ON p.passage_id = d.passage_id
  JOIN thesis t ON t.thesis_id = d.thesis_id AND t.status = 'active'
  WHERE d.relation IN ('overturn', 'weaken', 'uncertain')
)
SELECT r.*, la.action AS last_action, la.note AS action_note, la.acted_at
FROM ranked r
LEFT JOIN v_last_action la ON la.decision_id = r.decision_id
WHERE r.rk = 1;
```

分组规则（在 Python 里做）：`last_action` 为空或为 `reopen` → 待处理；否则 → 已处理。待处理里 `relation` 为 `overturn`/`weaken` → `items`，为 `uncertain` → `uncertain`。已处理只取最近 30 天（按 `acted_at`）。排序：`items` 按严重度（推翻在前）再 `headline` 降序；`uncertain` 按 `headline` 降序；`processed` 按 `acted_at` 降序。

### 8.2 持仓列表（`holdings.list`）

```sql
SELECT h.*, i.symbol, i.name, i.name_zh, i.exchange, i.currency, i.is_active,
       lp.close AS last_close, lp.trade_date AS last_close_date,
       CASE WHEN lp.prev_close > 0 THEN lp.close / lp.prev_close - 1 END AS day_change_pct
FROM holding h
JOIN instrument i ON i.instrument_id = h.instrument_id
LEFT JOIN (
  SELECT instrument_id, trade_date, close,
         LAG(close) OVER (PARTITION BY instrument_id ORDER BY trade_date) AS prev_close,
         ROW_NUMBER() OVER (PARTITION BY instrument_id ORDER BY trade_date DESC) AS rn
  FROM price_daily
) lp ON lp.instrument_id = h.instrument_id AND lp.rn = 1
WHERE h.archived_at IS NULL
ORDER BY (h.quantity > 0) DESC, i.symbol;
```

市值 = `quantity × last_close`（`Decimal`，4 位小数，`ROUND_HALF_UP`），在 Python 里计算。`status`：该标的没有有效逻辑 → `unguarded`；有待处理的推翻/削弱 → `attention`；否则 `guarded`。

## 9. 数据质量规则

| 规则 | 处理 |
|---|---|
| 同一标的同一日期重复行情 | `fetched_at` 最新的胜出（`INSERT ... ON CONFLICT DO UPDATE` 更新非主键列），并写一条 `debug` 日志 |
| OHLC 关系非法（`high < low`、`open`/`close` 超出 `[low, high]`） | 丢弃该行，写 `warn` 日志，计入 `prices.refresh` 的 `failed` 说明 |
| 价格 ≤ 0 或为 NaN | 丢弃并告警 |
| 披露发布时间缺失 | 用 `filing_date` 当天 00:00（美东）转 UTC，并在 `title` 末尾不做任何标记；该行的 `published_at` 以后不会被修正（SEC 几乎总是提供，缺失视为异常，写 `warn`） |
| 披露发布时间晚于抓取时间 | 以抓取时间截断，防止“未来信息” |
| 披露正文抓取失败 | `event_doc.content_status = 'fetch_failed'`，该批在下次扫描自动重试；已有的标题段落仍可判定，界面标注“仅依据标题” |
| 段落超过上限 | 每份披露最多保留 60 个段落（06 第 9 节），多出的丢弃并在 `event_file.text_status` 之外记 `warn`；界面标注“仅分析前 60 段” |
