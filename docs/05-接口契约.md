# 05 接口契约

> 版本：v2.0 · 2026-11-02 · 状态：已定稿 · 协议版本 `1.0`
> 前端（React）与核心进程（Python）之间唯一的通信契约。**机器可读的权威版本在 `contracts/`**（第 11 节）；本文是它的说明书，两者不一致时以 `contracts/` 为准，并立刻提变更申请修正本文。

## 1. 传输

- 通道：Tauri 主进程与核心进程的 stdin / stdout，细节见 [02](02-技术架构.md) 第 6 节。
- 编码：UTF-8，**每行一个 JSON 对象**（NDJSON），不允许换行美化；行尾只用 `\n`。
- 单行上限 1 MB（UTF-8 字节数）。超限的请求，核心进程返回 `INVALID_ARGUMENT`。
- 日志只写 stderr 与日志文件，**禁止**污染 stdout。
- 二进制内容（导出文件）不经过 RPC：由 Tauri 文件对话框选路径，核心进程只写那个路径（v1）。

## 2. 消息格式

JSON-RPC 2.0 的子集：**不支持批量请求**；`id` 必须是字符串（≤ 64 字符，同一连接内唯一）。

请求：

```json
{"jsonrpc":"2.0","id":"r-17-k3j9","method":"thesis.create","params":{"instrumentId":"us:ZZEN","statement":"…"}}
```

成功响应：

```json
{"jsonrpc":"2.0","id":"r-17-k3j9","result":{ }}
```

错误响应（`code` 是字符串，不是 JSON-RPC 的数字）：

```json
{"jsonrpc":"2.0","id":"r-17-k3j9","error":{"code":"INVALID_ARGUMENT","message":"逻辑内容不能为空","data":{"retryable":false,"field":"statement"}}}
```

通知（无 `id`，核心进程 → 前端）：

```json
{"jsonrpc":"2.0","method":"scan.progress","params":{"runId":"…","market":"us","stage":"decide","done":9,"total":17,"message":"正在判定 ZZCL 的 6-K"}}
```

取消（前端 → 核心进程，无响应）：

```json
{"jsonrpc":"2.0","method":"$/cancel","params":{"id":"r-17-k3j9"}}
```

规则：

1. 核心进程在收到 `$/cancel` 后**立即**（≤ 200 ms）对该请求返回 `CANCELLED` 错误，并丢弃之后到达的结果。取消一个已经完成的请求是空操作。
2. 未知方法：返回 `INVALID_ARGUMENT`，`data.reason = "UNKNOWN_METHOD"`。参数不符合 schema：返回 `INVALID_ARGUMENT`，`data.field` 指向第一个出错的字段（点号路径，如 `"killCondition"`）。
3. 一个请求**恰好得到一个响应**。核心进程不得对同一个 `id` 响应两次。
4. 通知没有响应，也没有送达保证；前端不得依赖通知来保证正确性，通知只用来更快地刷新（刷新用的是对应的查询方法）。

## 3. 错误

### 3.1 错误对象

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 第 3.2 节的 15 个取值之一 |
| `message` | string | **可直接展示给用户的简体中文**，写“发生了什么 + 你能做什么”。文案集中在 `core/sentinel/messages/` |
| `data.retryable` | boolean | 必有。是否值得自动或手动重试 |
| `data.field` | string | 可选。参数校验错误时指向字段 |
| `data.reason` | string | 可选。同一个 `code` 下的细分原因，取值见各方法与 [08](08-模拟交易与风险.md) |
| `data.requestId` | string | `INTERNAL` 时必有，与日志里的 `request_id` 对应，界面显示为“错误编号” |
| `data.detail` | string | 可选。英文技术细节，**界面默认不显示**，只在“复制错误详情”里出现 |

### 3.2 错误码

| code | 场景 | retryable | 前端处理 |
|---|---|---|---|
| `INVALID_ARGUMENT` | 参数校验失败；未知方法 | 否 | 字段级提示 |
| `NOT_FOUND` | 标的、记录不存在 | 否 | 空状态或提示 |
| `CONFLICT` | 乐观锁冲突；扫描已在进行；同一幂等键参数不同 | 否 | 提示刷新后重试 |
| `CONFIG_REQUIRED` | 缺少 Jev 密钥或 SEC 联系邮箱 | 否 | 引导到设置页，`data.missing` 列出缺什么（`jevKey`、`secEmail`） |
| `UNAUTHENTICATED` | Jev 返回 401（密钥无效） | 否 | 引导到设置页重新填写密钥 |
| `ENGINE_UNAVAILABLE` | 指定的引擎不可用且不允许降级（例如设置为 `jevdb` 但扩展加载失败） | 否 | 提示切换到 `auto` 或 `jev_direct` |
| `SOURCE_UNAVAILABLE` | SEC 或行情源不可用、离线 | 是 | 显示失败原因与“数据截至”，提供重试 |
| `RATE_LIMITED` | 来源返回 429 | 是 | 显示冷却时间（`data.retryAfterSec`） |
| `MODEL_ERROR` | Jev 返回 5xx / 529，或结果不完整 | 是 | 该批标 `failed`，稍后自动重试 |
| `BUDGET_EXCEEDED` | 今日 token 预算用完 | 否 | 提示用量与重置时刻；剩余批次挂起 |
| `DATA_INSUFFICIENT` | 风险样本不足、没有目标日行情 | 否 | 说明原因，不出数 |
| `ORDER_REJECTED` | 模拟订单校验失败 | 否 | 展示拒单原因；`data.orderId` 指向已保存的 `rejected` 订单 |
| `TIMEOUT` | 超时 | 是 | 提供重试 |
| `CANCELLED` | 用户取消 | — | 静默 |
| `INTERNAL` | 未预期的错误 | 是 | 显示错误编号与“复制错误详情” |

### 3.3 外部错误到错误码的映射

| 来源 | 情形 | 错误码 |
|---|---|---|
| Jev（官方 SDK 或 JEVDB） | HTTP 401 | `UNAUTHENTICATED` |
| | HTTP 429 | `RATE_LIMITED`（`retryAfterSec` 取响应头 `retry-after`） |
| | HTTP 5xx、529、连接失败、结果缺失或无法解析 | `MODEL_ERROR` |
| | 读写超时 | `TIMEOUT` |
| | HTTP 400 / 413 / 422 | `INTERNAL`（我们发了不合法的请求，是缺陷）；`data.detail` 带上服务端说明。例外：400 且说明为上下文超限时，把该段落的逻辑数减半后重试一次，仍失败再 `INTERNAL` |
| SEC | HTTP 429 | `RATE_LIMITED` |
| | HTTP 403 | `SOURCE_UNAVAILABLE`，`data.reason = "SEC_FORBIDDEN"`，文案提示检查联系邮箱 |
| | HTTP 5xx、连接失败、DNS 失败 | `SOURCE_UNAVAILABLE` |
| | 超时 | `TIMEOUT` |
| 行情源 | 同上 | 同上 |
| 离线模式（`SENTINEL_OFFLINE=1`） | 任何外联 | `SOURCE_UNAVAILABLE`，`data.reason = "OFFLINE"` |

## 4. 公共类型

下面是 TypeScript 写法的**说明性**定义；权威来源是 `contracts/types.schema.json`（第 11 节），前端类型由脚本从它生成。`Decimal` 是十进制字符串（金额与成交价，见 [00](00-术语与约定.md) 第 4 节）；`IsoTime` 是以 `Z` 结尾的 UTC 时间；`IsoDate` 是 `YYYY-MM-DD`。

```ts
type Decimal = string;          // 金额 4 位小数 "1234.5600"；成交价 6 位小数 "187.250000"
type IsoTime = string;          // "2026-11-02T00:31:12Z"
type IsoDate = string;          // "2026-10-30"
type Market = "us" | "cn" | "hk";   // MVP-0 只会出现 "us"
type Relation = "none" | "support" | "weaken" | "overturn" | "uncertain";
type Engine = "jevdb" | "jev_direct";
type EngineChoice = "auto" | Engine;
type ActionType = "still_valid" | "revise" | "exit_intent" | "ignore";

interface Instrument {
  instrumentId: string;           // "us:ZZAR"
  market: Market;
  symbol: string;
  name: string;                   // 英文名
  nameZh: string | null;
  exchange: string;               // "NASDAQ" | "NYSE" | …
  currency: "USD" | "CNY" | "HKD";
  isActive: boolean;
}

interface Holding {
  holdingId: string;
  instrument: Instrument;
  quantity: Decimal;              // "0.0000" 表示只关注
  avgCost: Decimal | null;
  note: string | null;
  lastClose: number | null;       // 行情价格是 number
  lastCloseDate: IsoDate | null;
  dayChangePct: number | null;    // 0.012 = +1.2%
  marketValue: Decimal | null;    // quantity × lastClose
  thesisCount: number;            // 有效逻辑数
  pendingCount: number;           // 待处理的推翻 + 削弱条数
  uncertainCount: number;
  status: "guarded" | "attention" | "unguarded";
}

interface Thesis {
  thesisId: string;
  instrumentId: string;
  version: number;
  versionCount: number;
  statement: string;              // 1..500 字
  killCondition: string | null;   // ≤ 300 字
  status: "active" | "archived";
  createdAt: IsoTime;
  updatedAt: IsoTime;
  lastDecision: { decisionId: string; relation: Relation; headline: number;
                  createdAt: IsoTime; eventTitle: string } | null;
}

interface ThesisVersionItem {
  version: number; statement: string; killCondition: string | null; createdAt: IsoTime;
}

interface Probabilities {
  relevant: number; against: number; contradicts: number;
  killMet: number | null;         // 没有失效条件时为 null
  supports: number;
}

interface EventRef {
  eventId: string;                // "us:0009990001-26-000001"
  instrumentId: string;
  title: string;
  formType: "8-K" | "8-K/A" | "6-K";
  publishedAt: IsoTime;
  url: string;                    // https
}

interface Evidence {
  kind: "sentence" | "passage" | "title";
  text: string;                   // kind=sentence：那一句；passage：整段；title：标题
  passageText: string;            // 完整段落（抽屉里高亮用）
  sentenceStart: number | null;   // 在 passageText 里的起止字符偏移
  sentenceEnd: number | null;
  filePart: string;               // "主文档" | "EX-99.1" | "标题"
}

interface ActionRecord { action: ActionType | "reopen"; note: string | null; actedAt: IsoTime; }

interface DecisionSummary {
  decisionId: string;
  thesisId: string;
  thesisVersion: number;          // 判定时的版本
  thesisCurrentVersion: number;   // 现在的版本；大于 thesisVersion 时界面显示"逻辑已更新"
  instrument: Instrument;
  thesisStatement: string;        // 判定时版本的文字（快照）
  killCondition: string | null;
  relation: Relation;
  headline: number;               // max(against, contradicts, killMet ?? 0)，界面显示的"概率"
  probabilities: Probabilities;
  engine: Engine;
  modelId: string;
  questionSetVersion: string;
  event: EventRef;
  evidence: Evidence;
  contentStatus: "full_text" | "title_only";
  createdAt: IsoTime;
  action: ActionRecord | null;    // 最新处理；null 或 reopen 表示待处理
}

interface DecisionDetail extends DecisionSummary {
  actions: ActionRecord[];        // 处理历史，新的在前
  thesisIsLatest: boolean;
}

interface DataStatus {
  market: Market;
  marketState: "open" | "pre" | "after" | "closed" | "holiday";
  nextOpenAt: IsoTime | null;
  source: { name: string; state: "ok" | "degraded" | "down"; lastSuccessAt: IsoTime | null; message: string | null };
  engine: { active: Engine | null; modelId: string; state: "ok" | "degraded" | "unconfigured" };
  budget: { usedTokens: number; limitTokens: number; resetAt: IsoTime };
  offline: boolean;
}

interface Inbox {
  asOf: IsoTime;
  summary: { pendingCount: number; overturnCount: number; weakenCount: number;
             uncertainCount: number; processedCount: number };
  items: DecisionSummary[];       // 待处理的推翻 + 削弱
  uncertain: DecisionSummary[];   // 待处理的待确认
  processed: DecisionSummary[];   // 最近 30 天已处理
  lastScan: { runId: string; status: ScanStatus; finishedAt: IsoTime | null;
              stats: { instruments: number; skippedNoThesis: number; filings: number;
                       passages: number; decisions: number };
              error: { code: string; message: string } | null } | null;
  dataStatus: DataStatus;
  setup: { holdings: number; activeTheses: number; scannableInstruments: number };
}

type ScanStatus = "queued" | "running" | "succeeded" | "partial" | "failed" | "cancelled" | "interrupted";

interface ScanRun {
  runId: string; trigger: "manual" | "schedule"; market: Market; status: ScanStatus;
  windowStart: IsoTime; windowEnd: IsoTime;
  stats: { instruments: number; skippedNoThesis: number; filings: number; passages: number;
           decisions: number; cachedDecisions: number; requests: number; inputTokens: number;
           estCostUsd: Decimal; durationMs: number };
  engine: Engine; modelId: string;
  startedAt: IsoTime | null; finishedAt: IsoTime | null;
  error: { code: string; message: string } | null;
  batchSummary: { total: number; succeeded: number; failed: number; pending: number };
}

interface ScanBatch {
  batchId: string; runId: string; instrumentId: string; eventId: string; eventTitle: string;
  status: "pending" | "succeeded" | "failed" | "cancelled"; attempts: number;
  error: { code: string; message: string } | null;
  passages: number; decisions: number; inputTokens: number;
}

interface PaperAccount {
  accountId: string; name: string; baseCurrency: "USD"; initialCash: Decimal;
  startDate: IsoDate; clockDate: IsoDate; createdAt: IsoTime;
}

interface Fill { fillId: string; filledOn: IsoDate; price: Decimal; quantity: number; amount: Decimal; fee: Decimal; }

interface PaperOrder {
  orderId: string; accountId: string; instrument: Instrument;
  side: "buy" | "sell"; quantity: number; orderType: "market_open";
  status: "pending" | "filled" | "rejected" | "cancelled";
  rejectReason: { code: string; message: string } | null;
  createdClockDate: IsoDate; reservedCash: Decimal | null; idempotencyKey: string;
  fills: Fill[];
  estimate: { price: Decimal; amount: Decimal; fee: Decimal } | null;
}

interface Position {
  instrument: Instrument; quantity: number; sellableQuantity: number; avgCost: Decimal;
  lastClose: number; marketValue: Decimal; unrealizedPnl: Decimal; unrealizedPnlPct: number;
}

interface Portfolio {
  account: PaperAccount; cash: Decimal; reservedCash: Decimal; availableCash: Decimal;
  positions: Position[]; equity: Decimal; asOf: IsoDate; pendingOrders: number;
}

interface RiskResult {
  asOf: IsoDate;
  window: { label: "6M" | "1Y" | "3Y"; from: IsoDate; to: IsoDate; observations: number };
  currency: "USD";
  annualizedVol: number;          // 0.187 = 18.7%
  maxDrawdown: number;            // 非负，0.214 = 21.4% 的最大回撤
  effectiveHoldings: number;      // 1 / Σw²
  topWeights: { instrumentId: string; symbol: string; weight: number }[];   // 前 3
  correlation: { instrumentIds: string[]; symbols: string[]; matrix: (number | null)[][] };
  svd: { explained: number[]; loadings: { symbol: string; value: number }[] };  // 前 5 个主成分；第一主成分载荷前 5
  conditionNumberRaw: number | null;
  conditionNumberShrunk: number | null;
  warnings: string[];
  excluded: { instrumentId: string; symbol: string; reason: string }[];
}

interface Settings {
  engine: EngineChoice; modelId: string; secContactEmail: string | null;
  dailyTokenBudget: number; firstScanLookbackDays: number; demoDataLoaded: boolean;
  language: "zh-CN";
  allowedDomains: { domain: string; purpose: string; sends: string }[];   // 只读
}

interface Bootstrap {
  protocolVersion: string; appVersion: string; dbSchemaVersion: number;
  platform: "macos" | "windows";
  engine: { requested: EngineChoice; active: Engine | null; modelId: string; jevdbAvailable: boolean };
  markets: Market[];
  configured: { jevKey: boolean; secEmail: boolean };
  demoDataLoaded: boolean; offline: boolean; now: IsoTime;
}
```

## 5. 方法清单

每个方法在 `contracts/methods/<方法名>.json` 里有完整的 schema 和示例。“负责”列是实现该方法的工作包。分页：带 `cursor` 的列表，`cursor` 是不透明字符串，传上一页返回的 `nextCursor`；`limit` 默认 50、最大 200；没有更多时 `nextCursor` 为 `null`。

### 5.1 生命周期（3）

| 方法 | 参数 | 返回 | 超时 | 负责 |
|---|---|---|---|---|
| `app.ping` | — | `{ ok: true, uptimeMs }` | 2 s | C-01 |
| `app.bootstrap` | — | `Bootstrap` | 30 s | C-04 |
| `app.shutdown` | `{ force?: boolean }` | `{ ok: true }` | 5 s | C-01 |

`app.ping` 由 reader 线程直接应答，不进线程池（[02](02-技术架构.md) 7.1）。

### 5.2 设置与密钥（6）

| 方法 | 参数 | 返回 | 错误 | 负责 |
|---|---|---|---|---|
| `settings.get` | — | `Settings` | — | C-04 |
| `settings.update` | `{ engine?, secContactEmail?, dailyTokenBudget?, firstScanLookbackDays? }` | `Settings` | `INVALID_ARGUMENT` | C-04 |
| `settings.testConnection` | — | `{ ok, engine, modelId, checks: { name, ok, latencyMs, message }[] }` | `CONFIG_REQUIRED` | C-04 |
| `secrets.set` | `{ name: "jevKey", value }` | `{ ok: true }` | `INVALID_ARGUMENT` | C-04 |
| `secrets.clear` | `{ name: "jevKey" }` | `{ ok: true }` | — | C-04 |
| `secrets.status` | — | `{ jevKey: boolean }` | — | C-04 |

密钥只允许单向写入：任何读取接口都不得返回明文。`secrets.set` 的 `value` 去首尾空白后必须非空、≤ 512 字符、不含空白或换行。`settings.testConnection` 的 `checks` 固定三项：`Jev`、`SEC`、`JEVDB`；`JEVDB` 项失败不影响“日常运行可用”的 `ok`（只要 `Jev` 与 `SEC` 通过，且至少一个引擎可用），但它仍会阻断最终验收 M-8，不能据此把 `jev_direct` 当成 JEVDB 交付证据。

### 5.3 标的与持仓（5）

| 方法 | 参数 | 返回 | 错误 | 负责 |
|---|---|---|---|---|
| `instruments.search` | `{ query: string(1..64), limit?: 1..50 }` | `{ items: Instrument[] }` | `INVALID_ARGUMENT` | D-02 |
| `holdings.list` | — | `{ items: Holding[], asOf }` | — | P-01 |
| `holdings.upsert` | `{ instrumentId, quantity: Decimal ≥ 0, avgCost?: Decimal \| null, note?: string \| null }` | `Holding` | `INVALID_ARGUMENT` `NOT_FOUND` | P-01 |
| `holdings.archive` | `{ instrumentId }` | `{ ok: true }` | `NOT_FOUND` | P-01 |
| `prices.refresh` | `{ instrumentIds?: string[] }` | `{ updated, failed: { instrumentId, error }[], asOf }` | `SOURCE_UNAVAILABLE` `RATE_LIMITED` | D-04 |

`holdings.upsert` 对已归档的标的等于“重新添加”。`note` ≤ 200 字。`holdings.archive` 后，该标的不再参与扫描、不计入风险；它的逻辑、判定、处理记录保留。

### 5.4 投资逻辑（5）

| 方法 | 参数 | 返回 | 错误 | 负责 |
|---|---|---|---|---|
| `thesis.list` | `{ instrumentId?, status? }` | `{ items: Thesis[] }` | — | P-01 |
| `thesis.create` | `{ instrumentId, statement, killCondition? }` | `Thesis` | `INVALID_ARGUMENT` `NOT_FOUND` | P-01 |
| `thesis.update` | `{ thesisId, statement, killCondition?, expectedVersion }` | `Thesis` | `INVALID_ARGUMENT` `NOT_FOUND` `CONFLICT` | P-01 |
| `thesis.archive` | `{ thesisId }` | `{ ok: true }` | `NOT_FOUND` | P-01 |
| `thesis.versions` | `{ thesisId }` | `{ items: ThesisVersionItem[] }` | `NOT_FOUND` | P-01 |

校验（`INVALID_ARGUMENT`，`data.field` 指向字段）：`statement` 去首尾空白后 1–500 个 Unicode 码点；`killCondition` 去首尾空白后若非空则 ≤ 300，空串按 `null` 处理；同一标的已有 5 条有效逻辑时 `thesis.create` 拒绝（`data.field = "instrumentId"`，`data.max = 5`）。`thesis.update` 的内容与当前版本完全相同（规范化后）时不生成新版本，直接返回当前 `Thesis`。`expectedVersion` 与 `current_version` 不一致返回 `CONFLICT`，`data.currentVersion` 给出最新值。

### 5.5 清单与判定（4）

| 方法 | 参数 | 返回 | 错误 | 负责 |
|---|---|---|---|---|
| `inbox.list` | — | `Inbox` | — | P-03 |
| `decision.get` | `{ decisionId }` | `DecisionDetail` | `NOT_FOUND` | P-03 |
| `decision.act` | `{ decisionId, action: ActionType, note?: string }` | `DecisionSummary` | `INVALID_ARGUMENT` `NOT_FOUND` | P-03 |
| `decision.reopen` | `{ decisionId }` | `DecisionSummary` | `NOT_FOUND` | P-03 |

`decision.act` 只记录处理，**不产生任何副作用**：`revise` 不修改逻辑，`exit_intent` 不产生订单。对已经处理过的判定再次 `act` 是允许的（追加一条记录，以最新为准）。`inbox.list` 的查询与分组规则见 [04](04-数据模型.md) 8.1。

### 5.6 扫描（6）

| 方法 | 参数 | 返回 | 错误 | 负责 |
|---|---|---|---|---|
| `scan.start` | `{ market: "us", from?: IsoTime }` | `{ runId }` | `CONFIG_REQUIRED` `CONFLICT` `BUDGET_EXCEEDED` | P-02 |
| `scan.cancel` | `{ runId }` | `{ ok: true }` | `NOT_FOUND` | P-02 |
| `scan.status` | `{ runId }` | `ScanRun` | `NOT_FOUND` | P-02 |
| `scan.history` | `{ limit?, cursor? }` | `{ items: ScanRun[], nextCursor, budget }` | — | P-02 |
| `scan.detail` | `{ runId }` | `{ run: ScanRun, batches: ScanBatch[] }` | `NOT_FOUND` | P-02 |
| `scan.retryBatch` | `{ batchId }` | `ScanBatch` | `NOT_FOUND` `CONFIG_REQUIRED` `BUDGET_EXCEEDED` `MODEL_ERROR` `SOURCE_UNAVAILABLE` | P-02 |

`scan.start` **立即返回** `runId`，扫描在专用线程里异步进行，进度走通知。同一市场已有 `running` 的运行时返回 `CONFLICT`（文案“扫描正在进行”）。`from` 缺省时窗口从水位线开始，首次默认回看 `firstScanLookbackDays` 天；`from` 不得早于 30 天前（`INVALID_ARGUMENT`）。`scan.retryBatch` 同步执行（≤ 60 s），成功后更新批次、所属运行的统计和清单。

## 6. 通知（核心进程 → 前端）

| 通知 | 负载 | 触发 | 节流与顺序 |
|---|---|---|---|
| `app.ready` | `{ version, migrationsApplied }` | 核心进程启动完成 | 每次启动一次，总是第一条 |
| `scan.progress` | `{ runId, market, stage, done, total, message }` | 扫描过程中 | ≥ 500 ms 一条；`stage` ∈ `fetch` `parse` `decide` `evidence` `finish` |
| `scan.finished` | `ScanRun` | 一次运行进入终态 | 每次运行一条，总在该运行最后一条 `scan.progress` 之后 |
| `inbox.updated` | `{ newItems, pendingCount }` | 一个批次提交后产生了新的清单条目 | ≥ 1 s 一条；前端收到后调用 `inbox.list` 刷新 |
| `engine.changed` | `{ from, to, reason }` | 引擎降级或恢复 | 立即；界面显示一次可见提示 |
| `source.degraded` | `{ source, reason }` | 数据源熔断触发 | 立即 |
| `budget.updated` | `{ usedTokens, limitTokens, resetAt }` | 用量变化 | ≥ 2 s 一条 |

## 7. 状态机

### 7.1 `scan_run`

```text
queued ──► running ──► succeeded     全部批次成功
                  ├──► partial       至少一个批次成功，且另有批次失败、挂起（预算耗尽）或标的获取失败
                  ├──► failed        无任何可交付结果（获取披露列表失败、或全部批次失败）
                  ├──► cancelled     用户取消；已提交的批次保留
                  └──► interrupted   核心进程崩溃；下次启动时由 P-02 把遗留的 running 标为 interrupted
```

- `queued` 在 MVP-0 是瞬时状态（创建后立即 `running`）。
- 同一市场同一时刻最多一个 `running`。
- 终态不可再变。重试失败批次不改变已结束运行的状态，但会更新它的统计与 `batchSummary`；若重试使失败批次全部成功，运行状态从 `partial` 变为 `succeeded`（唯一允许的终态后变更）。

### 7.2 `scan_batch`

`pending → succeeded | failed | cancelled`。`failed` 可经 `scan.retryBatch` 回到 `succeeded`（`attempts` 递增）。下一次扫描会重新发现并重试仍未成功的（标的，披露）。

### 7.3 `paper_order`

```text
pending ──► filled
        ├──► rejected    （撮合时无开盘价满 5 个交易日；开盘价上涨导致资金不足）
        └──► cancelled   （用户取消）
（下单时校验失败：直接以 rejected 保存，不经过 pending）
```

### 7.4 清单条目（派生状态，不单独存储）

```text
待处理 ──decision.act──► 已处理 ──decision.reopen──► 待处理
```

最新一条 `thesis_action` 决定状态：无记录或 `reopen` → 待处理，其余 → 已处理（[04](04-数据模型.md) 8.1）。

### 7.5 引擎状态

`engine.state`：`ok`（可用）、`degraded`（`auto` 下 JEVDB 不可用、已使用 `jev_direct`，或最近有请求失败）、`unconfigured`（没有密钥）。

## 8. 并发与幂等

| 场景 | 机制 |
|---|---|
| 编辑逻辑 | `expectedVersion` 乐观锁；冲突返回 `CONFLICT` 并附最新版本 |
| 下模拟单 | `idempotencyKey`（前端对每次点击生成一个新的 UUID）；重复提交返回原订单 |
| 扫描 | 同市场单运行；披露按 `event_id` 去重；判定按 `cache_key` 去重；重复扫描天然幂等 |
| 前端轮询 | 禁止轮询。依赖通知触发刷新；通知可能丢失，所以页面获得焦点时和用户点“刷新”时都应主动调用查询 |
| 取消 | 见第 2 节规则 1 |

## 9. 版本与兼容

- `app.bootstrap.protocolVersion` 必须以 `1.` 开头；前端发现主版本不一致，显示“请更新应用”并停止调用。
- 向后兼容的变更：新增可选参数、新增结果字段、新增错误 `data` 字段、新增通知。不兼容的变更（删除字段、改语义、改枚举含义）必须升主版本。
- 前端必须忽略不认识的结果字段。核心进程必须拒绝不认识的参数字段（`INVALID_ARGUMENT`），以便尽早发现拼写错误。
- 数据库 `schema_version` 与协议版本相互独立。

## 11. `contracts/` 目录

```text
contracts/
  index.json                 { protocolVersion, methods: [...40 个方法名], notifications: [...7 个] }
  types.schema.json          { "$defs": { Instrument, Holding, … } }，第 4 节的 JSON Schema 版本
  errors.json                15 个错误码、retryable 默认值、reason 取值
  notifications.json         每个通知的 params schema 和示例
  methods/<方法名>.json      每个方法一个文件，格式见下
```

方法文件格式：

```json
{
  "method": "thesis.create",
  "summary": "为一个标的新建投资逻辑",
  "owner": "P-01",
  "phase": "mvp0",
  "timeoutMs": 30000,
  "params": { "type": "object", "required": ["instrumentId", "statement"], "properties": { }, "additionalProperties": false },
  "result": { "$ref": "types.schema.json#/$defs/Thesis" },
  "errors": ["INVALID_ARGUMENT", "NOT_FOUND"],
  "examples": [
    { "name": "ok",    "params": { }, "result": { } },
    { "name": "empty", "params": { }, "error": { "code": "INVALID_ARGUMENT", "message": "逻辑内容不能为空", "data": { "retryable": false, "field": "statement" } } }
  ]
}
```

规则：

1. `params` 的 `additionalProperties` 必须为 `false`；`result` 允许多余字段。
2. 每个示例都是一个**场景名**，原型（`design/prototype/data/mock.js`）、前端 mock（`apps/desktop/src/rpc/mock/`）、后端契约测试共用它们。示例名的约定见 [03](03-界面设计规范.md) 第 6 节。
3. `scripts/gen_proto_mock.py` 从 `contracts/` 生成 `mock.js`，`--check` 模式检查是否过期；`scripts/gen_ts_types.py`（C-05）生成前端类型，同样有 `--check`。
4. 契约测试（C-01 起每个方法的工作包都要写）：示例的 `params` 能被处理器的参数模型解析；示例的 `result` 能被结果模型解析并序列化回等价的 JSON；所有 `error.code` 都在 `errors.json` 里。
5. 修改 `contracts/` 只能通过变更申请。
