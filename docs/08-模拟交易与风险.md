# A 部分 · 模拟交易

## 1. 范围与原则

MVP-0 只做美股、美元、**只做多、整数股、无融资、无卖空、只有开盘市价单**。

| # | 原则 |
|---|---|
| 1 | **不用未来信息**（ADR-013）：撮合和估值只读 `trade_date <= clock_date`（撮合当天用 `clock_date` 推进后的新日期）的行情。这靠查询条件保证，不靠约定 |
| 2 | **单笔订单是原子单位**：每笔订单的校验与成交各自一个事务；一笔失败不影响其他订单 |
| 3 | **金额只用 `Decimal`**，现金由流水汇总得出，不单独存储余额（[04](04-数据模型.md) 3.10） |
| 4 | **拒单要有原因**，原因是中文、说清“差多少”，并保存订单以便在历史里看到 |
| 5 | **费率可配置且标注来源**：监管费率放 `resources/market_rules/us.toml`，带 `effective_from`、`source`、`verified`；未核实的显示“费率为占位值” |
| 6 | 所有时间用 `clock.now()`；日期用交易日历（[07](07-美股数据源.md) 第 7 节） |

## 2. 概念：回放时钟

每个模拟账户有一个 `clock_date`，表示“账户现在处于哪个模拟交易日”。

```text
clock_date = D（交易日）
  用户看到的是 D 及之前的行情（含 D 的收盘价）
  用户在 D 下的单，在下一个交易日 D' 的开盘价成交
paper.advance：把时钟从 D 推进到 D'
  1. 在 D' 的开盘价撮合所有 pending 订单（先卖后买）
  2. clock_date 变为 D'
  3. 用 D' 的收盘价估值，写 equity_snapshot
```

- 账户创建时 `clock_date = start_date`，`start_date` 必须是交易日。
- `clock_date` 不能超过“库里最新的行情日期”（推进到没有行情的日子会 `DATA_INSUFFICIENT`）。
- 行情必须先通过 `prices.refresh` 或演示数据存在。

## 4. 下单（`paper.order.place`）

### 4.1 校验顺序

按下表顺序，**第一个不满足的就是拒单原因**。通过第 1–5 步的参数错误返回 `INVALID_ARGUMENT`（不保存订单）；第 6 步起的业务拒绝返回 `ORDER_REJECTED` 且**保存**一个 `rejected` 订单。

| 步 | 检查 | 失败 |
|---|---|---|
| 1 | 账户存在且未归档 | `NOT_FOUND` |
| 2 | `idempotencyKey` 非空、≤ 64 字符。若该键已有订单：`request_hash` 相同 → **返回原订单**（不重复冻结、不重复保存）；不同 → `CONFLICT` | `INVALID_ARGUMENT` / `CONFLICT` |
| 3 | `instrumentId` 存在、`is_active`、市场为 `us` | `NOT_FOUND` |
| 4 | `side ∈ {buy, sell}`；`orderType == "market_open"`（其他值 `INVALID_ARGUMENT`，文案“暂不支持限价单”） | `INVALID_ARGUMENT` |
| 5 | `quantity` 是正整数且 ≤ `max_order_quantity`；账户的 `pending` 订单数 < `max_pending_orders` | `INVALID_ARGUMENT` |
| 6 | 存在 `clock_date` 的收盘价（`close > 0`）。没有 → 拒单 `NO_PRICE` | `ORDER_REJECTED` |
| 7 | 买单：可用现金 ≥ 预估所需（4.2）。不足 → `INSUFFICIENT_CASH` | `ORDER_REJECTED` |
| 8 | 卖单：持仓数量 − 其他 `pending` 卖单的数量之和 ≥ `quantity`。不足 → `INSUFFICIENT_POSITION` | `ORDER_REJECTED` |

### 4.2 预估与冻结

```python
close = price_daily.close 在 clock_date
estimate_price = round6(close * (1 + slippage_bps / 10000))       # 买入；卖出用 (1 - slippage)
estimate_amount = round4(estimate_price * quantity)
estimate_fee = fee(side, quantity, estimate_amount)                # 第 5 节
required = estimate_amount + estimate_fee                          # 仅买单
```

- 买单通过校验后，写 `cash_ledger`：`entry_type = 'reserve'`，`amount = -required`，并把 `paper_order.reserved_cash = required`。
- **不加安全余量**。开盘跳空使实际所需大于冻结额时，撮合阶段如实检查，不足则拒单（`INSUFFICIENT_CASH_AT_FILL`）。这符合真实券商的行为，界面在下单确认处提示“按开盘价成交，价格可能与预估不同”。
- 卖单不冻结资金，但持仓数量在校验第 8 步被占用（通过“其他 pending 卖单数量之和”体现，持仓表本身不改）。

### 4.3 拒单原因

`ORDER_REJECTED` 的 `data.reason` 与中文文案（`{…}` 为填入的值，金额写 `$` 加千分位和 2 位小数）：

| `reason` | 出现时机 | 文案 |
|---|---|---|
| `NO_PRICE` | 下单时无 `clock_date` 收盘价 | 没有 {日期} 的收盘价，无法估算所需资金。请先刷新行情。 |
| `INSUFFICIENT_CASH` | 下单时资金不足 | 资金不足：预计需要 ${required}，可用现金 ${available}。 |
| `INSUFFICIENT_POSITION` | 下单时可卖数量不足 | 可卖数量不足：持仓 {held} 股，要卖出 {requested} 股。 |
| `NO_PRICE_AT_FILL` | 撮合时连续 `max_wait_trading_days` 个交易日没有开盘价 | 连续 {n} 个交易日没有行情，订单已取消。 |
| `INSUFFICIENT_CASH_AT_FILL` | 撮合时开盘价上涨，实际所需大于可用资金 | 开盘价高于预估，资金不足：需要 ${required}，可用 ${available}。 |
| `INSUFFICIENT_POSITION_AT_FILL` | 撮合时持仓不足（理论上不会发生，作为防御） | 成交时持仓不足，订单已取消。 |

## 5. 撮合与费用

### 5.1 `paper.advance` 算法

```text
输入: account
1. next_day = next_trading_day(account.clock_date)
   若 next_day > 库里该账户涉及标的的最新行情日期（或没有任何行情）→ DATA_INSUFFICIENT
        文案: 没有 {next_day} 的行情。请先刷新行情，或选择更早的回放日期。
2. 取所有 pending 订单，排序: 卖单在前，再按 created_at、order_id 升序
3. 开启一个事务，处理本次推进的全部订单:
   a. open = price_daily.open 在 next_day；缺失或 <= 0 →
        若 (订单已等待的交易日数 + 1) >= max_wait_trading_days → 拒单 NO_PRICE_AT_FILL，释放冻结
        否则保持 pending，继续
   b. 成交价  price = round6(open * (1 + slip))  买；round6(open * (1 - slip))  卖
      金额    amount = round4(price * quantity)
      费用    fee = fees(side, quantity, amount)
   c. 买单: 先 release 冻结 (+reserved_cash 流水)，再检查可用现金 >= amount + fee，
        不足 → 拒单 INSUFFICIENT_CASH_AT_FILL（冻结已释放）
        足够 → 写流水 buy(-amount)、fee(-fee)；position 增加；avg_cost 见 5.3
      卖单: 检查持仓 >= quantity，不足 → 拒单 INSUFFICIENT_POSITION_AT_FILL
        足够 → 写流水 sell(+amount)、fee(-fee)；position 减少，avg_cost 不变
   d. 写 fill；订单状态 filled
4. 同一事务内继续: clock_date = next_day；写 equity_snapshot(next_day)
   估值 = 现金 + Σ(持仓数量 × next_day 的 close)；缺 close 的标的用其最近一个 close 并 warn
5. 提交事务，返回 { clockDate, tradingDay: true, filled, rejected, pendingRemaining, portfolio }
```

- 一次 `advance` 的所有成交、正常拒单、资金、持仓、时钟与快照在**同一个事务**提交。业务拒单是正常结果；程序异常、数据库错误或进程中断会使整次推进回滚，绝不会出现“D+1 已成交、时钟仍为 D”。
- “订单已等待的交易日数”：从 `created_clock_date` 的下一个交易日起数，每次 `advance` 时无价则 +1；P-05 不单独存这个计数，用 `trading_days_between(created_clock_date, next_day)` 计算。
- 重新 `advance` 时，已成交订单已不是 `pending`，不会重复成交；由于时钟与成交同事务，进程中断后要么回到 D，要么完整到 D+1。

### 5.2 费用函数

```python
def fees(side, quantity, amount, cfg) -> FeeBreakdown:
    commission = max(cfg.commission_min, round2(quantity * cfg.commission_per_share))
    if cfg.commission_max_pct > 0:
        commission = min(commission, round2(amount * cfg.commission_max_pct / 100))
    if side == "buy":
        return FeeBreakdown(commission=commission, sec=0, taf=0)
    sec = ceil2(amount / 1_000_000 * cfg.sec_fee.usd_per_million)       # 向上取整到分
    taf = min(cfg.finra_taf.max_per_trade, ceil2(quantity * cfg.finra_taf.usd_per_share))
    return FeeBreakdown(commission=commission, sec=sec, taf=taf)        # 总和 = commission + sec + taf，2 位小数
```

- `round2`/`round4`/`round6`：`ROUND_HALF_UP`；`ceil2`：`ROUND_UP`（向上取整到 0.01）。
- `max_per_trade = 0` 且 `usd_per_share > 0` 视为配置错误，启动时抛 `INTERNAL`。

**测试专用费率**（只用于下面的样例和单元测试，**不是真实费率**，不得写进 `us.toml`）：

```text

commission_per_share = 0.005,  commission_min = 1.00,  commission_max_pct = 0
sec_fee.usd_per_million = 27.80
finra_taf.usd_per_share = 0.000166,  max_per_trade = 8.30
```

下列每一行都是一个单元测试。

| # | 操作 | 成交价 | 成交金额 | 佣金 | SEC | TAF | 费用合计 | 现金变化 |
|---|---|---|---|---|---|---|---|---|
| A | 买 100，开盘 51.10 | 51.125550 | 5112.5550 | 1.00 | 0.00 | 0.00 | 1.00 | −5113.5550 |
| B | 卖 100，开盘 51.10 | 51.074450 | 5107.4450 | 1.00 | 0.15 | 0.02 | 1.17 | +5106.2750 |
| C | 买 1000，开盘 28.55 | 28.564275 | 28564.2750 | 5.00 | 0.00 | 0.00 | 5.00 | −28569.2750 |
| D | 卖 5000，开盘 20.00 | 19.990000 | 99950.0000 | 25.00 | 2.78 | 0.83 | 28.61 | +99921.3900 |
| E | 卖 60000，开盘 10.00（触发 TAF 上限） | 9.995000 | 599700.0000 | 300.00 | 16.68 | 8.30 | 324.98 | +599375.0200 |

核对要点：B 的 SEC 费 = 5107.4450 ÷ 1,000,000 × 27.80 = 0.14198…，向上取整为 0.15；B 的 TAF = 100 × 0.000166 = 0.0166，向上取整为 0.02。E 的 TAF 原值 = 60000 × 0.000166 = 9.96，超过上限 8.30，取 8.30。

**平均成本（含买入费用）**：成本基数 = 数量 × 成交价 + 费用；加权平均 `avg = round6((原数量 × 原avg + 本次成交额 + 本次费用) / 新数量)`。

- 先买 100 股，成交价 49.900000，费用 1.00；再买 50 股，成交价 52.000000，费用 1.00：总成本 = 100×49.9 + 1 + 50×52 + 1 = 7592.00，`avg = 7592.00 / 150 = 50.613333`。
- 卖出不改变 `avg_cost`；清仓后 `quantity = 0` 保留该行。

**账本样例**（初始现金 10000.0000，使用上面的测试费率）：

1. 买 100 股，开盘 51.10 → 成交价 51.125550，金额 5112.5550，费用 1.00 → 现金 `10000 − 5112.5550 − 1.00 = 4886.4450`，持仓 100 股，`avg_cost = round6((5112.5550 + 1.00)/100) = 51.135550`。
2. 同账户后来卖 40 股，开盘 53.00 → 成交价 52.973500，金额 2118.9400，费用 1.07（佣金 1.00 + SEC 0.06 + TAF 0.01，拆分见下）→ 现金 `4886.4450 + 2118.9400 − 1.07 = 7004.3150`，持仓 60 股，`avg_cost` 仍为 51.135550。
3. 期末收盘价 54.00 → 权益 `7004.3150 + 60 × 54.00 = 10244.3150`。

（第 2 步的费用拆分：SEC = 2118.94 ÷ 1e6 × 27.80 = 0.0589…，向上取整 0.06；TAF = 40 × 0.000166 = 0.00664，向上取整 0.01；佣金 = max(1.00, 40×0.005=0.20) = 1.00；合计 1.00 + 0.06 + 0.01 = **1.07**。）

**冻结与成交的差额**：下单时收盘价 28.40 → 估算价 28.414200，100 股冻结 2841.4200（费用 0）。次日开盘 28.55，成交价 28.564275、金额 2856.4275。若佣金为 1.00，实际占用 2857.4275，比冻结多 16.0075。只要撮合时可用现金（释放冻结后）≥ 2857.4275 就成交。

### 5.4 订单取消

`paper.order.cancel`：只能取消 `pending`。事务内：状态改 `cancelled`，写 `release` 流水（`+reserved_cash`），清空 `reserved_cash`。其他状态返回 `CONFLICT`（文案“这笔订单已不能取消”）。

## 6. 余额、持仓、权益

| 量 | 公式 |
|---|---|
| 现金 | `SUM(amount) WHERE entry_type IN ('deposit','buy','sell','fee')` |
| 冻结资金 | `-SUM(amount) WHERE entry_type IN ('reserve','release')` |
| 可用现金 | 现金 − 冻结资金 |
| 持仓市值 | `Σ quantity × close(clock_date)`（缺 close 用最近一个 close） |
| 权益 | 现金 + 持仓市值（冻结资金仍属于现金，不单独扣） |
| 未实现盈亏 | `market_value − quantity × avg_cost`，百分比 = 盈亏 ÷ (`quantity × avg_cost`) |
| `sellableQuantity` | 美股无 T+1 限制，等于 `quantity`（字段为 v2 的 A 股保留） |

账户创建时写一条 `deposit` 流水（`+initial_cash`，`entry_date = start_date`）。`paper.reset`（需 `confirmText` 等于账户名）：自动备份后删除该账户的订单、成交、持仓、流水、快照，重新写入 `deposit`，`clock_date = start_date`。

## 7. 账本一致性（G3）

[04](04-数据模型.md) 第 7 节的完整性检查中与账本相关的 7 项在每次 `advance` 之后、每次测试结束时都要通过。另外有一个**随机序列测试**（P-05）：用固定种子生成 200 个随机订单序列（买、卖、取消、推进），每一步之后检查：现金 ≥ 0；持仓 ≥ 0；冻结资金 = pending 买单冻结额之和；权益 = 现金 + 市值；成交的 `amount` = `price × quantity`；`position.quantity` = 成交买入量 − 成交卖出量。

# B 部分 · 风险

## 8. 计算规则

位置：`core/sentinel/quant/`，**纯函数、只用 numpy、不读数据库**（便于测试）；P-06 的服务层负责取数。

### 8.1 输入

- `scope = "holdings"`：所有未归档且 `quantity > 0` 的持仓。`quantity = 0`（只关注）的标的不计入，列在 `excluded` 里。
- `window ∈ {"6M","1Y","3Y"}`，窗口年数依次为 0.5、1、3。窗口终点 = 所有参与标的**共同拥有的最新交易日**；起点 = 终点往前推窗口的日历长度。
- 价格：全部标的都有 `adj_close` 时用 `adj_close`，否则用 `close` 并加警告“价格未复权”。

### 8.2 步骤

记 `n` = 参与标的数，`T` = 收益率观测数。

1. **逐只收益**：对每只标的，按该市场交易日历取相邻交易日 `r_{i,t} = P_{i,t} / P_{i,t-1} − 1`；任一端点缺价，该日收益无效（不得跳过缺价日再压缩成“多日收益”）。
2. **有效日期交集**：取所有标的都拥有有效一日收益的日期，升序排列，共 `T` 个日期，得到 `T × n` 矩阵 `R`。
3. **样本门槛**：`T < 60` → 抛 `DATA_INSUFFICIENT`（`observations = T`，`required = 60`）。`n < 1` 同样不足。
4. **零方差标的**：保留在权重与协方差中，对应零行零列；不重算权重。相关系数对应格为 `null`；标准化 SVD 时该列不参与，但标的映射保留。
5. **权重**：`w_i = (quantity_i × 最新 close_i) / Σ`，最新 close 取窗口终点的收盘价（不复权）。
6. **协方差**：`X = R − 列均值`，`Σ = XᵀX / (T − 1)`（`ddof = 1`）。
7. **相关系数**：`ρ_ij = Σ_ij / sqrt(Σ_ii Σ_jj)`。`n = 1` 时矩阵为 `[[1]]`。
8. **年化波动率**：固定每年 `252` 个交易日，`σ = sqrt(252 × wᵀΣw)`。窗口标签只负责选择数据区间，不参与年化；3Y 只有 1Y 数据时仍按 252 年化，并在 `warnings` 中说明实际覆盖不足。
9. **最大回撤**：组合净值 `V_0 = 1`，`V_t = V_{t−1} × (1 + p_t)`，`peak_t = max(V_0..V_t)`，`maxDrawdown = max_t (peak_t − V_t) / peak_t`（非负）。使用**当前权重回看历史**（固定权重，不再平衡），界面注明。
10. **有效持仓数**：`1 / Σ w_i²`。
11. **前 3 大权重**：按 `w` 降序取 3 个。
12. **收缩与条件数**：`Σ_α = (1 − α)Σ + α · (tr(Σ)/n) · I`，`α = 0.1`。`conditionNumberRaw = λmax(Σ) / λmin(Σ)`，`conditionNumberShrunk` 同理用 `Σ_α`。特征值用 `numpy.linalg.eigvalsh`。`λmin ≤ 1e-12 × λmax`（奇异）→ 该条件数为 `null`，并加警告“协方差矩阵接近奇异”。
13. **SVD**：标准化收益 `Z_{t,i} = X_{t,i} / s_i`（`s_i` 为样本标准差，`ddof = 1`），`Z = U S Vᵀ`（`numpy.linalg.svd(Z, full_matrices=False)`）。解释方差占比 `explained_k = S_k² / Σ_j S_j²`，取前 `min(5, n)` 个。第一主成分载荷取 `V` 的第一列，符号归一化使**绝对值最大的元素为正**，按绝对值降序取前 5 个标的，输出 `{symbol, value}`。
14. **警告**：价格未复权；矩阵接近奇异；`n = 1`（相关系数与 SVD 无意义，界面显示“至少需要 2 只持仓”）；任一标的最新行情日期早于窗口终点 3 个交易日以上。

### 8.3 输出

`RiskResult`（[05](05-接口契约.md) 第 4 节）。`asOf` = 窗口终点。`window.from` = 第一个共同交易日；`window.observations` = `T`。

### 8.4 数值样例（手算可复核，期望值容差 1e-9）

构造一个 `n = 3`、`T = 4` 的小样本（测试里用参数 `min_observations=4` 绕过 60 的门槛）。收益率矩阵 `R`（行是日期，列是三个标的）：

| t | 标的 1 | 标的 2 | 标的 3 |
|---|---|---|---|
| 1 | +0.010 | +0.035 | +0.020 |
| 2 | −0.010 | +0.005 | −0.020 |
| 3 | +0.010 | −0.005 | −0.020 |
| 4 | −0.010 | −0.035 | +0.020 |

即三列分别是 `0.01·(1,−1,1,−1)`、`0.005·(7,1,−1,−7)`、`0.02·(1,−1,−1,1)`，每列均值都是 0。

**协方差** `Σ = XᵀX / 3`：

```text
Σ11 = 0.0004/3  = 1.3333333333e-4        Σ12 = 0.0002 = 2.0e-4        Σ13 = 0
Σ22 = 0.0025/3  = 8.3333333333e-4        Σ23 = 0
Σ33 = 0.0016/3  = 5.3333333333e-4
```

**相关系数**：`ρ12 = 0.6`，`ρ13 = ρ23 = 0`，对角线为 1。

**特征值**：Σ 的特征值 8.864462207e-4、5.333333333e-4、8.022044592e-5 → `conditionNumberRaw = 11.050128313`。

**收缩**（`α = 0.1`，`tr(Σ)/3 = 5.0e-4`）：`Σ_α` 的对角线 `1.7e-4, 8.0e-4, 5.3e-4`，`Σ_α,12 = 1.8e-4`；特征值 8.478015987e-4、5.3e-4、1.221984013e-4 → `conditionNumberShrunk = 6.937910721`。

**权重** `w = (0.5, 0.3, 0.2)`（测试直接给定，市值到权重的换算另有单测）：

- `wᵀΣw = 1.896666667e-4`；`A = 252`（测试直接给定 `periods_per_year`）→ `annualizedVol = sqrt(252 × 1.896666667e-4) = 0.2186229631`。
- 组合收益 `p = (0.0195, −0.0075, −0.0005, −0.0115)`；净值 `V = (1, 1.0195, 1.01185375, 1.0113478231, 0.9997173232)`；峰值 1.0195；`maxDrawdown = (1.0195 − 0.9997173232)/1.0195 = 0.0194042931`。
- `effectiveHoldings = 1 / (0.25 + 0.09 + 0.04) = 1 / 0.38 = 2.6315789474`。

**SVD**：标准化后的相关矩阵 `[[1, .6, 0], [.6, 1, 0], [0, 0, 1]]` 的特征值是 1.6、1.0、0.4，所以 `explained = (1.6/3, 1/3, 0.4/3) = (0.5333333333, 0.3333333333, 0.1333333333)`；第一主成分载荷 `(1/√2, 1/√2, 0) = (0.7071067812, 0.7071067812, 0)`（标的 3 的载荷为 0，输出时仍按绝对值降序，并列按标的顺序）。

价格序列怎么得到这些收益率：测试里直接传收益率矩阵给纯函数；服务层的“价格 → 收益率”另有单测（例：价格 `100, 101, 99.99, 100.9899, 99.980001`，收益率 `+0.01, −0.01, +0.01, −0.01`）。

### 8.5 边界

| 情形 | 行为 |
|---|---|
| 没有任何 `quantity > 0` 的持仓 | `DATA_INSUFFICIENT`，文案“没有可计算的持仓” |
| 只有 1 只持仓 | 返回波动率、回撤、有效持仓数；`correlation.matrix = [[1]]`；`svd.explained = [1]`；加警告 |
| 某标的价格缺失太多使共同交易日 < 60 | `DATA_INSUFFICIENT`，`data` 里给出观测数；文案指出是哪只标的拖累了样本（共同日最少的那只） |
| 所有价格相同 | 保留资产与权重；组合波动率为 0；相关性与标准化 SVD 返回 `null`/空并提示“资产无波动” |
| 价格含 NaN | 该日期对该标的视为缺失，参与第 1 步的丢弃 |
| `3Y` 窗口库里只有 1Y 数据 | 使用实际可得的一日收益，`window.label` 仍为 `3Y`，但 `window.from` 反映真实起点，年化仍用 252，并加警告“数据不足三年，实际 {起点} 起” |
