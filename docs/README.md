### 平台分工（详见 [ADR-016](decisions.md)）

| 车道 | 谁做 | 范围 |
|---|---|---|
| macOS 主线 | 团队主力 | 全部共享代码（`platform: shared`）+ macOS 专属代码（`platform: macos`）；MVP-0 验收以 macOS arm64 为准 |
| Windows | 一个人 | `platform: windows` 的工作包（ID 以 `W-` 开头）：Windows 开发模式对等、原生标题栏、凭据管理器、JEVDB 的 MSVC 构建尝试、NSIS 安装包、托盘与自启清理 |

三条规则让两条线互不拖累：Mac 工作包不得依赖 Windows 工作包；平台差异只放在平台层目录；Windows 发现共享代码的问题，只提交最小修复加复现测试，不改共享接口。

MVP-0 的验收标准分两档，详见 [01-产品需求.md](01-产品需求.md)：

- **必须**：主流程全部跑通（添加持仓和逻辑 → 手动扫描 → 看到带证据的待处理条目 → 处理 → 模拟下单 → 风险页出数），断网时仍能查看已有数据。
- **应该**：JEVDB 引擎可用；React 页面与原型的像素差异 ≤ 1%。

## 5. 一句话架构

Tauri 2 桌面外壳 + React / TypeScript 界面 + Python 3.12 本地核心进程（DuckDB、Jev、数值计算），两者通过 **stdio NDJSON JSON-RPC 2.0** 通信，不开本地端口。

## 6. 不可动摇的产品约束

1. **必须使用 Jev 模型**做语义判定。引擎有两种（JEVDB 扩展、官方 SDK 直连），用同一个固定的模型 ID，界面始终显示当前引擎。
2. **不给出买卖建议**，只报告事件与用户投资逻辑的关系。
3. **每条提醒必须能回到原文**；没有证据句的判定不进入清单。
4. 数据默认留在本机；Jev 密钥只存系统钥匙串，由 Python 进程读取。
5. **失败必须可见**：缓存数据、仅用标题、引擎降级、补扫、预算耗尽，界面上都要明确标注，不静默。
6. 美股先行，但接口和数据模型从一开始就按多市场设计（`market` 字段、`MarketAdapter` 协议）。

## 7. 变更规则

- 任何接口、数据表、页面结构、问题集的变更，必须在同一个 PR 里同步更新对应文档、`contracts/` 和原型，并通过 `python3 scripts/check_docs.py`。
- 实现中发现文档有错或做不到：**停下来**，在 `docs/wp/cr/` 新建 `CR-<日期>-<简述>.md`（模板见 [10-协作与工作包规范.md](10-协作与工作包规范.md)），由协调者批准后再改文档，然后才能改代码。
- ADR 只增不改：推翻旧决定要新增一条 ADR，并把旧条目标注“已被 ADR-xxx 取代”。

## 8. 检查命令

```bash
python3 scripts/check_docs.py             # 文档一致性：链接、锚点、文档名、状态、工作包依赖
python3 scripts/check_docs.py --strict    # 同上，并把"待重写"的文档当作错误
python3 scripts/check_proto.py            # 原型：样式约定 + 渲染全部状态做结构与无障碍检查（需要 node）
python3 scripts/check_contrast.py         # 设计令牌的对比度
python3 scripts/gen_wp_board.py --check   # 工作包看板是否与工作包文件、backlog.json 一致
python3 -m unittest discover -s scripts/tests -v    # 检查脚本自己的测试
```

脚本只用 Python 标准库，系统自带的 Python 3.9 即可运行（`check_proto.py` 另需要 `node`）。
