# 03 界面设计规范

> 版本：v2.0 · 2026-11-02 · 状态：已定稿
> 视觉方向：**Quiet Ledger（静默账簿）**——暖纸底色、墨色文字、一点朱红。像一本被认真维护的研究笔记，而不是行情终端。
> 实现方式：先在 `design/prototype/` 用纯 HTML / CSS 画出**可点击的原型**，React 页面输出与原型相同的 DOM 与类名，用截图比对验收（ADR-010）。
> **原型状态**：`design/prototype/` 已建成，含 7 个页面、43 个页面状态和今日页的 6 种证据抽屉（共 49 个画面，清单见第 6 节），文件结构与验收方法见第 9 节。它是 React 实现的基线。原型与本文冲突属于同级冲突，按 [README](README.md) 第 3 节停下来提变更申请；裁定后，文档与原型在同一个 PR 里一起改（README 第 7 节）。

## 1. 设计原则

1. **安静优先**：没有红绿闪烁、没有跑马灯、没有“紧急”角标。
2. **证据居中**：任何结论旁边都能看到原文；视觉层级依次是“发生了什么 → 和我的逻辑什么关系 → 原文”。
3. **数字要稳**：数值用等宽字体、右对齐、固定小数位，切换页面不跳动。
4. **克制的个性**：只有一种强调色（朱红），而且只用在“当前”和“焦点”上；卡片用细线而非重阴影；圆角小。
5. **明确的空**：没事发生时，用一句确定的话告诉用户“今天没有需要处理的变化”，而不是空白页。
6. **失败可见**：缓存数据、仅标题、整段证据、引擎降级、预算耗尽，都用文字标注，不只靠颜色。

## 2. 设计令牌

全部放在 `tokens.css` 的**第一个 `:root` 块**里（对比度检查脚本只读这个块）。禁止在其他 CSS 里写十六进制颜色（`scripts/check_proto.py` 与 ESLint 规则检查）。

### 2.1 颜色

```css

  --paper:        #FAF8F3;   /* 应用背景 */
  --surface:      #FFFFFF;   /* 卡片、表格 */
  --surface-2:    #F3F0E9;   /* 次级块、表头、骨架 */
  --ink:          #1A1C20;   /* 主文字、主按钮底色 */
  --ink-2:        #4A4D55;   /* 正文次级 */
```

对比度（WCAG 2.x；下表数字是 2026-11-02 用 `scripts/check_contrast.py` 实测的，该脚本是权威检查，完整 32 对见脚本的 `PAIRS`）：

| 前景 / 背景 | 比值 | 要求 |
|---|---|---|
| `--ink` / `--paper` | 16.07 | 4.5 |
| `--muted #64676F` / `--surface-2` | 4.97 | 4.5 |
| `--muted` / `--paper` | 5.33 | 4.5 |
| `--muted` / `--surface` | 5.66 | 4.5 |
| `--accent #C4472D` / `--surface` | 4.90 | 4.5 |
| `--accent #C4472D` / `--accent-soft` | **≈ 4.29（不达标，脚本未列入，仅为说明）** | 因此强调色**文字**一律用 `--accent-text`，`--accent` 只用于边、环、填充 |
| `--accent-text #A93A22` / `--accent-soft` | 5.55 | 4.5 |
| `--verdict-over` / `--verdict-over-bg` | 5.78 | 4.5 |
| `--verdict-weak` / `--verdict-weak-bg` | 4.73 | 4.5 |
| `--verdict-hold` / `--verdict-hold-bg` | 4.72 | 4.5 |
| `--verdict-unsure` / `--verdict-unsure-bg` | 6.06 | 4.5 |
| `--focus-ring` / `--paper` | 4.62 | 3（非文字组件） |

规则：

1. **旧稿的 `--muted #7A7D86` 废弃**（在白底只有约 4.1:1，低于它自己声明的 4.5:1）。
2. 主按钮是**墨色底白字**（`--ink` / `--on-ink`）。朱红不用于按钮底色，这样界面里的红色只剩三类含义：当前项、焦点、判定“推翻”。
3. 判定颜色同时配文字标签和形状，颜色不是唯一信息载体（第 8 节）。
4. 禁止：紫色渐变、玻璃拟态、彩色光晕、纯黑背景作为默认主题。

### 2.2 字体

```css
:root {
  --font-sans: "IBM Plex Sans", var(--font-cjk, "PingFang SC"), system-ui, sans-serif;
  --font-mono: "IBM Plex Mono", "SF Mono", "Cascadia Mono", ui-monospace, monospace;
}
```

- `--font-cjk` 由平台样式覆盖（`platform-macos.css`：`"PingFang SC"`；`platform-windows.css`：`"Microsoft YaHei UI"`）。
- 打包 IBM Plex Sans / Mono 的 Latin 子集（Regular 400、Medium 500、SemiBold 600），`woff2`，放在 `assets/fonts/`；中文用系统字体，控制体积。IBM Plex 以 SIL Open Font License 发布，`TODO-VERIFY(U-00)`：下载时核对许可证并写入 `THIRD_PARTY.md`。原型阶段字体文件缺失时回退到系统字体，**两边（原型与 React）必须使用相同的回退**，像素比对才可靠。
- 价格、涨跌幅、百分比、概率、日期时间、代码：`--font-mono` + `font-variant-numeric: tabular-nums`。
- 标题不用全大写英文；中文标题不加字距。

```css
:root {
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px; --space-4: 16px;
  --space-5: 24px; --space-6: 32px; --space-7: 48px;
  --radius-input: 6px;  --radius-card: 10px;  --radius-drawer: 12px;  --radius-tag: 4px;

  --scrim: rgba(26,28,32,.18);

```

- 间距基数 4px，只用上面的 7 档。
- 阴影只用于浮层（抽屉、菜单、弹窗、Toast）；卡片是 1px `--line` 边框，无阴影。
- 圆角：输入 6，卡片 10，抽屉 12，标签 4（不用胶囊形）。

### 2.4 动效

```css
:root {
  --ease: cubic-bezier(.2,.8,.2,1);
  --dur-in: 180ms;  --dur-out: 140ms;  --dur-drawer: 200ms;
}
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
```

页面切换淡入 + 上移 8px；卡片列表按 30ms 递进，最多 6 项。不使用弹跳、脉冲、持续循环动画（进度条除外，进度条用确定的宽度变化）。

### 2.5 图标

图标是内联 SVG：24×24 视口，描边 1.5，`currentColor`，尺寸 16 或 20。**路径数据是权威，放在 `design/prototype/js/icons.js`**；React 的 `components/ui/Icon.tsx` 复制同一份数据、渲染同样的 `<svg>`，**不依赖 `lucide-react`**（这样像素比对没有图标差异，也少一个依赖）。形状参考 Lucide（ISC 许可），路径为手写复刻。现有图标：`sun`（今日）、`briefcase`（持仓）、`arrow-left-right`（交易）、`activity`（风险）、`radar`（扫描）、`settings`（用竖向滑块表示）、`search`、`x`、`chevron-down`、`chevron-right`、`external-link`、`check`、`alert-triangle`、`info`、`refresh-cw`、`play`、`more-horizontal`、`wifi-off`、`clock`、`plus`、`arrow-down`、`minus`、`help-circle`。新增图标先加到 `icons.js`，再加到 React。

### 4.2 今日（`#/today`）

目的：30 秒内知道“今天有没有需要我处理的事”。

```text
2026年11月2日 星期一 · 美股 已收盘                              [立即扫描]  上次扫描 08:31

今天有 3 件事需要你看一眼
────────────────────────────────────────────────────────
[美股] ZZAR  Zenith Arc Robotics        [推翻] 0.93
你写过：控股股东长期持股，不会大幅减持
证据：On October 29, 2026, Zenith Arc Robotics Inc. (the "Company") was notified by … 
8-K · 10月31日 04:12
                 [查看原文]  [仍然成立]  [修正逻辑]  [⋯]
────────────────────────────────────────────────────────
… 另外两张卡 …

▸ 系统拿不准的 2 条
▸ 已处理（1）
```

- 卡片内容（US-07）：市场徽标、代码与名称、关系标签、概率（`headline`，两位小数，等宽）、“你写过：”逻辑摘要（≤ 1 行，超出省略）、“证据：”证据摘要（≤ 2 行）、披露类型 · 发布时间 · 披露标题（去掉表单类型前缀）、操作。页头右侧写“上次扫描 08:31”；上次扫描失败时写“上次扫描失败 08:36”，不得让用户误以为失败的那次成功了。
- 操作：`查看原文`（打开抽屉）、`仍然成立`、`修正逻辑`、`⋯` 菜单里 `准备卖出`、`忽略`。`逻辑已更新` 标签：`thesisCurrentVersion > thesisVersion` 时出现在标题行。
- 标注：`contentStatus = title_only` → 证据行前缀“仅依据标题”；`evidence.kind = passage` → “未能定位到单句”。
- 排序：推翻在前，削弱在后；同级 `headline` 降序（与 04 的 8.1 一致）。前 5 条展开，其余折叠为“其余 M 条”。
- “系统拿不准的 K 条”：折叠组，标签是“待确认”，不计入 N。
- “已处理（N）”：折叠区，最近 30 天；每条一行（标的 + 关系 + 处理方式 + 时间 + 备注）+ `重新打开`。

| 状态（`inbox.list` 示例名） | 展示 | 操作 |
|---|---|---|
| `pending` | 如上 | 全部可用 |
| `empty` | `display` 大字“今天没有需要处理的变化”；下方“已检查 4 只标的、6 份披露、17 个段落，上次扫描 11月2日 08:31”；仍可展开“已处理” | 立即扫描 |
| `no_holdings` | 空状态：线条插画 + “先添加第一只标的” + 按钮 `去持仓` | — |
| `scan_failed` | 清单照常显示（上次成功的结果）；顶部 danger 提示条：失败原因（来自 `lastScan.error.message`）+ `重试`；页头写“上次扫描失败 {时间}”，状态栏的“最近扫描”仍是最近一次成功的时间 | `重试` = `scan.start` |
| `offline` | 清单照常显示；warn 提示条“当前离线，显示的是上次的结果。”，顶栏出现“离线”标签；（原型里 `立即扫描` 仍可点，v1 评估是否禁用） | — |
| 加载（无示例，本地状态） | 3 张骨架卡（灰阶块，无 shimmer） | — |
| 扫描中（`scan.status` 的 `running` 示例 + 通知） | 页头按钮变为 `取消`；下方进度条 + “正在判定 ZZCL 的 6-K · 9 / 17”；清单保持可用并随 `inbox.updated` 增量更新 | `取消` = `scan.cancel` |
| 缺配置（`app.bootstrap` 的 `unconfigured`；清单用 `never_scanned`） | 全局 info 横幅“尚未配置 Jev 密钥和 SEC 联系邮箱，扫描无法开始。”+ `去设置`；页头 `立即扫描` 禁用并带 `title` 说明；主体是空状态“还没有扫描过” | — |

### 4.3 证据抽屉

宽 400px。打开后焦点移到抽屉标题，`Esc` 关闭。内容自上而下：

1. 标题行：`[推翻]` 标签 + 概率 + 关闭按钮；副标题 `ZZAR · Zenith Arc Robotics Inc.`。
2. **披露**：标题、类型（8-K）、发布时间（本地时区）、来源文件（`主文档` / `EX-99.1`）、`在 SEC 查看原文 ↗`（外链：点击前小字显示域名 `www.sec.gov`，只允许 https；演示数据显示“这是演示数据，没有真实原文”）。
3. **原文段落**：整段文字，等宽以外的正文字体，行高 24px，证据句用 `--accent-soft` 底 + 2px `--accent` 下划线高亮（`<mark class="c-evidence-mark">`）。证据是整段或标题时，上方一行说明文字：“未能定位到单句，以下为整段原文” / “仅依据标题判定”。
4. **你的逻辑**：判定时版本的文字 + 失效条件；`thesisCurrentVersion > thesisVersion` 时显示“你已将逻辑更新到第 N 版”。
5. **五个概率**：5 行小条形（label 英文原名不显示，显示中文：相关、削弱、矛盾、失效条件、支持），右侧两位小数；`killMet = null` 的行显示“未设置失效条件”。条形用 `--ink-2` 填充，不用判定色。
6. **来源信息**（小字）：`Jev 直连 · jev-1.14.0 · 问题集 qs-2026-11-02.1`。
7. **操作区**（底部固定）：`仍然成立` `修正逻辑` `准备卖出` `忽略` + 备注输入框（可选，≤ 200 字）；已处理条目显示处理记录与 `重新打开`。

| 状态（`decision.get` 示例名） | 差异 |
|---|---|
| `overturn` / `weaken` / `uncertain` | 如上；`uncertain` 的标签为“待确认” |
| `title_only` | 原文段落区只有标题，说明“仅依据标题判定” |
| `processed` | 操作区换成“已处理：仍然成立 · 备注 · 时间”和 `重新打开` |
| `not_found` | 抽屉显示错误：“没有找到这条判定”，只有关闭按钮 |

### 4.4 持仓（`#/holdings`）

- 工具栏：`+ 添加标的` 输入框（带搜索图标，占位“代码、英文名或中文名”）、`刷新行情` 按钮、右侧“行情截至 10月30日”。

## 5. 组件规格

所有组件的类名前缀 `c-`，状态类 `is-`/`has-`。下面给出**标准 DOM**，原型与 React 必须输出同样的结构（属性顺序不要求）。尺寸来自令牌。

### 5.1 Button

```html
<button class="c-button c-button--primary" type="button">立即扫描</button>
<button class="c-button c-button--secondary" type="button">查看原文</button>
<button class="c-button c-button--text" type="button">重置账户</button>
<button class="c-button c-button--danger" type="button">清除演示数据</button>
<button class="c-button c-button--icon" type="button" aria-label="关闭"><svg …/></button>
```

高度 32px；内边距 0 12px；圆角 6px。`primary`：`--ink` 底、`--on-ink` 字；`secondary`：`--surface` 底、1px `--line-strong` 边、`--ink` 字；`text`：无边无底、`--ink-2` 字、悬停 `--surface-2` 底；`danger`：`secondary` 外观 + `--danger` 字色。按下位移 1px。`disabled`：整体 40% 透明度，`cursor: not-allowed`，并带 `title` 说明原因。加载中：`is-loading`，文字不变，前面一个 12px 的 `refresh-cw` 图标（不旋转，避免持续动画）并 `aria-busy="true"`。点击目标 ≥ 32×32。

### 5.2 Input / Textarea / Field

```html
<div class="c-field has-error">
  <label class="c-field__label" for="f-statement">逻辑</label>
  <textarea class="c-textarea" id="f-statement" aria-describedby="f-statement-help f-statement-err" aria-invalid="true"></textarea>
  <div class="c-field__meta"><span id="f-statement-help" class="c-field__help">…</span><span class="c-field__count">0 / 500</span></div>
  <p class="c-field__error" id="f-statement-err" role="alert">逻辑内容不能为空</p>
</div>
```

输入框高 32px（textarea 自适应，最小 3 行）；1px `--line-strong` 边；聚焦：2px `--focus-ring` 外环，偏移 1px；错误：边 `--danger` + 说明文字 `--danger`（同时有文字，不靠颜色）。计数用 `--font-mono`；超限时计数变 `--danger`。

### 5.3 VerdictChip

```html
<span class="c-verdict c-verdict--over"><svg aria-hidden="true" …/>推翻</span>
```

高 22px，圆角 4px，12px 字、字重 500；类 `c-verdict--over | --weak | --hold | --none | --unsure`；文字固定四五类：`推翻` `削弱` `支持` `无关` `待确认`。每类带一个**形状图标**（推翻：`alert-triangle` 实心感用线条；削弱：向下箭头；支持：`check`；无关：短横线；待确认：`?` 圆圈），颜色之外还能区分。

### 5.4 Probability

```html
<span class="c-prob" title="Jev 回答“是”的概率"><span class="c-prob__value">0.93</span></span>
```

等宽两位小数；前面不加“置信度”字样（00 禁用）；`title` 说明含义。

### 5.5 MarketBadge / EngineBadge / StatusTag

- `MarketBadge`：高 20px，1px `--line-strong` 描边，`美股`。
- `EngineBadge`：顶栏用，`Jev 直连 · jev-1.14.0`；降级时加 `is-degraded`，带 `info` 图标。
- `StatusTag`：`c-tag c-tag--{ok|warn|danger|none|info}`，12px，高 20px，圆角 4px；用于持仓状态、运行状态、订单状态。

### 5.6 Card / DecisionCard

```html
<article class="c-card c-decision" aria-labelledby="d-01-title">
  <header class="c-decision__head">
    <span class="c-market">美股</span>
    <h3 class="c-decision__title" id="d-01-title"><span class="u-mono">ZZAR</span> Zenith Arc Robotics</h3>
    <span class="c-verdict c-verdict--over">…推翻</span><span class="c-prob">…0.93</span>
  </header>
  <p class="c-decision__thesis"><span class="c-decision__label">你写过：</span>控股股东长期持股，不会大幅减持</p>
  <p class="c-decision__evidence"><span class="c-decision__label">证据：</span>On October 29, 2026, …</p>
  <p class="c-decision__meta">8-K · 10月31日 04:12</p>
  <footer class="c-decision__actions">…按钮…</footer>
</article>
```

白底、1px `--line`、圆角 10px、内边距 20px。卡片之间 12px。

### 5.7 Table

`c-table`：表头高 36px、`--surface-2` 底、12px 字；行高 44px；行分隔 1px `--line`；悬停 `#FCFAF6` 对应的令牌（`--paper` 与 `--surface` 之间，**不要写十六进制**，用 `color-mix(in srgb, var(--paper) 50%, var(--surface))`）；选中行左缘 2px `--accent`。数值列加 `c-table__num`（右对齐、`--font-mono`）。行可展开：`aria-expanded`。表格外层加 `overflow-x: auto`（窗口窄时表格内滚动，页面不得横向溢出）。

### 5.8 Drawer / Modal / Toast / Banner

- `Drawer`：宽 400px，`--surface`，左边 1px `--line`，圆角只在覆盖模式下（左侧 12px）；自右滑入 200ms；`role="dialog"`、`aria-modal="false"`（推开模式）或 `"true"`（覆盖模式）、`aria-labelledby`；焦点陷阱仅在覆盖模式启用。
- `Modal`：最大宽 480px，仅用于破坏性确认（归档、重置账户、清除演示数据）。重置账户需要输入账户名才能启用确认按钮。
- `Toast`：右下，最多 3 条；`role="status"`（成功）/`role="alert"`（错误）；4 秒消失，错误不消失，带关闭按钮。
- `Banner`：`c-banner c-banner--{info|warn|danger}`，图标 + 一句话 + 可选操作；位于内容区顶部，不遮挡内容；`role="status"`（info/warn）/`role="alert"`（danger）。

### 5.9 Heatmap（SVG）

```html
<svg class="c-heatmap" role="img" aria-label="相关系数热图，5 只标的" viewBox="0 0 W H">
  <g class="c-heatmap__cell" data-row="0" data-col="1"><rect …/><text …>0.21</text></g>
</svg>
```

- 单元格 56×56，间距 2px；行列标签在上方和左侧，11px 等宽。
- 填充色：对称的线性混合。`ρ > 0`：`color-mix(in srgb, var(--heat-pos) {k}%, var(--heat-zero))`；`ρ < 0`：用 `--heat-neg`；`k = round(|ρ| × 70)`（**强度上限 70%**，这样单元格内的深色文字仍满足对比度）。对角线（1.00）用 `--surface-2`。`null` 值显示斜线纹理（SVG `pattern`）。
- 数字：始终 `--ink`，两位小数，等宽。
- 悬停：`title` 显示“ZZAR 与 ZZCL：0.58”。图例：横向色条 `−1 … 0 … +1`。
- 无障碍：`表格视图` 提供同样数据的 `<table>`。

### 5.10 BarList（SVD 解释方差）

```html
<ul class="c-barlist" aria-label="主成分解释方差">
  <li class="c-barlist__row"><span class="c-barlist__label">第 1 主成分</span>
    <span class="c-barlist__track"><span class="c-barlist__fill" style="--w:46%"></span></span>
    <span class="c-barlist__value">46.0%</span></li>
</ul>
```

填充宽度用 CSS 变量 `--w`（内联样式只允许设置自定义属性，不允许写颜色）。填充色 `--ink-2`。

### 5.11 其他

- `SegmentedControl`（风险窗口、买卖方向）：`role="radiogroup"` + `role="radio"`。
- `Skeleton`：灰阶块，`--surface-2`，**无动画**。
- `EmptyState`：一句结论 + 一句解释 + 一个主操作；线条插画是 CSS 画的（一张纸、一条横线），不引入位图。
- `Progress`：`c-progress`，`role="progressbar"` + `aria-valuenow`。
- `Menu`（`⋯`）：`role="menu"`，方向键移动，`Esc` 关闭。

| 页面 | 状态 id | 含义 | 组合的契约示例（方法/示例名） |
|---|---|---|---|

## 7. 文案规范

- 语气：克制、具体、第二人称；不喊口号。
- 日期时间：`11月2日 08:31`（本年省略年份）；跨年才写年；相对时间只用于“刚刚”“N 分钟前”（< 1 小时）。时区为用户本机时区；交易日按美东并标注“美东”。
- 数字：千分位；概率两位小数；比例一位小数百分比；金额美元 `$1,234.56`（界面显示 2 位，接口是 4 位）。
- 禁止用语：建议买入、建议卖出、必涨、抄底、牛股、AI 精准预测、置信度（指概率时）。
- 固定声明：“仅记录与提醒，不构成投资建议。”（设置页“关于”、导出文件、首次启动）
- 判定描述：
  - 推翻：`这条披露与你的逻辑直接冲突`
  - 削弱：`这条披露削弱了你的判断前提`
  - 支持：`这条披露支持你的判断`
  - 无关：`与你的逻辑无关`
  - 待确认：`系统拿不准，请你看一眼`
- 空状态：`今天没有需要处理的变化`，不用“暂无数据”。
- 错误：说清“发生了什么 + 你能做什么”，例：`SEC 暂时无法访问，当前显示的是 11 月 2 日 08:31 的结果。`
- 所有文案放 `apps/desktop/src/i18n/zh-CN/<页面>.ts`，组件里不散落长文案（短标签如按钮可以内联常量，但同一句话不得出现两处）。

## 8. 可访问性

- 正文对比度 ≥ 4.5:1；大字号与非文字组件 ≥ 3:1（`check_contrast.py`）。
- 焦点可见：2px `--focus-ring` 外环，偏移 1px；**禁止 `outline: none`**（CSS 检查）。
- 全部操作可键盘完成；Tab 顺序符合视觉顺序；抽屉打开后焦点进入抽屉，`Esc` 关闭并还焦点。
- 点击目标 ≥ 32×32。
- 图表（热图、条形）有 `role="img"` + `aria-label`，并提供“表格视图”切换。
- 颜色不是唯一信息载体：判定有文字 + 形状图标；涨跌有正负号；状态标签有文字。
- 每个 `<button>`、`<a>`、表单控件有可访问名称；图标按钮必须有 `aria-label`。
- 动态更新（Toast、进度）用 `aria-live`/`role`。

## 9. 原型与实现

### 9.1 原型的文件结构

```text
design/prototype/
  index.html            应用外壳 + 页面容器；hash 路由 #/today #/holdings #/trading #/risk #/scan #/settings #/v1
  gallery.html          令牌与全部组件的陈列页（每个组件的所有状态）
  README.md             怎么打开、怎么切换状态、与 React 的对应关系
  css/
    tokens.css          第 2 节的令牌（第一个 :root 块）
    base.css            重置、排版、焦点环
    layout.css          l-* 外壳布局
    components.css      c-* 组件
    pages.css           p-* 页面专用样式
    platform-macos.css  platform-windows.css
    proto.css           仅原型使用：状态切换控制条与陈列页（proto-* 类名），React 不复制
  js/                   经典脚本（非 ES module），file:// 双击可打开
    icons.js format.js render-ui.js render-pages.js render-pages2.js states.js
    router.js proto-controls.js app.js gallery.js
  data/mock.js          由 scripts/gen_proto_mock.py 从 contracts/ 生成；纯 JSON
```

- **经典脚本**：不使用 `<script type="module">`，因为从 `file://` 打开时浏览器会拦截模块加载。
- 渲染函数是纯函数（输入 mock 数据，返回 HTML 字符串），这样可以用 Node 直接渲染做自动检查（`scripts/check_proto.py`）。
- 状态切换：参数写在 `#` 之后（hash 路由，这样从 `file://` 切换状态不会整页重新加载）：`index.html#/<页面>?state=<页面状态名>&drawer=<抽屉>&platform=macos|windows&w=&h=&bare=1`。`bare=1` 隐藏 `proto-*` 控制条和水印，用于截图。
- 原型页面角落常驻水印“原型示例数据”（`bare=1` 时隐藏）；演示公司全是虚构。

### 9.2 React 与原型的对应

| 原型 | React |
|---|---|
| `css/{tokens,base,layout,components,pages}.css` | 原样复制到 `apps/desktop/src/styles/`，**不改类名** |
| `css/platform-*.css` | 同名复制 |
| `js/render-ui.js` 里每个 `renderXxx` | `components/ui/Xxx.tsx`，输出相同 DOM |
| `js/render-pages.js` 里每个页面 | `pages/<页面>/index.tsx`，输出相同 DOM |
| `data/mock.js` | `src/rpc/mock/` 由同一个脚本生成 |
| `css/proto.css`、`js/proto-controls.js` | 不复制 |

### 9.3 像素比对（验收）

在同一台机器的 Playwright Chromium 里，先后打开原型（`index.html#/<页面>?state=<状态>&bare=1`）和 React 应用（`VITE_RPC=mock`，同一状态），在 1280×820 和 1024×700 两个视口截图，用 Playwright 的快照比较，`maxDiffPixelRatio = 0.01`。不保存跨平台基线图。比对的（页面，状态）清单：第 6 节总表里**除 `loading`、`scanning`、`running`、`advanced`（含动态元素）之外的全部状态**，加上 `today` 的抽屉 `overturn`、`weaken`、`uncertain`、`title_only`、`processed` 五种。命名格式 `<页面>:<状态>` 或 `today:pending:<抽屉>`，与 `scripts/proto_render.js` 的输出键一致。

细节与失败处理见 [09](09-测试与评测.md) 第 7 节。
